## 現在の状態

ぷよぷよeスポーツ（Steam版）のフィーバールールで、ゲージ増加ありの対戦を protocol 3 のエンジンで判断する。**いまエンジンがどう判断するかは [FEVER_MODE_ENGINE.md](FEVER_MODE_ENGINE.md)（現行仕様）にまとめてある。** 日ごとの経緯は [WORK_LOG.md](WORK_LOG.md) にあり、本書には載せない。

- **通常盤面**：本線を構築し、予告・相手連鎖があれば積む・最小相殺・本線発火・受けるを比較する。通常相手ではゲージ増加に加点せず、Fever突入目的の小消しを減点する。双方が未突入の通常戦では自分の突入を避け、本線を残した副砲で相手の突入を促す選択を評価する。相手が実際にFeverへ入った後は双方のゲージを用いた合戦用の返しへ切り替える。必要な本線の返しと代替のない緊急相殺は維持。初回は設定目標を守り、初回本線（初回目標-1以上、既定14）の実発火またはFever突入後はランチャーのセカンド目標（既定14、空欄＝指定なし）を使う。指定時は構築と発火を同じ連鎖数に揃え、指定なしは安全容量まで構築。安全に積めなくなったら連鎖数を問わず発火を探す。通常戦術も中央列の余白を守る。確定済み相手攻撃は予測を保持し、得点から予告へ計上されただけでは最終収支が同じ準備手を捨てない。
- **フィーバー中**：すべての手順を「このフィーバーが終わるまでに見込める得点」で比べる（方針 `value`）。タネは伸ばすのが基本で、相手の通常盤面に降らせて連鎖を組む時間を与えない場合と、両者フィーバー中で相手に保留予告がある場合だけ、規定以上を即発火する（2026-10-08ユーザー指示）。おじゃまを受ける手順も見えているツモへ読み進める（同日）。送った分で相手を倒せる見込みは、通常盤面の戦術探索だけが使う。2026-10-07に、消さずに待つ手順の見積もりを直した（規定未満の即発火と、正規発火が見えているのに失敗する手への対応。[SEARCH_PLAN.md](SEARCH_PLAN.md) 第12節）。
- **今回の修正**：通常／Fever予告の4値と実送信先を探索まで保持。Steamの突入境界を読取測定し、先読み準備の時間予算・セカンド設定漏れを修正。本線・副砲はmain由来の得点・残ぷよ・受入れ許容量の判断へ戻した（Fever用の配置・倍率へ移植）。詳細と実測の限界は [調査と修正](FEVER_INVESTIGATION_2026-10-09.md) を参照。
- **確認の範囲**：Fever系の自動テスト292件、記録済み要求の再生、オフラインの計測まで。10-08に妨害・全消し・少量予告の過剰相殺を追加修正した（[TACTICS_PROGRESS.md](TACTICS_PROGRESS.md)）。相手攻撃中の探索再利用・入力取消と初手の開始前準備も修正した（[操作接続](FEVER_MODE_LIVE.md)）。初手の開始前準備は追加修正後の実機1試合で両AIの再利用・指定配置への設置を確認（判断待ち15ms）。戦術の効果・勝敗と他の遅延場面の実機受入れは未完了。代表キャラでの先行対戦（[BATTLE_ROADMAP.md](BATTLE_ROADMAP.md) の順序4）は、2026-10-06にユーザーが完了といってよい状態と申告している。
- **リファクタリング**：[REFACTOR_PLAN.md](REFACTOR_PLAN.md) のR0〜R6（R3・R6は一部）と、[SEARCH_PLAN.md](SEARCH_PLAN.md) の探索の再編（P0〜P6）を実施した。残りと理由は各書の末尾の節にある。
- **検証の入口**：`python tools/fever_check.py test`（全テスト）、`python tools/fever_check.py replay`（記録済み要求と同じ返答をするか）、`python tools/bench_fever_baseline.py`（計測）。

2026-10-09潰しの追加修正：ジャブの数量評価、次の種を上回る副砲／本線の継続圧力、本線温存、絶対締切による先読み・early・種発火検査、相手の種レベルと連鎖終了時刻の記憶を追加。[フィーバー潰しの現行仕様](FEVER_DISRUPTION.md) を参照。実機の着弾・勝率・操作待ちは未検証。
