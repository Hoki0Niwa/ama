# 満杯付近の本線を小連鎖へ変換する探索

## 可視探索と構築ビームの再利用

`normal_build.conversion.reuse_visible=true` が既定。相手が初回本線・Fever前の通常モードのとき、既存の可視ツモ探索から現在手の2〜4連鎖を回収し、通常構築ビームで消去後の再構築を読む。falseおよび相手Fever時は後述の従来探索を使う。

通常ビームでは小連鎖後の枝が早く消え、残形の予測値が発火した小連鎖の点数のままになる場合があった。`side_frontier_slots` は現在手が2〜4連鎖になる配置ごとに少数の継続を同じ層に残す。強制保持は全ビーム幅の1/8以内で、残りは従来評価で選ぶ。幅・最大深さ・6仮想列・探索の呼出し回数を増やさない。実際の生存枝や完了深さが変わるため、実展開数や準備計算時間が同じになる方式ではない。

枠を使うのは、既知3ツモのセル数が残り容量を埋める、非消去配置が2以下になる、または観測した小連鎖後の再構築中の局面。被弾・飛行中の攻撃・相手の初回本線後には枠を使わない。規定の一つ手前以上の可視本線（通常は12連鎖以上）を保護する。入力直前の `cold_spawn` でキャッシュがない場合は枠を無効にし、既存の縮小幅を使う。完成済みの構築は縮小前に照合して再利用する。

選択時機は48個以上、非消去配置が設定上限以下で、既知3ツモの量が残り容量を埋めるか、非消去配置が2以下の場合に限る。現在手で実際に2〜4連鎖し、中央のマージン1と24個以上の色ぷよが残る候補だけを使う。後続手の準備を選んで次の判断で計画を失う経路は選ばない。

残形の値は、既に完了した通常構築の配置別・6仮想列別の本線点数を使い、単発罰点を引く前の値を保存する。全列で再構築下限の点数を満たし、元の配置の予測を単色4個消し連鎖へ換算して最大2リンク分の組み替えに収まる候補を残す。元の予測が下限より小さい列は、その元の点数を下限とする。最悪列、合計、材料、固定評価の順で選ぶ。全列で元以上という条件を緩め、未完成本線の一部を組み替える余地を作る一方、完成直前の本線は選択対象から外す。

実際の2〜7連鎖を観測した後は本線の再構築を優先する。8連鎖以上を経験した後も直近の消去から12手未満や手数不明なら追加の小連鎖を選ばない。予定した発火を観測履歴に書き込まない。構築の既知キューが現在と完全一致しない場合は比較を省き、再探索せず元の手を使う。6列の見込みは未知色での実行保証ではなく、返す手順は現在手だけ。

現在手のtransition再確認以外にnativeの探索呼出しを足さない。同じ記録ツモで2連鎖と3連鎖を各1回選び、3連鎖後の13連鎖を確認した。準備計算時間は増える局面があるため、入力直前・キャッシュ再利用の時間と分けて検証する。条件・本線点数・遅延・実機未確認の範囲は [検証](VALIDATION.md) を参照。

## 目的と判断範囲

通常盤面が満杯に近く、規定未満の本線を撃って構築を終える代わりに、小さい攻撃で空間を作って構築を続ける。元の本線の保持を必須とせず、一度崩して組み直す候補も比較する。`normal_build.conversion`（`data/fever/battle_policy.json`）が有効化と探索・受入れ条件の正本。

対象は現在の通常構築が選んだ手で、盤面が混み、安全な非消去の置き方が少なく、可視本線が小連鎖の上限より大きく、十分な本線の下限には届かない場合。満杯になる直前から探す。満杯の手で置ける配置がすべて大連鎖になる場合には、その手から分割できない。

相手の状態は次のいずれかに限る。

- 通常で、初回本線（`first_main_chain` 以上の通常連鎖）もFever突入もまだ経験していない。履歴不明、初回本線後、Fever復帰後、突入待ちは対象外。
- Feverの種を伸ばしている。連鎖中・種待ちではなく、色ぷよを操作できる状態。時計が進む場合は予測送信が残り時間に収まること。
- Feverの観測済み連鎖終了から妨害窓までに送信を確定できる。現在手の発火だけを使い、おじゃま落下を挟む準備手を使わない。相手の残る観測攻撃を全量差し引いても最低送信量が残り、自分が相殺でFeverに移らないこと。

自分の予告・飛行中の攻撃・レート変更の予測がある局面は既存の防御を使う。自分が突入する場合、既に十分な本線を撃てる場合、構築以外の戦術が選ばれた場合も、この変換では上書きしない。相手への既存予告が致死量を満たす場合も通常構築を続ける。pressure/finishの設定とは別の通常構築の方針で、ランチャーの通常戦術を有効にしなくても働く。事前判断の再利用・入力承認でも相手の履歴、種、連鎖開始、時刻の条件を再検査する。送信予測は既存の連鎖終了モデルであり、実着弾の保証ではない。

## 二段階の探索

`fever_battle/normal_conversion.cpp` のnative操作 `normal_conversion` が、次の二つを行う。

1. 渡された既知ツモだけで、非消去の準備手から小連鎖までをビーム探索する。消去は最終手の1回のみで、上限は最大5連鎖。候補は実際に着地・消去させた盤面で生成する。現在手には実行可能な持ち上げを含め、先の段は通常構築と同じ保守的な配置候補を使う。
2. 消去後の盤面を、残りの既知ツモと通常構築と同じ6本の固定仮想列で再構築探索する。各仮想列に共通する次手の候補を比較し、6本すべてで一定以上の連鎖の見込みと次の安全な非消去配置がある候補だけ残す。攻撃点、残存材料、再構築点の平均、準備手数を比較する。本線を残したかどうかによる禁止はしない。

再構築の仮想列は形をキャラの周期、色を既存の固定色袋から作る。実機の未来色ではない。返す `path` は既知ツモでの小連鎖までに限り、仮想列で見つけた連鎖を実行手順として返さない。再構築の値は探索内の見込みであり、将来の色・相手の行動・実際の復元を保証しない。

ノード上限・ビーム幅で落とした候補があり得るため、「変換が見つからない」は不可能の証明ではない。`budget_exhausted` は既知ツモの探索のノード上限到達を示す。再構築対象は盤面評価で絞った候補であり、すべての残存盤面を再構築するわけではない。

## エンジンへの組み込み

`normal_conversion.py` は通常構築後に適用条件を確認し、結果を同じ入力・手順検査へ渡す。現在の配置はnativeの `transition` でもう一度確認する。同じ盤面・既知ツモ・周期・得点表・探索設定では探索結果をキャッシュする。事前判断にも同じ処理を使う。

選択理由は `normal_capacity_conversion`。`capacity_conversion` に既知の経路、変換連鎖・点数・送信量、残る材料、6本の再構築連鎖見込み、探索深さ、次の安全配置数、展開数を返す。現在手が準備手なら `fire=false` で、予定された後続の小連鎖を今撃ったとは報告しない。

次の要求では実際の盤面と新しい既知ツモで判断する。変換を撃っただけで初回本線の完成やFeverの経験を捏造せず、通常の観測履歴のまま本線構築を続ける。変換が見つからない場合は既存の発火・生存手へ戻り、5連鎖以下にするために自滅する手は選ばない。

## 実局面での確認と制約

[満杯発火の調査](FEVER_PREPARATION_QUALITY.md)の2Pアリィの局面を使った。10連鎖を撃つ27手目は、現在手の生存配置がすべて10連鎖であり、変換は見つからなかった。

その2手前の25手目（`pair=24`）では、従来の非消去配置から、x=1,r=Rの3連鎖2,460点へ変更できた。現在レート120・端数147で送信量は21、消去後の色ぷよは39個、次の既知ツモに対する安全な非消去配置は20。再構築の仮想6列では、設定した深さ16の探索で各10連鎖の見込みを得た。規定13〜14連鎖の復元達成としては数えない。

同じ局面から後続の記録ツモで30手の構築を比較した。新たな相手の攻撃・相手の応手・実機入力・時間を入れず、通常戦術のquiet探索を切った比較である。

| 方針 | 主な発火（pieceは0始まり） | 比較範囲の到達 |
| --- | --- | --- |
| 変換なし | piece 26で10連鎖、piece 51で13連鎖 | 13連鎖に到達 |
| 変換あり | piece 24で3連鎖、piece 45で10連鎖 | 30手では13連鎖未到達 |

この比較では、小連鎖への変換と構築継続は確認できたが、本線復元や総合的な強さの改善は示せていない。相手へ早く21個を送る効果も含まないため、勝率の比較とは扱わない。小消しで先延ばしするだけになるケース、変換後の材料のつながり、再構築評価と実際の構築の差、計算待機は校正が必要。

30手の構築比較の最大判断時間は変換なし約328ms・変換あり約609ms（壁時計、同時負荷の影響あり）。全盤面の上限や実機で間に合う保証ではない。

計算費用の切り分けでは、`test/test_fever_normal_conversion.py` の `case()`（アリィ、25手目の固定盤面、幅250・深さ16）を、通常戦術のquiet探索を無効にして比較した。各条件で最初の1回を除く5回を測り、protocol 3の判断は毎回新しいエンジンで、変換の有無を交互の順に実行した。既存のローカルworkerを使用し、この調査では再ビルドしていない。

| 測定範囲 | 中央値 | 最大 |
| --- | ---: | ---: |
| protocol 3の判断全体・変換なし | 65.06ms | 67.56ms |
| protocol 3の判断全体・変換あり | 249.74ms | 267.71ms |
| nativeの変換操作のみ | 174.37ms | 179.74ms |
| 同じ既知ツモ探索で再構築評価へ進ませない操作 | 4.86ms | 5.43ms |

最後の行は `min_sent=10000` として再構築候補をすべて棄却する費用切り分けであり、新しい選択方式の性能ではない。どちらも既知ツモの展開は564ノード。通常の変換は3候補について各6仮想列を再構築評価するため、この局面では後段の費用が支配的だった。`max_nodes` は前段だけの上限で、再構築を含む経過時間の上限ではない。

同じworkerで、満杯の2手前にはマージン1・捨てぷよなしの非消去5配置と3連鎖3配置があり、満杯の固定盤面では同じ安全条件を満たす配置は10連鎖3配置だけだった。選べる2〜4連鎖が満杯後も残っているとは限らない。

生の計測値、設定・ソース・workerのハッシュと条件はローカル証拠 `data/fever/baselines/small-chain-audit.json` に保存した。単一盤面の費用比較であり、作業ツリー全体のビルド確認、実機入力待機、両席同時負荷、勝率、候補再利用方式の効果は検証していない。

## 再現入口

`test/test_fever_normal_conversion.py` はGit管理の固定盤面だけで実行できる。経路の遷移一致、5連鎖以下・既知ツモ範囲、残存材料と6仮想列の条件、変換できない満杯盤面、安全・資源不足の棄却、ノード上限、型・周期の拒否、protocol 3での選択、攻撃・十分な本線などによる適用除外を検査する。

記録ツモによる構築比較は、ローカル証拠がある場合に次で再実行する。

```powershell
python tools/bench_fever_conversion.py data/fever/baselines/preparation-quality/live-first-round.json --output data/fever/baselines/preparation-quality/conversion-comparison.json
```

`conversion-selected.json` と `conversion-comparison.json` はローカル証拠で、元要求・バイナリのハッシュと比較条件を照合する。証拠のないcheckoutで実測済みと推定しない。実機での変換・復元、対戦勝率、全キャラの受入れは未実施。
