# 検証方法と確認範囲

## 実行する確認

```powershell
python tools/fever_check.py test
python tools/fever_check.py replay
python test/test_engine_protocol.py
```

`test` はFeverの自動検証、`replay` は `data/fever/golden/` の記録済み要求との一致を調べる。Tsuに触れる共有変更では、このリポジトリの `build.ps1` でビルドし、同一seedの `bench` で時間以外の列を比較する。

テスト成功、ビルド成功、再生一致、実機入力、対戦の強さは別の確認。文書だけの変更で過去のテスト件数を今回の実行結果として転載しない。時間制限のある対戦ログは同じバイナリでも変わり得るため、固定seedのログ一致だけを互換性の根拠にしない。

## protocol 3の通常戦術指定

`normal_tactics` の要求単位の切替・閾値・重み、型と範囲の拒否、共有方針への非漏出、先読みと入力承認の設定照合を自動検証する。`test/test_fever_tactical_options.py` の8テストに、初回・再構築・相手Fever・観測待ち・妨害範囲の境界を含む。

省略時の互換性は `data/fever/golden/normal-tactics-defaults.json` の10局面で確認する。変更前の `source_commit` のPython層が返した配置・色・発火・理由・連鎖点・次盤面を保存し、現在の返答と比較する。これは代表局面の回帰保証で、全局面・勝率の同値証明ではない。

`build.ps1 -Target fever_battle`、`-Target pvp`、`-Target bench` のビルド成功。`python tools/fever_check.py test` は47ファイル462件成功（追加8件を含む）、`python test/test_engine_protocol.py` は8件成功。Windows sandboxの一時ディレクトリの権限エラーを避けるため、Fever全件検証では `TMP` と `TEMP` を作業ツリー内の `bin/test-temp`、`PYTHONIOENCODING` を `utf-8` にした。Tsuのソースは変更せず、変更前コミットと作業ツリーのそれぞれを再ビルドした `bench` でseed 42、幅10・深さ3・10手を比較し、時間以外の17列が一致した。

長い対戦・掃引、PPFAIとの接続、実機確認、戦術の強さの校正は実施していない。`window_build` は現行方針JSONに設定があるため、省略時は従来どおり条件付きで有効になる。要求による無効化と部分上書きは自動検証済み。

## 実機の操作と残件

先読みオフの `ahead_piece`（NEXT2の次を色の表から読み、次のツモを3ツモで準備）：エンジンとブリッジの自動検証は済み。幅250×深さ16の実エンジンでは、準備が約325ms、出現時の再利用が約2msで3ツモ分の探索を使った。実機での色の表の一致率、出現後の待ち（`wait_ms`）、自由落下の解消は未確認。連鎖直後の構築探索の事前実行（`build_only`）：自動検証は済み。幅250×深さ16の実エンジンで、連鎖直後の次のツモの出現時の判断が352msから52msになった（残りは出現時にやり直す戦術判断約44ms）。2AI・250×16・先読みオフの実機ログ（212設置）では、通常の設置182件中179件が出現時に判断済みで、遅れた13件は連鎖直後と、相手の着地で次の盤面が変わりうる場面だった。構築探索の再利用が連鎖後に外れる原因（連鎖後は `normal_chain_max` により探索設定が変わる）を直し、記録済みの連鎖22件すべてに準備を通した（通常14件・Fever4件が構築探索を準備、残り4件は続くFeverの連鎖で対象外）。直したあとの実機は未確認。

3個組の測定済み持ち上げ（`lift_allow`）の実機確認：症状seed2/8/16と成功seed5/7/15/23の7局・130設置で目標外／到達不能再試行／断念0。続く連続223局（連番seed、6.9時間、ログSHA256先頭 `c921e94b9c96`、エンジン `6f25b525`、1Pラフィソル幅200・先読みあり／2Pアリィ幅100・先読みなし）では、26,448設置中の目標外6（ペア5・4個組1）、3個組3,910設置はすべて目標どおり、同じ駒の再試行ループ0、許可付きの持ち上げ57回が目標どおり（提示盤面115のうち58回を選択、1回は設置記録なし）。旧版の5時間・187局では「届かない」988件（3個組926）だった。全高段配置の保証ではない。

通常確認余裕10F（`timing.nuisance_check_margin`）：同223局で、予告が確定していないのに降った回は43（0.16%、余裕なしの旧ログは24,800設置中60）。うちちぎりのある手28、30個降下15。モデルが「安全」と見て降った回は6（旧16）で、予測確認時刻の1〜10F以内に収まる。降下量・勝敗への効果は独立シミュレーターでも測定できなかった（10対0で勝ち89対89、降下量3,403対3,420）。
