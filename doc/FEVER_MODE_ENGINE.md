# Fever対戦エンジン（protocol 3）

`python -m fever_battle.mode_engine` が通常構築・攻防・タネ探索を統合する。判断の係数は `data/fever/battle_policy.json`、倍率は `scoring.json`、時間は [FEVER_TIMING.md](FEVER_TIMING.md) を参照。値は対戦での最適化が済んだものではない。

## 構成

| 部品 | 責務 |
| --- | --- |
| `mode_engine.py` | 要求検査、振り分け、事前判断と入力承認 |
| `bin/fever_battle/fever_battle.exe` | `solo` 構築・通常戦術・タネ探索・盤面遷移を処理するnative worker |
| `fever/search.*`・`fire.*`・`engine.*` | 単独エンジンと共通の構築・発火 |
| `transition.h`・`normal_defense.h` | 得点・相殺・予告・落下・防御と時系列 |
| `mode.py`・`model.py` | 明示イベントの審判、ゲージ・時計・保管盤面 |

通常のみの [protocol 2](FEVER_BATTLE_ENGINE.md) と [単独API](FEVER_ENGINE.md) は別入口。

## 要求・返答

1行JSON。`protocol_version: 3`、`rule: "fever_battle"` を必須とする。

両席に盤面、現在手を含む既知ツモ1〜12個、キャラ、周期位置、予告、`mode`、`gauge`、`mode_generation`、`seed_id`、`prepared_frames`、`remaining_frames`、`clock_running`、`seed_base`、`seed_chain`、`stored_field` を渡す。通常／Feverの確定・未確定予告は4値で別に保持し、操作中モードの `confirmed/unconfirmed` と一致させる。

観測不能値を0にしない。`garbage_phase`・`moves_since_chain`・Fever途中の準備時間など、許される未知値はnullと `_status: "unknown"` で表す。要求の `pattern` はキャラ別周期の上書き。検査の正本は `mode_engine.py` と `protocol.py`。

| op | 動作 |
| --- | --- |
| `think`（既定） | 現在の判断 |
| `prepare`・`prepare_normal`・`prepare_observed` | 既知の盤面とツモで次手を準備する。`ahead_piece` は受け付けず、要求の既知ツモだけを使う（ブリッジが出現時に見る数まで色表で補って渡す）。盤面が不確定な場合は構築探索だけを準備する |
| `recover_placement` | `reachable_placements` に限って再選択 |
| `score`・`predict_chain`・`referee` | 得点・相手連鎖予測・明示イベント再生 |
| `ready` | 初期化完了を返す。探索・状態更新なし |

返答は `action: "place"` または `"wait"`。でかぷよは `color` を含む。`wait` を配置として実行しない。`reason`・`decision_kind` は診断値で、依存関係は `decision_dependencies` に持つ。入力前に `authorize_mode_reply()` で現在の盤面・ツモ・モード・世代・予告・時計・攻撃期限を照合する。

## ランチャーで選ぶ作戦

判断の入口は全作戦で共通にし、作戦名によって全消し・本線／セカンド・防御・Feverの処理全体を省略しない。新しい作戦は `fever_battle/strategy.py` の `PROFILES` に共通の `BASE_PROFILE` との差分を登録する。空の設定でも大連鎖と同じ判断を継承し、潰し型も `pressure_style` などの方針だけを変更する。未登録の全消し倍率は100%を継承する。静かな盤面で探索を省く条件は共通の目的の有無で決め、潰し用の探索上限で共通の全消し探索予算を下げない。新しい作戦名を仮登録する回帰テストで共通判断の継承を検査する。

`normal_tactics.strategy` は `mainline`（大連鎖・既定）、`brawl`（乱戦）、`hybrid`（ハイブリッド）。席ごとに指定し、prepare・入力承認の通常戦術署名にも含める。タネ探索は共通。

3作戦とも通常の構築重み・要求された探索幅と深さ・本線/セカンドの発火目標を共有する。作戦による浅い探索への切替や、乱戦で常時突入資源だけを組む切替は行わない。防御で十分に返せる本線は発火する。構築が発火を選んだ本線/セカンドについて、現在の交換を相殺しきり、安全な継続を確認できた候補は、省資源突入のための小消しへ置き換えない（`tactics.ready_main`）。

序盤の全消しも3作戦の共通基盤とする。開始8手以内・Fever未経験・観測最大4未満、消す色ぷよ16個以下・3連鎖以下の全消しを、現在手からNEXT2までの既知ツモで比較する。狙う強さは乱戦＞ハイブリッド＞大連鎖。基礎重み `weights.all_clear` に、方針の `opening_all_clear_scale` を掛ける。既定は200/150/100%で、明示した要求の `normal_tactics.weights.all_clear` があればそちらを優先する。

まず色の総数から必要条件を検査し、どの既知ツモの接頭列でも全消しにならない場合は共通枠を起動しない。でかぷよは色を変えられる4個組として数える。必要条件を満たす場合は、大連鎖と同じ既存の戦術探索予算で比較し、潰し用の初手絞り込みで全消しの準備手を落とさない。潰し・とどめは既存の資源条件で同時に比較する。全消しの準備手が通常構築と同じ配置でも、全消し判断を捨てない。

現在手で全消しできることが既存の配置検査で分かった場合は、通常構築のビームを起動せず、現在手だけを戦術で比較する。NEXT2までの準備手は事前判断へ保存し、出現時は配置・戦術の再探索を行わない。未知ツモによる全消しの見込みには加点しない。

乱戦・ハイブリッドは4連鎖以下の潰しを比較する。通常の新規送信下限は12個、攻撃後の色ぷよ下限は乱戦12個・ハイブリッド16個。両作戦とも、攻撃後の残存盤面に、同色ぷよを最大2個足して発火できる5連鎖以上を要求する。既存の stock 評価の起爆検査から再利用し、将来の色列や仮想袋で5連鎖を補う判定はしない。残存色ぷよ28個未満は単発、28〜35個は2連鎖、36〜43個は3連鎖、44個以上は4連鎖まで。この絶対量・連鎖可能数に加え、攻撃までの可視経路で本線を失う量を1リンク以内に制限する。大きな本線を最低5連鎖まで繰り返し削る攻撃は選ばない。マージン後、実際の倍率・端数・現在レートで4個消し単発が6個以上を送れる場合は送信下限を6個とする。大連鎖作戦もこの条件で事前判断の単発潰しを比較する。

潰しは双方が通常盤面で、双方の通常・Feverトレーに予告がなく、飛行中のおじゃまもなく、相手が連鎖中でも突入直前でもないときに比較する。回数上限は設けず、消去後の盤面・次ツモから毎回比較し、三の矢以降も継続する。相手が本線を打つかFeverへ入ったら、潰し・自動ジャブを止め、本線の返し・伸ばし・発火判断へ戻る。攻撃・予告が解消して双方通常盤面へ戻れば再び潰しを比較する。相手Feverを理由に本線を崩す加点は両作戦で無効。本線・セカンドの発火目標は共通のまま。

相手が操作中（placing）でも、固定盤面と既知ツモを用いて応手を評価する。送信量と相手の相殺によるゲージ増分を圧力として評価するが、実際の応手や準備時間増加は保証しない。作戦が追加する応手探索は準備中に限り1手・96配置。通常戦術は幅6・512ノード以下を維持する。直下の候補を再計算せず、通常の構築手を含む上位6候補に先の潰し構築を絞り、残る枠に収まる候補だけNEXT2まで読む。すべての即発火候補は保持する。攻撃量と相殺による負荷を送信完了までのフレーム数で割って評価し、遠い将来の大きい潰しだけを過大評価しない。配置を決めた後に即発火候補へ上書きせず、同じ探索の評価で準備と発火を比較する。構築が決めた本線発火は優先する。出現後に完成判断がなければ追加の潰し探索を起動せず、防御と構築へ戻る。予測済みの相手連鎖の残量がトレーへ移っただけなら配置を保持する。入力直前に予測を超える新規予告が増えた非消去判断や、相手の発火・突入で条件を失った潰しはそのまま実行せず、完成済み構築を残して防御・本線を再判定する。

予告の受け入れは、中央2列が7段未満でも合計12個まで、7段以上は6個までとし、7個以上を受けるときは中央に2段の余白を要求する（6個以下は既存の1段を維持し、微量のおじゃまのための本線消費を防ぐ）。これを超える場合は、単に今すぐ死亡しないという理由で非消去へ固定せず、既存の可視探索で相殺・返しを比較する。返せる手の存在や実機での生存は別途確認が必要。窓構築は両作戦の既定では無効。検証範囲は [VALIDATION.md](VALIDATION.md) を参照。

## 通常戦術の要求単位の指定

`think`、`prepare` 系、`recover_placement` のトップレベルに任意の `normal_tactics` オブジェクトを渡せる。方針JSONを変更せず、その要求だけに適用する。省略または `{}` は現在の作戦・レートの既定方針を使う。通常レートの大連鎖は従来の判断を維持する。子項目は部分指定でき、省略した値は現在の方針を継承する。null、未知のキー、型違い、範囲外は `ValueError`（JSON入口では既存のエラー返答）になる。整数にbooleanや小数は使えない。

| 項目（`normal_tactics.` 以下） | 型・範囲 | 省略時 |
| --- | --- | --- |
| `invite_fever` | boolean | 双方通常かつ双方 `mode_generation == 0` のときtrue |
| `avoid_own_fever` | boolean | 同上 |
| `harass` | boolean | true（探索の許可。必ず撃つ指定ではない） |
| `harass_min_count` | 整数 0〜84 | 24（以上） |
| `harass_max_count` | 整数 0〜85 | 52（未満） |
| `harass_min_height` | 整数 0〜14 | 4（以上） |
| `harass_columns` | 整数 1〜6 | 左から3列 |
| `window_build` | 下記のオブジェクト | 方針JSONを継承 |
| `window_build.enabled` | boolean | 方針JSONに非空の設定があればtrue（現在true） |
| `window_build.hold` | 整数 1〜19 | 現在10 |
| `window_build.min_pieces` | 整数 1〜100 | 現在3 |
| `window_build.fire_pieces` | 整数 0〜100 | 現在4（0で窓内の即発火を無効） |
| `window_build.beam_width` | 整数 1〜10000 | 現在30 |
| `weights` | 下記の整数値のオブジェクト | 方針JSONの各値 |

`harass_min_count <= harass_max_count` が必要。同値なら通常の範囲条件を満たさない。個数・高さはおじゃまを含む。通常の妨害は予告のない局面で、個数の範囲と指定列すべての最低高さを満たすときに探索する。埋まった相手への旧harass例外・単発加点は使わず、致死量の追い打ちは専用探索で判定する。`harass: false` は一般の妨害を無効にする。相手がFever中なら一般のharassは無効で、タネ交換への攻撃を使う。

明示指定した非空オブジェクトでは、従来の「再構築期の静かな盤面は戦術探索を省く」「色ぷよ17〜23個は省く」という入口を外す。これにより初回以外でも切替と範囲の指定が評価される。ゲージ満杯・相殺加算なしなどの探索不能条件は維持する。`invite_fever` は相手の突入を促す評価、`avoid_own_fever` は自分の突入を避ける評価であり、突入を強制・禁止するものではない。

`weights` の受理キーと現在の既定値（評価式は `tactics.cpp` の `Weights`）：

| キーと現在値 | 型・範囲 |
| --- | --- |
| `entry=6000`, `gauge=1000`, `stock=40`, `color=60`, `drop=150`, `consume=12` | 各整数 0〜1000000 |
| `mainline=1120`, `height=300`, `early=1500`, `builder=250`, `step=400`, `exposed=700` | 各整数 0〜1000000 |
| `pending=0`, `uncountered=2500`, `fever_reach=100`, `harass=400`, `all_clear=5000`, `disrupt=3000` | 各整数 0〜1000000 |
| `mainline_min=4` | 整数 1〜19 |
| `arrival_pieces=2` | 整数 0〜100 |

方針JSONの `kill` は `Weights` では使っておらず要求で受理しない。上表の値は現行既定の説明で、調整結果や戦術の有効性を示さない。

```json
{"normal_tactics":{"invite_fever":true,"avoid_own_fever":false,"harass":true,"harass_min_count":20,"harass_max_count":54,"harass_min_height":3,"harass_columns":3,"window_build":{"enabled":false},"weights":{"entry":4000,"disrupt":5000}}}
```

通常モードの判断返答には `normal_tactics` を追加する。`selected` は最終採用した `reason`（構築・戦術・窓内の構築／発火・回復・観測待ちを含む）、`disruption_kind` は採用した戦術候補の攻撃区分（なければ `none`）。`effective` は解決した切替・閾値・重み、`evaluated_switches` は戦術探索へ渡した `invite_fever`、`avoid_own_fever`、盤面条件適用後の `harass`。探索を省略した場合はnullで、指定値が評価されたと誤認しない。入力承認にも `normal_tactics` を含め、変更した要求に古い判断を流用しない。

## 埋まった相手への追い打ち

`normal_build.followup` は通常相手が被弾し、空からつながる使える色ぷよが少ないとき、致死量を満たす既知ツモの経路を探す。任意戦術とは独立して既定で有効。相手はゲージ4未満、操作可能、連鎖前で、自分には予告・飛行中のおじゃま・予測レート変更がないこと。防御・到達候補制限・別目的の戦術判断は上書きしない。自分がFeverの場合は時計に余裕のある現在手の発火だけを使う。

通の `kill` を参考に、相手の保持する返し量に、最も低い列でも12段へ届く段数×6個を加えた量を必要量とする。返しは相手キャラのFever通常倍率で評価し、保持する連鎖だけでゲージを満たせる場合も除外する。必要量以上の候補では、準備手、入力、ちぎり、落下幾何を含む連鎖時間を合計し、最も早く送信が確定する経路を優先する。時間が同じなら高得点を選ぶ。

許容ゲージは連鎖数ではなく現在からの予測送信時間で決める。`gauge_step_frames` ごとに上限を1段下げ、3から0までとする。閾値の正本は `battle_policy.json`。1連鎖も必要量に達しなければ候補にしない。マージン等でレートが下がり致死量を送れる場合は残す。既存の相手予告が必要量を満たしていれば追撃せず、通常構築を続ける。少量攻撃を足すための累積送信目標や、単発を繰り返す追撃モードは持たない。

事前判断・入力承認でも相手盤面、ゲージ、予告量を照合し、相手の盤面変更・連鎖開始・Fever突入・既存予告が致死量へ到達した場合に失効する。診断は `normal_lethal_followup` と `followup_forecast`。これは保持火力と盤面高さによる致死見積もりであり、未知の将来ツモによる掘り返し・相殺、実配送時間まで含む詰みの証明ではない。勝率・実機での逃げとの関係は未検証。

## 通常相手への潰し・催促ととどめ（任意）

`normal_tactics.pressure` は潰し・催促を1つの戦術として扱う。`normal_tactics.finish` はとどめ。基礎設定の `enabled` は双方false。乱戦・ハイブリッドと、4個消しが1段以上になる大連鎖の事前判断では、作戦側の既定としてpressureを有効にする。pressureを有効にすると旧 `harass` の誘い加点を置き換える。旧 `finish_buried` 加点は停止し、下記の追い打ち探索へ置き換えた。既定は自分の予告がない通常盤面、相手の通常盤面を対象にする。`pressure.allow_pending` で自分に予告がある局面も許可できる。相手の連鎖中・操作中・Fever中・突入直前は相手の可視相殺探索の対象外で、既存の防御・Fever妨害の判断を使う。finishにも予測送信時間によるゲージ上限を適用する。

以下は `normal_tactics.` 以下の追加項目。各オブジェクトは部分指定できる。型・範囲・未知キーを検査する。既定値と範囲の正本は `fever_battle/normal_pressure_options.py`。

| `pressure.max_chain` | 整数1〜19 | 2。送信した各連鎖の上限 |
| `pressure.min_send` / `max_send` | 各整数1〜1000000 | 6 / 30。新規送信の累積範囲、両端を含む。min <= max |
| `pressure.min_remaining` | 整数0〜84 | 24。撃った後に残す色ぷよ数（おじゃまを除く） |

| `pressure.max_main_loss` | 整数0〜84 | 基礎設定84、乱戦・ハイブリッドの既定1。可視経路で自分から失う保持本線の累積リンク数の上限。0で本線を保護、84は制限しない |

実装は `fever_battle/normal_pressure.*`。相手のキャラ別通常倍率、群・色ボーナス、端数、相手側レート予定、ちぎり、リンク時刻を使い、合法な可視配置を読む。Tsuの `gaze` の得点は使用しない。`defence_1` は1手の、`defence_2` は指定した可視手数の、着弾時刻までの最大相殺量で、mainの1手／4手・3／6連鎖の制限とは異なる。可視を超える4手目の色を補わない。特殊形状も実配置で得点計算する。

相殺を強いる圧力は、着弾までに送信分を返せる観測経路の最小色ぷよ消費 `counter_cost_cells` で評価する。本線に使える資源を使わせ、飽和連鎖量を下げる機会の近似であり、実際に何リンク減るかや相手が必ず相殺することの保証ではない。突入を促す加点は既存の `invite_fever` にも従う。撃った後の自分の資源条件は全て要求で調整できる。大きなタネへの再突入を助けるだけの攻撃は、探索不十分で残余が不明な場合も抑える。残余があっても相殺でゲージが満ちるなら、Feverへ逃げられるので同じく抑える。3列目を埋める加点もゲージ逃げがない場合に限る。

先制は、`counter_read` で実際に置けた可視経路の最大累積得点と、それを得る相対フレームを使う。同点は早い経路。自分はFever通常倍率で再得点した本線の見込みに、自キャラの通常倍率で1リンク4個の得点を足して相手の点数に届くまでの不足リンクを求める。不足を可視ツモの平均個数と自分の設置ペースで補う時間、配置・リンク時間を足す。19リンクまで足しても届かなければ見積時刻を1000000Fとする。自分の見積時刻＋余裕が相手より遅く、自分の送信連鎖終了が相手の得点時刻以前なら先制加点する。これは未知色を確定しない楽観的な成長近似で、相手の本線完成時刻や実着弾の保証ではない。探索不足でも見つけた相手の得点は先制の根拠に使うが、未探索の返しを「ない」と扱わず、余剰・とどめの根拠にはしない。

評価は従来の埋没加点に、相殺費用×`counter_cost_weight`、突入可否×`gauge_weight`、新規送信のゲージ増分×`gauge_gain_weight`、確認できた余剰×`surplus_weight`、先制条件×`preempt_bonus` を足し、`weight` を掛ける。ゲージの2加点は `invite_fever` に従う。`max_main_loss` は既存の本線保護の対象（`weights.mainline_min` 以上）から減るリンクを測り、必要相殺による既存の費用減免前の値を使う。非消去で発火口を埋めた損失も含み、おじゃま落下の損失は含めない。`consumed_cells` は本線以外も含む色ぷよ消費で、失ったリンクと区別する。Fever通常倍率とその時刻のレートで送信量を求めるため、同じ少量送信でもTsuより資源を多く要する場合がある。

`max_attacks` は `attacks_used`＋可視経路内の新規送信連鎖数に適用する。非消去の準備手は数えず、一連鎖内の複数リンクは1回。取消・回復で回数が増えないよう、エンジン内部では実行回数を記憶しない。呼出側は実行を観測して更新し、催促終了や局の変更時に0へ戻す。何手空けたら別の催促とするかは呼出側の方針であり、回数を省略して渡すと判断をまたぐ上限は効かない。相性と強さの選択もPPFAI側の責務で、Amaに相性表はない。

とどめは相手のゲージが既に7、または相殺リンクで7に届く経路があれば無効。着弾後に始める連鎖も相殺に使えるため、最初の非消去・落下までの経路を含めて検査する。相手に有利に、既存予告を払わずに全得点を新規送信の相殺へ使え、連鎖終了後の盤面で受けられるものとする。それでも全経路・全端数列で最大30個の1回の落下を耐えられないときだけ加点する。探索上限、可視不足、連鎖中・配置中の相手などで判定できない場合は、とどめにしない。相殺加算が0なら、相殺してもゲージは増えない。

非消去の準備手には可視後続の評価を使える。現在の発火は、その発火自身が得た加点と種類を上限とし、後続の本線やとどめを理由に現在の小消しを採用しない。必要防御・生存の優先は既存のまま。

返答理由は `tactics_pressure`、`tactics_finish`、`tactics_prepare_finish`。候補の `normal_attack` が初手、`projected_normal_attack` が可視後続の評価。最終返答の `normal_tactics.normal_attack` は発火する手では初手、準備手では後続の評価を転記する。`kind` は `preempt` / `surplus` / `invite` / `force_counter` / `bury` / `finish` / `pressure` / `none`。`blocked` は最初の不成立条件、`blocked_conditions` は同時に検査した不成立条件の配列（`no_send`、`enemy_unavailable`、`pending`、`min_remaining`、`min_heights`、`max_redundancy`、`max_chain`、`min_send`、`max_send`、`max_main_loss`、`max_attacks`、`large_seed_gauge_only`、`zero_weight`、`no_pressure_value`）。先に打ち切った場合は後段の検査結果を含めない。`main_loss_links`、`consumed_cells`、`attacks` が自分の費用と送信回数、`race` が両者の得点・時刻と先制条件の診断。`counter` に上記の防御量、連鎖終了まで許した `full_counter`、`counter_cost_cells`、既存予告だけの場合と比べた最大追加ゲージ `gauge_gain`、`entry_possible`、`complete`、`cutoff`、`expanded`、残余を返す。`complete` は可視と配置上限で必要な反応経路を覆えたかを表し、未知なら防御量は下限の観測値で、とどめの証拠にはしない。ブロックされた探索候補も `tactics_forecast.candidates` に残る。

```json
{"normal_tactics":{"pressure":{"enabled":true,"min_remaining":28,"block_seed_chain":9},"finish":{"enabled":true},"counter_read":{"depth":3,"max_nodes":8000}}}
```

控えめな要求の例は `min_remaining=32, min_heights=[4,4,4,3,3,3], max_chain=2, min_send=6, max_send=30, max_main_loss=0, max_attacks=1, allow_pending=false, preempt=false`。強引な例は `min_remaining=8, min_heights=[0,0,0,0,0,0], max_chain=5, min_send=1, max_send=180, max_redundancy=24, max_main_loss=8, max_attacks=3, allow_pending=true, preempt=true, race_margin_frames=60, min_enemy_points=2100, preempt_bonus=18, counter_cost_weight=2, gauge_weight=12, gauge_gain_weight=2, surplus_weight=2`。どちらも `enabled=true` とし、`attacks_used` は実行済み回数を渡す。例は対戦未調整で、勝率改善を確認した設定ではない。強引な値でも生存・必要防御の優先と `block_seed_chain` は迂回しない。

## 可視情報と時間の制約

- 色は要求で渡された既知ツモだけを使い、先の色は仮想列と区別する。未知タネ・突入先・全消し交換後は確定探索しない。
- 端数列カーソルが既知ならその順序で落とす。不明なら全組合せを評価し、実落下後に再観測する。仮の落下盤面を `next_field` として返さない。
- 観測した相手の連鎖はリンク別に一度予測し、得点済みを再送しない。確定時刻と自盤面への落下時刻を分ける。
- CPU時間による構築・戦術・種探索の打切りは行わず、設定した幅・深さ・ノードで探索量を制限する。旧 `decision_budget_ms`／`budget_ms` は探索完了時間の保証ではない。workerの通信故障検出は別。
- Fever時計、マージン、連鎖終了、実際の着弾期限はゲーム時間として検査する。

## 通常盤面の構築と発火

通常は最長本線を構築し、初回からキャラ別通常倍率で候補・実発火を評価する。重みは `config.json` のFever設定。仮想6列のビームと、可視ツモでの実発火探索を使い分ける。設定した深さと実際に完了した深さは区別する。

初回の目標・panic・容量条件は `solo_options` と要求に従う。初回目標−1以上（下限4）の通常連鎖を実観測した後、またはFever経験後に再構築へ移る。小連鎖の掃除や、準備返答だけで初回完了としない。

セカンドの `second_target_chain` 指定時は構築と発火の目標をそろえる。省略時は初回目標−1（既定14）、明示nullは容量まで構築する。安全な非消去配置がなくなると連鎖数を問わず容量発火を探す。目標未満の容量発火を目標達成には数えない。

セカンドの目標に満たない本線でも、相手のFeverが最後のタネ消化で、返されても大きく残る見込みなら発火する（`normal_build.final_seed_fire`、理由 `normal_final_seed_fire`、実装は `final_seed_fire.py`）。条件は次の全て。初回後で、相手がFever中に連鎖を実行中（予測の終了時刻あり）、その連鎖の後に撃てるタネが `max_seeds_after`（1）個以下（2個以上は対象外）、マージンのレート変更がなく、既存の発火がない。連鎖数が `min_chain`（8）以上の非死亡配置のうち、自分の連鎖終了が相手の連鎖終了＋`disrupt_window`（26F）以内に収まる最後の1手だけを撃つ（次の1手では窓を過ぎる手。窓より早ければ構築に任せる）。自分の確認済み・飛行中の予告と、相手の観測済み残りリンクが自分へ送る分は自分のリンクが先に相殺し（予告が残る間は1リンク最低1個）、なお送信量が正であること。相手の残りリンクは、まず相手自身に溜まっているおじゃま（通常トレー、Fever中はFeverトレーも）を相殺し、残りだけが自分へ飛ぶものとして数える（`chain_to_us.py`。以前は相手の溜まりを無視して全量を数え、相手に1000個以上溜まっていても数百個が飛んでくるとして妨害を見送っていた）。その送信量から、相手が最も稼いだ場合の返し — 残りのFeverの最大得点（残りタネを1レベルずつ上げて撃った得点、または伸ばしたタネ `enemy_reply_nuisance` の大きい方）に、続けて戻る通常盤面の本線（`_board_hold`）を足した量 — を引いた残りが `min_remaining`（70個）以上であること。窓の検査は期限の `disruption_timing`（kind `jab`）として事前判断・入力承認でも再検査する。要求の `normal_tactics.final_seed_fire`（真偽値）はポリシーの `enabled` を席ごとに上書きし、ブリッジの設定画面のスイッチ（既定オン）がオフのときだけ `false` を送る。通常戦術の他の項目とは独立。相手がFeverの判断では、見送った理由（`why`：残りタネあり、窓の外、残り不足など。数値つき）を応答の `final_seed_fire_status` に入れ、ブリッジの `planning` ログの `final_seed_fire` に出す。未知ツモの掘り返し、相手の実際の置き方、実着弾時間は見ない推定で、勝率・実機での効果は未検証。

相手の連鎖でFever突入が確定した場合、`entry_fire` は最初のリンクを突入後へ合わせる。本線など構築が選んだ発火は、最短ロック6F＋最初のリンク15Fを用い、突入の予測誤差の余裕24Fを加えてDOWN開始時刻を決める。実機でモデルの置き時間より速く確定したため、一般の配置・ちぎりモデルでなく最短下限を使う。

自動の突入ジャブは、本線（8連鎖以上）を残し、新規6個以上・3連鎖以下、連鎖終了が突入＋窓122F以内、待ちが `max_jab_hold_frames` 以下（既定60F）の場合に限る。窓を逃す攻撃や数手分の構築を止める待ちは選ばず、構築を続けて後の手で比較する。本線発火の時機合わせとは区別する。

待てる上限は接地高さ、自然落下25.6F/段、接地後の猶予32F、安全余裕30Fから求める。相手の連鎖から自分へ戻る量があるときはジャブを検討せず、相殺オブジェクト・自分への飛行中攻撃・予告の増加でも取り消す（`chain_returns_nuisance` / `nuisance_comes_back`）。入力前は `disruption_timing` で対象と時機を検査する。実DOWN時刻は待ちによるマスク適用後のログに記録する。落下と接地猶予の全条件の実機照合は未完了。
相手攻撃の到着と自分の発射を合わせる `gauge_wait` は、自分の連鎖が既知の攻撃総量を超えて相手へ返せる場合、またはマージン開始後だけ、自由落下による発火待ちを許可する。総量は確認済み・未確認予告、飛行中攻撃、相手の未送信リンクから自分へ届く分を足す。マージン開始は要求の明示設定か観測した開始時刻の範囲で確認し、低いレートだけでは推定しない。全ての自分リンクと相手の残り攻撃の組合せから待ち候補を作る。自分の発射は最短ロック＋最初のリンク＋各リンク間隔＋発射24F、相手攻撃は `chain_to_us.flights_to_us` の時刻で扱い、到着予測へ12Fの余裕を加える。ゲージを最大化し、同点は待ちが短い候補を選ぶ。今より2目盛り以上増えるか、7に届く場合だけ待つ。マージン後も、相手へ返る量と未相殺残量が即発火より増えない候補を比較する。少量の許容値と自然落下・接地の上限は方針JSONが正本。

返せる量に届かない通常盤面は、待つ代わりに完成済みの設定幅の構築結果で伸ばす（`normal_extend_before_entry`）。選択した非消去配置の、ちぎりと実測ペースを含む着地・おじゃま確認時刻が相手の連鎖終了より前である間は続ける。期限に間に合わない、確認済み予告がある、安全な非消去配置がない場合は元の防御判断へ戻す。既に成立した時機指定の潰しは保持する。この延長に追加の探索は使わず、乱戦・ハイブリッドでも同じ条件を適用する。

通常発火には `offset_timing` として選択済み配置の落下形状・予測攻撃の絶対時刻を保存する。準備済み発火を使う際は、最新の予告・実相殺オブジェクト・現在フレームで時機だけを更新する（`retime_cached`）。配置探索やworker通信は行わず、選択した位置は変えない。同じ到着時刻・量の別オブジェクトをまとめず、量が変わった相殺オブジェクトは最新値へ置換する。`gauge_forecast` と突入見込みも待った場合の予測に合わせる。相手の連鎖世代や現在レートが変わった場合、古い予測攻撃量は流用しない。レートの将来変化・ゲージ加算の32F遅れ・再発射後の飛行の完全な校正は残る。

Feverへ入る手（ゲージが7に届く手）は、入るのに必要な最少のぷよ（ゲージ1段につき4個の1リンク）を超えて消したぷよ1個ごとに、重み `normal_tactics.weights.entry_consume`（400、要求の `normal_tactics.weights` で上書き可）を引く。突入で盤面は保管され、次の突入を組む資源になるため、必要以上にぷよを消す手より、最少で入る手（ゲージ6ならでかぷよ1つの4個消し）を選ぶ。最少で入る手は引かれず、入るのに多くを要する手（ゲージ1の8連鎖など）も入れなくはならない。入る手が複数あるときは、検索の評価値の順位にかかわらず、確実に入れて生き残る候補のうち消すぷよが最少の手を選ぶ（`tactics.least_entry`。盤面を全部消す入り方は、それだけで別のタネを得るので対象外。探索を足さず、評価済みの候補から選ぶので、判断の時間は増えない。事前に決めた応答にも同じ規則が働く。2026-10-25の実機では、事前の判断が10個を消す2連鎖を選び、4個消しの1連鎖で入れる盤面だった）。小さな連鎖での相殺（1個の相殺でゲージ+1）を続ける動き自体は想定どおりで、変えない。2026-10-25の記録11判断を再生すると、超過分だけを引く重み150〜600で、ゲージ3の8連鎖（61→18個）が5連鎖（61→26個）に、ゲージ5の3連鎖（40→9個）が入らない1連鎖（40→38個）に変わり、入るのに多くを要する8連鎖（ゲージ1）は変わらない。ほかの手が無い判断（残りが10連鎖しか置けない、本線の発火など）は変わらない。値は試作で、対戦では未調整。

可視の本線を保持・延長できる配置と発火を比較する。自然な1〜2連鎖の整理を一律に禁止せず、未完成本線を小さい攻撃で失う経路を抑える。`upper_12`／`upper_13` と `waste_14` はFever構築で無効。2・5列13段を一律には候補除外せず、物理経路と死亡列の余白で判断する。

## 通常盤面の防御・戦術

要求の既知ツモで、構築・受ける・最小相殺・本線発火・突入を同じ時系列で比較する。各手で操作時間・ちぎり・リンク得点・相殺・相手イベント・非消去時の落下（最大30個）を進める。未知端数列の通常探索は落下後の架空盤面へ進まない。

受入れは盤面の実配置と既知の未到着攻撃で検査する。本線を自発的に消費する費用と、おじゃまで壊される結果を区別する。安全に受けられる少量予告だけを理由に、十分返しの優先群で本線を消費しない。必要防御・唯一の救済・構築自身の目標発火は維持する。

判断結果は温存 `build`、防御成立 `defense`、未確定 `unresolved`、探索不能 `unavailable` を区別する。`current_*` は初手、`projected_*` は可視後続を含む結果。現在生存していることを、未知色まで含む防御保証にはしない。

既定では通常相手にはゲージ増加へ一般加点せず、双方未突入なら自分の突入を避け、本線を残す副砲で相手の突入を促す。相手の実Fever経験後は合戦の返しへ切り替える。通常相手の90個未満の攻撃では、十分に返せる可視経路同士は本線の損失が少ないものを優先し、同じ損失なら残る盤面の評価を使う。即時の小返しだけでなく、非消去準備からの返しにも適用する。大きな攻撃やFever相手の十分な本線返し同士は実得点優先、同点なら短時間。推定kill比率だけで構築を上書きせず、互換の `projected_kill` は0。

全消し目的の加点は開始8手以内・Fever未経験・観測最大4未満、消す色ぷよ16以下・3連鎖以下に限る。全消しの実効果、必要相殺、構築の発火を禁止する条件ではない。

相手Feverへの攻撃は [FEVER_DISRUPTION.md](FEVER_DISRUPTION.md)。`finish_probe` は可視経路と全端数列で救済の有無を検査し、逃げがなければ最短決着を選ぶ。出現列が塞がる場合は観測した現在姿勢が必要。

## Feverのタネ探索

実盤面・要求の既知ツモの配置列を探索し、最初に消した所でタネ交換として打ち切る。規定未満の掃除でも交換し、同じタネの掃除後を継続しない。

`seed_options.depth` が可視の手数より大きいときは、通常の構築（`fever::search_multi`）と同じ6つの仮想列（形はキャラの周期と `dropset_index`、色は固定の色袋）で、その深さまで同じ探索を行う。根の手は、6列での最悪の区分、次に期待点の合計で順位を付け、返す手順は可視の範囲で切る（`virtual_values`、`virtual_line_truncated`）。`width` は各段に残す局面数、`max_nodes` 0 はノード上限なし。`depth` を省くと可視3手だけを読む。用意した答えがない判断（`cold_spawn`）では、通常の構築と同じく幅を50以下にし、深さは変えない。実機用にこのPCのCPU向けで速くビルドするときは `tools/build_fever_native.ps1`（返答は `build.ps1` と同じ。別のPCではビルドし直す）。

基本方針 `value` は、現在の連鎖得点、残り時計で消化できる後続タネの期待点、終了時に持ち越す段、有害な保留予告で比較する。消さない手は実盤面の発火口・必要色数・残りツモと空きに基づく見込みを使う。可視ツモが残る間はその続きの最善値を使う。

後続タネは標準リンクと成功見込みによる近似で、実タネの予知ではない。大きいタネを伸ばす際は盤面の空きによる失敗リスクを加味する。値の係数は `fever_seed.value_model`。

原則は伸ばしを比較する。相手の通常盤面へ実際に降らせる余剰がある場合と、相手もFever中で通常用の保留予告がある場合に規定以上の早い発火を優先する（`press_reason`）。規定発火が見えなければ通常の値で比べる。全消しの実利益も扱う。

不明端数列での落下後は最悪の生存・発火口の盤面で可視先を比較するが、返す経路は落下時点で切る。観測中の相手の未送信分は短い手・長い手の両方へ同じ全量を含める。時計0でも実際に操作可能なら現在手を返す。

`seed_forecast.alternatives` に規定発火・失敗発火・非消去の最良値、`extension_potential` に待つ連鎖と見込みを返す。成功保証や未知タネの予測値ではない。

## 事前判断とイベント審判

停止盤面からの準備でも明示された既知ツモをすべて使う。既に準備した判断が通常のthinkの署名・時計・配送検査に通る場合は、cold要求であっても再探索せず、その判断の探索幅と既知ツモ数を維持する。転送された準備には実行要求も引き継ぐ。

判断要求のキューは現在手を含む1〜12ツモ。次手の準備には現在手を除いた既知のキューを渡し、未観測のツモは追加しない。事前判断・構築結果の転送と再利用、先行入力を使う。準備した全ツモの一致を検査し、盤面・世代・予告・時計・期限の検査も維持する。beam探索は別に維持する。

Feverの相手解析は突入・タネ到着・発火イベントで固定し、絶対終了フレームを保持する。経過時間だけで終了時刻を先へずらさない。古い観測で新しい解析を上書きしない。

`ModeReferee` は明示された `enter`・`seed`・`exit`・`clock` を処理する。周期位置はモードで戻さない。これは全対戦の自動schedulerではなく、完全自己対戦は別リポジトリが担当する。

検証と残件は [VALIDATION.md](VALIDATION.md)、起動・入力は [FEVER_MODE_LIVE.md](FEVER_MODE_LIVE.md)。

## 満杯付近の本線保持と実機向け設定

`normal_build` の `retain_floor`／`retain_cells` で可視本線を保護し、`retain_fire_cells`／`retain_fire_chain`、残る安全配置数 `retain_fire_safe_moves` で保持継続と発火を比較する。`forced_lookahead` は置き場所が尽きる前の可視救済、`opening_fire_ramp` は初回の充填に応じた発火連鎖を扱う。条件と現行値は方針JSONと `_normal_options`／`_forced_lookahead` が正本。

`normal_build.conversion` は、満杯に近く本線が規定未満のとき、5連鎖以下の攻撃と消去後の再構築を探索する。元の本線の一時的な崩壊も許容する。既知ツモだけで小連鎖までを作り、その先は通常構築の6仮想列で見込みを比較する。攻撃対応や十分な本線は上書きせず、変換できなければ従来の生存・発火へ戻る。条件・診断項目・未達事項は [満杯付近の変換探索](FEVER_CAPACITY_CONVERSION.md) を参照。

通常構築のビームは、送信がほとんどない消去（整地）を重みで嫌う。fever重みセットの `level_links`（2）連鎖以下で、得点が `level_score`（720点＝通常の送信6個）未満の消去が対象になる。`level_root`（40,000点）は、その手自体が整地する初手の候補から、各仮想列の最大連鎖得点を差し引く。初手の順位付けに効く。`level`（0）は、探索中に整地する局面の行動評価に加える値。どちらも探索の手数を増やさない。セカンド（持続構築の時間効率順位）とFeverの狙い（`aim`）の順位には `level_root` が効かない。防御のおじゃま探索（`garbage_search`）は読まない。実装は `fever/search.h`（`read_level_weights`・`is_leveling`）と `fever/search.cpp`。ブリッジのランチャーでは「評価設定ファイル」の「編集…」画面の長連鎖探索タブで変更できる。値は起動時の設定の写しとしてエンジンへ渡る。

通常構築は、既存の盤面評価で調べた「2個までの起爆で残る連鎖」を初手候補へ保持する。本線発火条件を満たす場合は従来の発火を優先する。それ以外の構築では、置く余地を残し、5連鎖以上を持つ初手がある場合、その最大値から1リンクを超えて本線を失う1〜2連鎖の小消しを、構築を継続できる候補に数えない。通常の非消去手は元のビーム順位で比較し、連鎖の延長や形の組み替えの自由度を保つ。小消しを「置く余地がある」という理由だけで構築継続とみなさない。追加の盤面探索やビームを起動しない。

相手連鎖中の余裕を使う `_window_build` は、返せない本線の延長では完成済みの設定幅の構築を直接使う。それ以外の任意の本線保持判定では、幅30の窓判定用探索の前に完成した通常構築のキャッシュを退避し、判定後は元のキャッシュと幅・再利用診断を復元する。窓判定の候補は幅30で比較し、最終配置は元の設定の構築を使う。判定不成立や例外でも完成構築を失わず、幅250→30→250の最後の同一探索を省く。窓内で直ちに本線発火を選ぶ経路は、窓判定用探索の未計算結果を参照しない。

`_window_build` は、既に選ばれた `jab`／`overpower` を構築で上書きしない。`unready_main` は実際に撃った本線で判定し、埋めた分は費用へ残す。押し発火の下限は `press_min_held=30`、`press_min_lands=6`。いずれも実戦効果の校正は未完了。

測定済み3個組の持ち上げは要求の `lift_allow` を使う。条件・キャッシュ世代・実機確認範囲は [操作制限](DISABLED_TRIPLE_OPERATIONS.md) を参照。`arrival` の時間診断と通常確認余裕は [時間モデル](FEVER_TIMING.md)。
