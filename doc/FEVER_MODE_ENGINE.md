## 2026-10-06 大量予告への次回突入用伸ばしと、返せる予告のタネ消化

自動方針は、通常盤面の保留予告＋Fever盤面の確定・未確定予告を、残り時計で複数のタネを消化した場合の推定相殺量と比較する。推定以内なら `quick` と `prefer_seed_turnover` を使い、予告を返し切る発火、規定達成して次タネを操作できる発火、全消し、消化周期の短さを順に重視する。推定を超える量なら `extend` で現在のタネを大きく育て、次回フィーバー突入のタネを強くする。方針と根拠は `seed_strategy_reason`・`seed_strategy_plan` に返す。予告量・レート・時計が変われば毎回選び直し、準備手も未確定予告を含めて再検査する。明示した `strategy` はこの自動切替より優先する。

量の見積もりはキャラ別Fever倍率・各リンク4個1色・現在の観測レートを使う。タネ準備に3非消去周期＋最大ちぎり1回、初消去13F、各リンク68F（最後43F）の推定、規定消化後のレベル＋1、連鎖終了での時間加算、交換100Fを計上する。期限内発火は連鎖終了が時計0後でも全得点を計上するが、次タネ消化は終了時に時計が残る場合だけ積み重ねる。全消し加算と未知タネの成功を先取りしない。これは入力経路・次タネの配置・未来色を証明する上限／成功保証ではなく `template_current_rate_unseen_seed_success_not_proven` の概算。将来レートの減少を成功量へ決め打ちせず、実際の消去の相殺量は既存のマージン対応nativeで計算する。

伸ばしでは、以前の固定手数上限（低タネ12手など）と、延長後の次タネ操作に100000点相当を付ける評価を廃止した。幾何上の規定発火口を残し、中央高さ9未満・11段までの空き12個以上・未知色の観測を待つ時間があれば積む手を優先する。未知色待ちの時間予算は3×（配置14＋非消去26＋最大ちぎり45）＋初消去13＋安全8＝276Fを残り時計と現在手の実ちぎり込みで比べる。この予算を失った後は可視3ツモで実際に発火する手順を選び、同価値なら遅い期限内発火を選ぶ。残り300F以下はこの可視の最終伸ばしを使う。時計0の実在ツモを放棄する条件は追加していない。

大きな連鎖数を主目的とし、目標は15連鎖。`extension_patience` の旧数値は互換用の表示で、停止判断には使わない（`extension_stop_policy=time_and_space_no_fixed_move_limit`）。同時消しによる点数・送信量を次タネ連鎖数の上昇として評価しない。全消しは次タネに＋2の価値があるため別に比較し、可視の成功発火＋全消し加算が未知の幾何候補より強ければその手順を使う。可視で確認できた大連鎖を、それより小さい未知の幾何候補のために失うことも避ける。消化方針でも同時消しの点数は消化周期・連鎖数より後の小さな比較とし、実際に予告を返し切れる効果は別に扱う。

検証はFever203件、保存タネ40手順、現在＋NEXT2だけを毎回見せる18条件の比較。試作用色列・保留1000個・公開3連鎖タネで、残り600Fの6条件は平均3.67→6.83連鎖、900Fは5.67→8、1500Fは7→8。600Fの一例は4手目4連鎖・発火まで439Fの余裕から、12手目9連鎖・余裕16Fになった。全18例はモデル上生存、CPU予算50ms/8000ノードと可視範囲は維持した。[再生データ](../data/fever/baselines/2026-10-06-fever-long-extension.json)、`tools/verify_fever_long_extension.py`、`test/test_fever_long_extension.py`。Steamの色列・実入力・勝率・次の突入での有利を実証した結果ではない。

## 時計とイベント

時計は `clock_running` が明示的に真の区間だけゲームフレーム差で減る。`clock` イベントで観測した残りフレームと停止／再開を設定できる。`enter`・`seed`・`exit` は観測境界を明示したイベント。ゲージが満ちると `entry_pending` を返し、連鎖を終えてから `enter` を受け付ける。時間切れでも開始済みの連鎖は最後まで処理し、残り時間0から報酬で時計を復活させない。

タネは明示した盤面の `seed` イベントで供給する。実機未採取のタネを乱数で生成しない。タネIDは交換ごとに増やし、通常／フィーバー切替ではモード世代を増やす。周期位置は切替でリセットせず、観測した通算位置を使う。

おじゃま端数のカーソルもモード切替で勝手にリセットせず、既存のユーザー指定どおり実際に落ちた個数だけ進める。モード間の実機照合は未完了。再生状態には採用ルールのハッシュを含め、別のルール値で再生した結果を同一と扱わない。

ソルバーの時刻予測には通常盤面で校正した幾何時計を参考として用いた。**フィーバー中の時計・演出は未校正**なので `mode_timing_status=normal_geometry_reference_fever_unverified` を返す。時計が連鎖中も減るかは `clock_policy.count_chain_frames` で明示する。発火が締切内なら、連鎖終了が時間切れ後でも発火候補として扱う。追加の未確定予告の到着時刻を発明せず、探索結果には未スケジュールと表示する。

## 2026-10-06 操作継続と致死量予告の補正

protocol 3の通常判断のうち、自分の盤面・ツモ・受けた予告だけを使う方針は `decision_dependencies: ["self"]` を返す。事前承認では自分の状態と共通ルール・試合・時計を照合し、相手のツモ・演出の変化で返答を捨てない。指定のない返答、タネの戦術、相手配送予測を伴う返答は従来どおり両者を照合する。

nativeの新しい `finish_probe` は可視3ツモと各落下の全端数列を列挙し、生存する消去または残る生存経路があれば不成立とする。12msの探索予算に達した場合も不成立。救済がなければ3回目のおじゃま落下まで長引かせず、中央死亡列が2回以下で埋まる配置を返す。移動・回転・高速落下の推定と接地・実測ちぎり時間で最短を選び、操作側が実際の現在位置から届く候補を再比較する。未知の4ツモ目や未確定配送を読まない。側列あふれだけを敗北確定の根拠にはしない。未知列の仮盤面はこの救済検査内だけで使い、実際の次の要求は再観測した盤面に限る。

通常の出現経路で配置を列挙できない高い盤面では、追加された要求の `active_placement` を使って `closing_transition` で現在位置の直下設置を検査する。元盤面の死亡しきい値を越えていても、ここからの消去で生存できれば `observed_current_pose_drop` として救済を残す。死亡するなら `no_rescue_fast_finish` を返し、配置なし例外で両AIを終了させない。観測済みの現在位置がない場合は補わない。通常のnative `placements` の死亡・到達判定、protocol 2、単独FeverとTsuは維持する。

## 2026-10-06 返せない本線を消費するカウンターの修正

# 2026-10-06追加：構築先読みと操作承認

通常盤面では相手の連鎖観測を理由に構築先読みを一律拒否しない。相手のリンク・予告・マージンは構築AIの入力ではないため、実盤面・現在ツモ・可視キューの一致する接頭辞・キャラ・形状周期・モード世代・タネ・試合・探索設定で構築結果を再利用する。先読みは可視2ツモ、出現時の最新戦術は現在の観測で再計算する。`normal_build_search_reused` と `normal_build_searched_visible` はこの部分再利用を示し、完成した判断全体の `search_reused` とは区別する。

相手連鎖や未来レート変化を含む通常の準備要求は、構築だけを保存した場合 `prepared=false`、`normal_build_prepared=true` と返す。事前入力用 `plan` は出さない。相手終了が現在の設置＋ちぎり＋おじゃま判定以前に来る場合や、確定予告が盤面を変える場合は仮想次盤面を使わず、実落下後の観測を待つ。自分のフィーバー中の相手攻撃を含む完全な判断の先読みは引き続き保守的に拒否する。

選択した現在手の操作承認では未確定予告だけの増減を無効化条件から外す。自分のフィーバー中の保留通常予告も現在の盤面を変えないため同様。確定予告は非消去手では厳密に照合し、消去によってその設置のおじゃま落下を止めることが確認された手では取消理由にしない。実盤面・ツモ・キュー・世代・操作状態・時計方針等の検査は維持する。拒否ログには変化した状態キーを追加し、過去ログの一律 `self state changed` だけから原因を断定しない。

可視範囲の異なる構築結果は同一の完全探索結果を保証しない。オフライン比較と実機の入力遅延は別に扱う。詳細と検証根拠は `WORK_LOG.md` の同日追記を参照。
