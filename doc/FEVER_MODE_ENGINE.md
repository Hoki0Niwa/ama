## 実装した範囲

2026-10-06追記：通常モードで相殺ゲージが有効かつ予告おじゃまがある「フィバ待ち」では、`gauge_wait.cpp`・`gauge_wait.py` が可視3ツモの相殺手順を調べる。生存する手順に限り、到達ゲージ、消える色ぷよの合計の少なさ、必要手数を比較する。残りゲージ1なら過剰な同時消し・連鎖より4個程度の最小相殺を優先し、ネクストの色に合わせて残す消去候補を選ぶ。ゲージ満了と全消しでは通常盤面の先読みを止め、実際のタネを待つ。

確定予告は非発火設置で最大30個落ちるとして端数列の全組合せを検査し、最悪の生存・ゲージ進捗を評価する。未確定予告の到着フレームは補わない。探索は深さ1から3へ進め、全初手の比較が終了した最も深い段階を使う。native予算12ms・継続候補幅8・展開数60000。時間切れの部分的な初手比較は採用せず、検査できた深さを `searched_visible` に記録する。相殺を進められる安全な手順がなければ既存の防御・救済なしの最短決着へ戻す。明示された相手配送予測は既存処理を維持する。

返答理由は `fever_wait_conserve`。`consumed_puyos` は現在手の色ぷよ消去数、`wait_forecast.choice.projected_popped` は先読み手順全体の消去数、`projected_gauge` はその進捗。仮のおじゃま盤面を実観測の次盤面として返さず、実落下後に再観測する。到達不能後の `recover_placement` も実際に到達する候補だけで同じ方針を使う。ゲージ加算0、フィーバー中、単独構築、Tsuは対象外。

- 全26キャラのフィーバー倍率1〜17リンクを `scoring.json` に追加。通常倍率とは別の表を参照する。未収録リンクは拒否し、通常倍率で代用しない。
- `fever_battle/mode.py`：相殺によるゲージ、準備時間／残り時間、通常盤面と予告の保管、フィーバー側予告を先に消費する相殺、通常復帰時の予告合算、タネ成功／失敗／全消し、時間切れを扱うイベント審判。
- `seed_search.cpp`・`seed_solver.py`：観測盤面と現在手＋NEXT2で探索。CPU時間・展開数・探索幅を制限し、打切り時にも最初の合法手を返す。最初の消去でタネが交換されるため、消去後を同じ盤面の建築として探索しない。保管通常盤面のおじゃまは相殺に使えるがフィーバー盤面には落とさない。
- `mode_engine.py`：別入口のprotocol 3。通常時は既存の構築／予告探索、フィーバー時はタネソルバーを使う。大量の確定予告等がある場合はゲージを満たせる即時消去も比較する。入力前の照合は試合・ツモ・周期・モード世代・タネIDと両席の状態を使い、自然な時計減少は許容するが締切不足は拒否する。
- `mode_tactics.py`：2026-10-06の伸ばし強化で、残り300フレーム以下は得点・タネ消化、それ以外は次の突入に向けた連鎖数を重視する。予告の存在や相手の現在1ツモでの発火有無だけでは即発火へ切り替えない。受けた後の発火口・生存は配置ごとにタネ探索で比較する。

通常用のprotocol 2と単独エンジンは引き続き別入口。新しいバイナリは `bin/t14/fever_battle.exe` へ配置し、実行中の既存バイナリを上書きしていない。

## 時計とイベント

時計は `clock_running` が明示的に真の区間だけゲームフレーム差で減る。`clock` イベントで観測した残りフレームと停止／再開を設定できる。`enter`・`seed`・`exit` は観測境界を明示したイベント。ゲージが満ちると `entry_pending` を返し、連鎖を終えてから `enter` を受け付ける。時間切れでも開始済みの連鎖は最後まで処理し、残り時間0から報酬で時計を復活させない。

タネは明示した盤面の `seed` イベントで供給する。実機未採取のタネを乱数で生成しない。タネIDは交換ごとに増やし、通常／フィーバー切替ではモード世代を増やす。周期位置は切替でリセットせず、観測した通算位置を使う。

おじゃま端数のカーソルもモード切替で勝手にリセットせず、既存のユーザー指定どおり実際に落ちた個数だけ進める。モード間の実機照合は未完了。再生状態には採用ルールのハッシュを含め、別のルール値で再生した結果を同一と扱わない。

ソルバーの時刻予測には通常盤面で校正した幾何時計を参考として用いた。**フィーバー中の時計・演出は未校正**なので `mode_timing_status=normal_geometry_reference_fever_unverified` を返す。時計が連鎖中も減るかは `clock_policy.count_chain_frames` で明示する。発火が締切内なら、連鎖終了が時間切れ後でも発火候補として扱う。追加の未確定予告の到着時刻を発明せず、探索結果には未スケジュールと表示する。

## 起動と入力例

```powershell
./build.ps1 -Target fever_battle
python test/test_fever_mode.py
Get-Content -Raw data/fever/examples/t14-seed-request.json |
  ConvertFrom-Json | ConvertTo-Json -Depth 30 -Compress |

```

1行JSONで1要求。`protocol_version: 3`、`rule: "fever_battle"` を必須とする。例は公開参照盤面に対する架空の観測で、実機観測ではない。

両席は通常版のフィールドに加え、`mode_generation`、`seed_id`、`prepared_frames`、`remaining_frames`、`clock_running`、`seed_base`、`seed_chain`、`stored_field`、`normal_confirmed/unconfirmed`、`fever_confirmed/unconfirmed` を渡す。`confirmed/unconfirmed` は操作中モードの予告と一致する必要がある。通常時の保管盤面はnull、フィーバー時は通常盤面を明示する。観測できない値は0で合成しない。

返答は `action: "place"` または `"wait"`。突入／タネ待ちや操作期限不足の `wait` を配置として入力してはいけない。入力直前は `authorize_mode_reply()` で照合する。`seed_options` で幅・展開数・CPU予算・安全フレーム・経路時間推定・`quick/extend` を指定できる。

## 2026-10-06 操作継続と致死量予告の補正

protocol 3の通常判断のうち、自分の盤面・ツモ・受けた予告だけを使う方針は `decision_dependencies: ["self"]` を返す。事前承認では自分の状態と共通ルール・試合・時計を照合し、相手のツモ・演出の変化で返答を捨てない。指定のない返答、タネの戦術、相手配送予測を伴う返答は従来どおり両者を照合する。

nativeの新しい `finish_probe` は可視3ツモと各落下の全端数列を列挙し、生存する消去または残る生存経路があれば不成立とする。12msの探索予算に達した場合も不成立。救済がなければ3回目のおじゃま落下まで長引かせず、中央死亡列が2回以下で埋まる配置を返す。移動・回転・高速落下の推定と接地・実測ちぎり時間で最短を選び、操作側が実際の現在位置から届く候補を再比較する。未知の4ツモ目や未確定配送を読まない。側列あふれだけを敗北確定の根拠にはしない。未知列の仮盤面はこの救済検査内だけで使い、実際の次の要求は再観測した盤面に限る。

通常の出現経路で配置を列挙できない高い盤面では、追加された要求の `active_placement` を使って `closing_transition` で現在位置の直下設置を検査する。元盤面の死亡しきい値を越えていても、ここからの消去で生存できれば `observed_current_pose_drop` として救済を残す。死亡するなら `no_rescue_fast_finish` を返し、配置なし例外で両AIを終了させない。観測済みの現在位置がない場合は補わない。通常のnative `placements` の死亡・到達判定、protocol 2、単独FeverとTsuは維持する。

## 2026-10-06 フィーバー伸ばしとおじゃま受け

`extend` は「見えている発火が必ず非発火より上」という従来の順位を廃止した。現在手＋NEXT2で確認した連鎖に加え、非発火盤面の発火口・連鎖の残り方を幾何評価する。到達可能な縦配置の列へ同色を1〜3個補った場合の連鎖数、必要個数、消去後の残り個数を調べる。これは未知のツモや実行手順ではない。`extension_potential.status` は `geometric_heuristic_not_visible_solution`、`solved` は実際に見える手順で規定以上を発火するときだけ真にする。

低いタネほど伸ばしの加点と試行余裕を大きくする。試行枠は `15 - seed_chain` 配置（3連鎖は12、9連鎖は6、15連鎖は0）。同じ試合・モード世代・タネIDを最初に観測した設置番号から数え、同じツモの再要求では増えない。タネ交換でリセットする。履歴は `placements_since_first_observed_seed` と明示し、未観測の過去を実測値にしない。規定3〜5は+3、6〜8は+2、9〜12は+1を発火の目安にするが、連鎖潜在値に上限は設けず、さらに伸ばす価値も比較する。中央が10段以上、次の操作時間不足、規定以上の発火口が残らない場合は建築を減点する。小連鎖・規定未満の発火は減点し、安全な伸ばしや本線がある局面で安易な小相殺を選ばない。

全消しには `extend` で連鎖3リンク相当の加点を与え、規定未満でも全消しの価値を比較する。幾何評価の消去後残りが0〜4個なら、全消しへ近づく配置にも補助点を与える（`all_clear_setup_bonus`）。未観測の次のタネを生成して全消しの確定手順とすることはしない。

`quick` の目的は `deadline_score_and_seed_turnover`、`extend` は `max_chain_for_next_fever_entry`。`quick` は期限内に発火する手順の全連鎖得点を比較し、全消しにおじゃまレート×30点相当の評価上の加点を与える。これは実得点・攻撃へのボーナスではない。続いて規定達成と次タネの操作余裕、全消し、終了時刻を比較する。開始済みの連鎖は期限後も最後まで得点するため、`total_points` と期限前に出る `points_before_timeout` を分け、後者だけで発火価値を切り捨てない。`completed_before_timeout` は連鎖終了、`next_seed_input_fits` は終了後の出現・次の設置・発火までの推定余裕である。次のタネの色・発火成功や時計報酬の獲得は保証しない。時間に余裕がある場合の `extend` は全連鎖数を主目的にする。

非発火では確定おじゃまを最大30個落とした後の盤面を評価する。生き残るだけでなく、規定連鎖数以上の発火口が残るかを `target_ignition_preserved` として比較する。端数列が未知なら6列の全組合せを列挙し、生存・発火口・伸ばし評価の最悪値を使う。端数落下の仮盤面を続きの探索や返答の `next_field` として使わず、1手の後に再観測する。全段（6の倍数）の落下は列の不確実性がないため、見えるツモでの先読みを続けられる。未確定予告の到着フレームは補わない。回復判断でも観測済みの到達候補だけで同じ伸ばし評価を使う。

しきい値と係数は共通の試作ヒューリスティック。入力時間・Fever演出は従来どおり未校正であり、潜在連鎖やおじゃま受けの判定は実機成功の保証ではない。再生と制御された色列の結果は [比較記録](../data/fever/baselines/2026-10-06-fever-extension.json)、再実行は `tools/verify_fever_extension.py`。通常のフィバ待ち・Tsu・ブリッジの入力処理は今回変更しない。

## 2026-10-06 通常盤面の必要色と落下を止める消去

`color_needs.cpp/.h` は到達可能な列へ同色を1〜3個補い、消える連鎖の最大値を本線候補とする。色・列・高さ・必要個数を記録し、現在ツモとNEXT2までの同色の個数と不足を照合する。本線候補と1〜2連鎖の相殺候補を分ける。でかぷよは各色の発火口を単独で評価するときだけ4個供給可能とし、4色を同時供給したとは扱わない。`normal_color_needs.status` は `reachable_color_completion_heuristic_not_executable_future`、供給の状態は `visible_color_counts_shape_and_placement_not_guaranteed`。同色の縦補充と色個数による近似で、特殊形状の置き方・複数色の同時補充・自然な未来色列まで証明するものではない。

フィバ待ちの順位は生存・ゲージ進捗・本線の必要色の温存・総消去数・手数・高さの順。同じ相殺進捗なら本線を支える色を減らす手を抑える。通常のおじゃま状態探索にも必要色の消費と可視ツモでの発火口評価を加える。予告のない通常構築では、選んだ手でNEXTの必要色の発火口が埋まるなどの明確な劣化があれば、本線連鎖数を保つ合法手へ変更する。通常の次手準備と現在位置からの回復判断にも反映し、回復では観測済みの到達候補を守る。実際の本線発火・全消し・死亡回避や、相手連鎖の配送時刻を使う選択をこの補助処理で上書きしない。

通常時に本線を現在手で発火できず、確定予告があり、本線を保てる小消しがあれば落下を止めて必要色を待つ。`intentional_small_clear` と `hold_nuisance_for_missing_color` により本線発火と区別する。小消し自体は通常ルールで得点・相殺・攻撃を計算する。規定未満という失敗条件を通常盤面へ持ち込まない。非消去手は確定おじゃま最大30個の落下後の発火口と生存を端数列の全組合せで比較する。未確定の配送時刻や未知の端数列を確定値にしない。

フィーバー中も必要色を `seed_color_needs` へ記録する。全初手比較が完了し、確定おじゃまを受ける全ての非発火手で生存または規定以上の発火口を保てず、選ばれた生存手が規定未満の消去なら `intentional_seed_failure` を真にする。理由は `fever_intentional_failure_hold_nuisance`。規定未満の消去はタネ交換で先読みを止め、`solved` を真にしない。探索打切りや時計だけを根拠に「おじゃま受けで発火口が塞がる」と断定しない。規定以上の発火口を保てる受け手があれば、従来の伸ばしと比較を続ける。
