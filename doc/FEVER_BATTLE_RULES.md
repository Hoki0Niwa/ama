# 通常盤面の対戦仕様と確認状態（T9〜T12）

更新：2026-10-05。対象：Steam版ぷよぷよeスポーツ、4色、両者の相殺時ゲージ増加0。現在の実装は独立した試作モデルであり、実機の審判としての一致は未確認。

## 得点

`data/fever/scoring.json` に全26キャラの通常盤面の1〜19リンクの倍率を転記した。出典は[男庭氏のVer.2.02の調査](https://puyo-camp.jp/posts/67754)。作品・調査者・転記日・状態を保存し、全キャラを `local_steam_verified: false` としている。20リンク以降は未収録として拒否し、他キャラの表や通の表で代用しない。

共通計算は `10 × 消去した色ぷよ数 × clamp(連鎖倍率 + 多色ボーナス + 各連結群ボーナス, 1, 999)`。隣接するおじゃまの消去は得点に含めない。同色の離れた群は個別に数え、多色数はそのリンクで消えた異なる色の数。

ボーナスは[既存の得点解説](https://puyonexus.com/wiki/Scoring)を暫定参照している。2／3／4色は2／4／8、連結4〜10個は0〜6、11個以上は8。これらは本機のSteam版で未照合であり、キャラ倍率表と出典・確認状態を分けた。13段目を含む盤面モデルの最大セル数は78。

通常盤面の開始レートは開発基準120。実機接続では観測した現在レートを必須入力とする。審判は `rate` イベントで変更できるが、マージンの自動スケジュールはまだ実装しない。旧メモの128秒は確定仕様として撤回する。[SEGAの1.02更新告知](https://puyo.sega.jp/portal/topics/info/20181217_001796/)ではPS4／Switch版のフィーバー初期値を192へ変更している。ローカルSteam版の設定と変化周期は別に確認する。

## 攻撃と相殺

[なもこ氏の仕様解説](https://puyo-camp.jp/posts/86313)を参照し、連鎖リンクごとに得点をおじゃまへ換算し、自分の予告を消費した余りを相手へ送る。予告が残る状態の1連鎖で最低1個相殺できることをモデルにした。

試作では `divmod(リンク得点 + 持越し端数, 現在レート)` を使う。最低1個の相殺が発生した場合も端数をそのまま残す。この端数との関係、および落下操作による加点の得点プールへの関与は実機照合待ち。連鎖点以外を勝手に加算しない。

攻撃は連鎖ID付きのパケットとして保持する。送信直後は未確定、送信元の連鎖終了時に残存パケットを確定する。相手が先に相殺した分を、終了時に再作成しない。相殺の消費順は試作では発生順。確定／未確定が混在した場合の実機の消費順は未確認。

消去した設置は残り予告の落下を保留する。後の非消去設置で確定予告から最大30個を落とし、未確定予告は落とさない。落下上限・送信確定時刻・消去開始と到着が重なる順序は実機で照合する。端数列は上記仕様解説の1→4→3→6→2→5列を使用する。

相殺ゲージの加算は審判設定として0だけを受け付け、攻撃・相殺自体は有効にする。エンジンにも両者の実際に観測したゲージ0と通常モードを要求する。ただし入力JSONの設定値はゲーム側の設定を証明しない。実機でゲージ加算0を設定する手段と、再戦後も維持することはT10の未完了事項。

## 全消し・敗北・イベント順

上記仕様解説では通常時全消しに4連鎖のタネと時間加算がある。試作審判は全消し後を `awaiting_seed` にし、実際に採取したタネ盤面の `seed` イベントが来るまで次の設置を拒否する。自己対戦もタネが未収録なら停止する。タネを省略したり、通の全消しおじゃま+30で置き換えたりしない。ゲージ加算0設定時にもこの効果が残るか、盤面交換時刻・周期進行・端数保持は実機照合待ち。フィーバー時計そのものはT14へ回す。

盤面遷移は既存の `core` の保守的なFever配置を使う。2個組も `plain_pairs=true` とし、13段目保持・14段目消滅のモデルを引き継ぐ。中央2列の12段目で敗北を判定する。消去との細かな判定順、上端のおじゃま消滅順は未確認。

イベントの順序は明示した `(frame, order)` の昇順。自己対戦の同フレームは登録順であり、実機の同時処理順を再現したものではない。イベント適用に失敗したら、そのイベント前へ状態を戻す。試合のリセットは新しい審判の生成で行う。

審判単体の `link.points` は明示的に与えた得点を扱う。自己対戦ではネイティブ盤面遷移の消去群からキャラ別計算で作る。観測ログとの校正では、実際の得点増分とこの計算を別に比較する必要があり、イベントログの再生一致だけでは得点式の実機一致を証明しない。

## 実機で先に採取する局面

1. 4個1色、5個、離れた同色群、多色、複数リンクの得点差。倍率の異なるキャラも含める。
2. 120未満のリンク、相殺最低1個、次リンクへの端数持越し、レート変更前後。
3. 相手連鎖中の相殺、確定と未確定の混在、連続消去→非消去、30個超の残り。
4. 双方が同じフレームに消去・設置・連鎖終了する場合。
5. ゲージ加算0での通常全消し、タネ盤面交換、次ツモと周期、落下後の死亡。

現時点でコードの固定局面テストとログ再生は実施可能。実機採取・一致確認・T13の対戦完走は未実施。
