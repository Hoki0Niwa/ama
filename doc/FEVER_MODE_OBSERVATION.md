### 実際の盤面を選ぶ

player +0xc8のシミュレータ盤面はフィーバー中も通常盤面などの古い状態を保持し、通常復帰直後も保管盤面と一致しなかった。フィーバー対戦の入力盤面には使えない。

field +0x100の可視セル表から、操作中の組ぷよのセルオブジェクトを除外する。Operate +0x38〜0x50の4参照と、各描画セル+8の参照を照合する。色や座標の近さで除去しない。+0x58〜0x70は除去対象ではない（除去すると固定済みのぷよも消える）。通常盤面では242記録中239で従来のシミュレータ読取と一致し、残る3記録は落下途中のおじゃま0x16を含んだ。0x16等の未確定セルは判断用の盤面に変換しない。全5形状を含む記録で確認した。

操作可能な処理段階・静止フラグが揃ったときだけ、この固定セル盤面を通常／フィーバー両モードへ渡す。上端セルを勝手に消したり浮いたセルを詰めたりしない。

### 時計の単位

ユーザーが画面の最初の時間を**15秒**と確認。内部初期値は**960フレーム**、上限は**1860フレーム**だった。連鎖・タネ演出を含むフィーバー観測3142件で、生の値が `max(0, deadline-frame)` と一致した。観測範囲では停止フラグは偽だった。

protocol 3に `clock_policy.frame_domain="pc_15209927_internal"` を追加し、生の期限をそのまま探索へ渡す。この指定時だけ1860まで許可する。省略時は従来のモデル（900開始・1800上限）を維持する。60を減算すると実際の操作期限を短くするため、表示時間への変換とは区別する。表示の丸め方、停止する例外条件、入力経路の所要時間は未校正。


## 変換と確認

`fever_mode_bridge.py` は観測したモード切替とタネ交換を世代で区別する。演出中・結果画面・混在フレームの要求は保留する。端数カーソルや履歴が不明なら推測で埋めない。エンジンは未知端数列を全候補で評価し、実落下後に再観測する。

読取り専用の確認はブリッジ側で行う。

```powershell
python fever_mode_memory.py --output observations/fever-mode-new.jsonl --seconds 120
python fever_mode_bridge.py --input observations/fever-mode-new.jsonl --output observations/fever-mode-shadow-new.jsonl --player 1 --max-decisions 150
```

保管盤面と復帰盤面の一致は3回の突入・復帰で確認。実測20局面×6カーソルのタネ探索では盤面・得点のモデル再生が一致した。これらは独立20タネの成功率や全26キャラの受入れではない。

時計表示の丸め、例外的な停止、モードをまたぐ端数カーソル、配送の同時処理順は未確認部分がある。起動と入力は [実機接続](FEVER_MODE_LIVE.md) を参照。
