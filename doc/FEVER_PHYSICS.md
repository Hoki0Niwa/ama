# T2：配置・落下・衝突・敗北判定

更新：2026-10-04

対象は段階Aの配置後の盤面遷移と、保守的な到達判定。実機の入力フレーム・壁蹴り・床蹴り・引っかけの完全再現は段階E。全キャラの実機照合はT7。

## 1. 座標と回転

列は0〜5、行は床から0始まり。画面内は行0〜11（1〜12段目）、隠れた13段目は行12。14段目は行13。

| 形状 | 配置のx・衝突判定のy | 配置のr |
| --- | --- | --- |
| PAIR | 軸の列・行。LEFTの子はx−1、DOWNの子はy−1 | UP/RIGHT/DOWN/LEFT |
| TRIPLE | 2×2の外接枠の左列・下段。x=0〜4 | 初期L字から時計回りに0〜3回 |
| QUAD | 2×2の左列・下段。x=0〜4 | 四角の中心で時計回りに0〜3回 |
| BIG | 2×2の左列・下段。x=0〜4 | 絶対色添字：0=赤、1=黄、2=緑、3=青 |

TRIPLEの回転は元の軸を固定する。回転後に外接枠を正規化するので、入力状態のx/yは回転前後で変わる。`core/piece_geometry.*` にセル位置・色・軸の枠内位置を集約した。同色3個組でも形はL字のまま。

QUADはセル位置を四角の中心で回転する。BIGは色だけを変え、位置を回転しない。BIGのrは初期色からの回転回数ではなく、着地させたい色を指す。実機の正変色順は赤→緑→青→黄であり、列挙値の順とは異なる。入力への変換は段階Eで行う。

**4個系は回転による壁越え・引っかけを使わない。** QUAD/BIGでは回転・変色の際に外接枠のx/yを変えず、蹴りによる移動・上昇も行わない。12・13段の壁が出現位置の左右にある局面で、どの回転・選択色でも壁を越える候補が出ないことを専用テストで固定した。段階Eで2・3個組の回転テクニックを拡張しても、4個系には適用しない。

## 2. 落下とちぎり

`Field::drop_piece(x, r, piece, rules)` は選択済みの配置の盤面結果を計算する。入力経路の可否は `move::generate()` で別に確認する。

1. セル位置・色・盤内の列を検証し、最初に剛体として接地する位置を求める。
2. 列ごとに下のセルから順に置く。上下の色順を保存し、別の列はそれぞれの高さまでちぎれて落ちる。
3. 選択したモデルで14段目以上のセルを消滅させる。Feverでは `row14` の障害物を残さない。
4. 呼び出し元が `pop()` または `pop_count()` を実行する。
5. 連鎖が完了した盤面に `is_dead(rules)` を適用する。置いた直後に中央12段目を埋めても、連鎖後に空けば生存する。

戻り値は `std::optional<piece::DropResult>`。有効なら残した個数 `retained`、消滅した個数 `discarded`、ちぎりの有無 `split` を返す。各形状のセル数は `retained + discarded` で保存される。14段目以上に捨てたセルの色は盤面・連鎖・全消し判定に参加しない。

不正な色・回転・盤外列などは `std::nullopt` とし、盤面を変更しない。すでに死亡した盤面や到達できない配置も、単独の遷移APIでは入力経路の判定をしない。探索は生成した候補だけを適用する。

`get_drop_piece_frame()` は設置1・ちぎりがあれば追加1という既存の仮コストを拡張したもの。TRIPLEでは列の高さだけでなく、その回転で各列の最下セルがどこにあるかも考慮する。実測フレームではなく、段階Bで置き換える。不正な配置は `std::nullopt`。

## 3. 13・14段目と未確認のタイミング

- 13段目のぷよは保存する。同色の接続・消去対象は1〜12段目のみ。下のぷよが消えると13段目から落下し、その後の連鎖に参加できる。隣接おじゃまの消去は13段目にも届く。
- **14段目に置いたぷよが消滅する点は2026-10-04のユーザー指示で確認済み。** [実機観察者による基本仕様](https://puyo-camp.jp/posts/86313)にも、14段目への設置・消滅と引っかけを使う無限回しが記載されている。
- ちぎり落下の前後どちらで消滅するかは、質問に対してユーザーから「タイミングは未確認」と回答された。Web資料でもこの順序は確定できていない。
- 既定の `rule::FEVER` は**試作上の仮定として最終着地点で消滅**する `AFTER_SPLIT`。比較用の `rule::FEVER_CONTACT` は剛体の初回接地時点で行13以上のセルを消滅させ、その後、残りを落とす `ON_CONTACT`。高い列と低い列にまたがる配置で両モデルの結果が違うことをテストする。実機確認後は既定を必要に応じて変更する。
- 操作中の空間は15段目までを仮の上限として扱い、14・15段目に最終配置されたセルは保存しない。15段目の操作可否・正確な天井条件はSteam実機未照合。16段目以上を経由する候補は作らない。
- Tsuの `drop_pair()` と `row14` は変更していない。Tsuを選択した新APIも、従来の軸13段目以下・子14段目以下と14段目の占有保持を使う。

## 4. 候補生成と到達判定

`move::generate(field, piece, rules)` の既定はFever。最大候補数は既存の `avec<Placement,22>` に収まる。空盤面では異色PAIRが22、同色PAIRが11、他の形状は各20候補。

- PAIRは従来の生成器を使い、順序・同色時の重複除去・既存の床蹴り判定を維持する。`rule::TSU` なら旧APIと完全に同じ候補。Feverでは4列目の敗北も判定し、14段目の古い占有ビットを障害物として使わない。
- 特殊ツモは左移動・右移動・落下・軸を固定した90度回転を、衝突しない状態だけで探索する。上昇・壁蹴り・床蹴りは加えない。高い壁の向こうへ配置結果だけを見て飛び越す候補は作らない。
- 特殊ツモの出現は左列x=2、外接枠下段y=11、初期回転0と仮定する。BIGの初期色はPieceに保存された色。出現位置・向きの実機照合は残る。
- 到達した状態から真下へ落とせる配置を、同じx/rにつき1件返す。2列幅の形状は必ずx=0〜4。
- 14段目への部分・全体の消滅自体は遷移APIで扱う。ただし引っかけ・上昇を要する廃棄経路を、特殊ツモの保守的な生成器はまだ返さない。生成されない配置のテストは遷移の意味の検証であり、実機で合法な入力経路を確認したものではない。

## 5. 敗北判定とTsuの分離

`core/rule.h` の `death_columns` はTsu=3列目のみ、Fever=3・4列目。`Field::is_dead(rules)` はその列の高さが12以上かを判定する。盤面は重力で詰まった状態を前提にする。

既存のbeam・DFS・発火・pvp・bench・puyop・tuner・testに散在した高さによる敗北判定は、明示的な `rule::TSU` で置き換えた。既存の探索をFeverへ切り替えてはいない。Feverの探索接続はT4で行う。高さによる評価・到達上限などのTsu固有処理は、T4の対象としてそのまま残す。

## 6. 検証

`python test/test_fever_transition.py` はソフトウェアPEXT・BMI2の両経路で検証する。

- 固定のセル図と、配列上で剛体を1段ずつ落とす参照モデル。全形状・全回転・端の列、2列の高さ0〜13の全組合せ、2種類の消滅タイミングを比較。
- 着地後の盤面・色順・残存／消滅個数・ちぎりコスト、独立したflood fillと列の重力による連鎖結果の比較。
- ランダム256盤面で、別の固定図から状態グラフの閉包を求め、特殊ツモ1280件の到達候補を照合。衝突判定もキャッシュあり・なしで比較。
- 高い壁、中央4列目の敗北、消去による救済、13段目が初回消去に参加しないこと、同じ上端への廃棄を繰り返しても14段目に障害物が蓄積しないことを確認。
- ランダム2000盤面で新旧Tsuの候補順・配置結果・衝突・設置コスト・敗北判定が一致することを確認。

このテストは定義したモデルとの一致を検証する。未確認の消滅タイミング・出現位置・特殊ツモの蹴り・操作上限をSteam実機の確定仕様として保証するものではない。
