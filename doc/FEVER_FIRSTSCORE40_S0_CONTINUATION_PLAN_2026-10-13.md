## 3. S0Gの正確な仕様

### 3.1 省略条件と成立理由

Actorが受け取る既存7項目の公開`Observation`だけを使う。

```text
t = observation.placed_total                 # 既に置いた手数
h = min(3, 40 - t)                           # 今回のprobeが読める手数
N = colored(observation.field)
    + sum(piece_mass(p) for p in observation.visible[:h])

if N < 4 * MAINLINE:                         # 今回のMAINLINEは10
    追加score-probeを省略して、同じB0へ進む
else:
    凍結済みS0と同じscore-probeを実行する
```

`colored`は盤面全体のR/Y/G/Bだけを数える。おじゃま`#`、空セル、累積投入数を数えない。`piece_mass`は既存の2個組=2、L/J=3、4個組=4、でかぷよ0=4を再利用する。でかぷよの文字列中の色1文字を1個と数えてはならない。置く途中で廃棄する色も供給上限には含める。上限を過小評価しないためである。

一度の実10連鎖以上には、各リンクで最低4個、合計最低40個の**異なる色ぷよ**が必要。同じぷよを別リンクで再度消すことはできない。このprobeは新しい不可視ツモを追加せず、途中の1〜9整理消しや上端廃棄は残る資源を増やさない。したがってN<40なら、その可視範囲にS0の採用可能な初回本線は存在しない。群消しが大きい13/14連鎖、色変更できるでかぷよも、この必要条件を回避しない。

**N=40では省略しない。** 今回は15連鎖の60個条件を使わず、点数目標も引き上げない。40個という閾値はデータに合わせた調整値ではなく、「初回本線=最初の実10以上」という契約から定まる。残り1/2手のときはその1/2手だけを供給へ加える。

この判定は「今回の可視範囲で本線発火なし」という意味だけである。40手までの達成不能、構築中止、発火許可の変更には使わない。B0の構築や1〜9の整理消しは従来どおり続ける。

### 3.2 最小の実装位置

新規`fever_battle/firstscore40_s0_mass_gate.py`に次を置く。

1. 公開観測からN/h/省略理由を返す純粋関数。契約・形式・Pieceを解釈できない場合は省略を許可せず、元workerの検証へ渡す。未対応状態を0個扱いしない。
2. `JsonProcess`のplanner側だけを包む薄いproxy。`score-probe`で条件成立時だけ「未実行・資源上界による解なし」の記録を返す。他の操作は元processへ委譲する。
3. `ScoreBackend`を継承する研究adapter。初期化後のplannerを上記proxyで包み、`ScoreBackend.choose()`とB0 fallbackはそのまま再利用する。比較用ラベルは`s0g`。

現`ScoreBackend`はplanner応答の`decision is None`で既存B0へ進む。ここを再利用すると、B0を別インスタンスへ切り替えたり、chooseごとに`mode`や`planner`を一時変更したりする必要がない。元のB0 process・キャッシュ・enemy状態を共有し続ける。`process`と`close()`をproxyから元plannerへ渡し、既存資源計測と終了処理を保つ。

S0の`score-probe`は実行時にplanner状態をresetすることを確認済み。省略した呼び出しが残すH1状態等に依存してはならない。本adapterは通常初回研究のS0にだけ使う。

総250msの時計は従来の`ScoreBackend.choose()`入口で開始する。guardの時間も含め、fallback時に時計をリセットしない。実行するprobeの内部25ms、遷移上限16000、B0の幅250・深さ8・仮想6・最大6threadを変えない。期限後の返答を成功扱いせず、timeoutは引き続き試行失敗にする。

### 3.3 記録と監査

全chooseで`gate_checked`、`gate_horizon`、`board_colored`、`visible_mass`、`mass_upper`、`gate_threshold=40`、`gate_elapsed_ms`、`probe_invoked`、`probe_status`を残す。

省略時は`probe_status=not_run_mass_impossible`、`decision=null`、実probe時間はnull、追加transitionは0。**列挙していないのに`score_probe_complete=true`としない。** 代わりに`proof_kind=colored_mass_bound`として、N<40による判断を記録する。`last_planner`はこの記録を含み、fallback timeout時も失わない。元S0とB0では従来の記録を維持する。

最初のF採用後の期限D、全予測transition、実発火、途中の最短深度と得点・廃棄・辞書順を従来同様に監査する。F採用後にN<40で省略されるなら、期待した残り発火手順と矛盾するため不整合として停止する。未知色、環境seed、試行IDをadapterへ渡さない。

**以下は次の独立実験に対して事前固定する新基準であり、旧S0Cを合格へ書き換えるものではない。** 最重要指標は、損失・死亡・timeoutを既に含む全開始試行の目標点達成率。個々のseedでlossがあること自体を拒否条件にしない。

| 実行失敗 | S0Gのtimeout率がB0、S0それぞれに対して+2pt以下（各128試行では増加2件以内）。死亡/配置不能の合計率はB0/S0の高い側を超えない。全件を主指標と時間統計に含める |
| Fの正当性 | 採用したFの実発火は最初の期限D以内。予測した合法遷移・通常点との不整合0。証明を出しただけの試行を成功へ加算しない |
| 費用 | 各キャラでP95がB0+25ms以下、CPU/判断がB0比+15%以内。正常返答の250ms超0。固定観測では省略対象のprobe往復費用が減ることを実測する。最大遅延・起動費用・メモリも表示 |

2ptの許容は研究候補の比較のために今回提案した範囲で、S0Cのloss3を消すための救済ではない。実行失敗はすでにPscoreを減らすが、成功数だけで遅延の悪化を無制限に許さないため別にも見る。実戦の操作許容や製品の遅延目標を2ptへ緩めたものでもない。

64seedをクラスタとして両キャラを一緒に再標本化し、平均差のbootstrap95%を10000回・解析RNG `0x540`で算出する。各対比の区間、キャラ別Wilson95%、gain/lossと一側sign-flipを併記する。主検定はS0G−B0だけ。S0G−S0とtimeout率差の区間も出し、点推定の許容条件に入ったことを統計的な同等性保証と呼ばない。

| 結果 | 次の扱い |
| --- | --- |
| 上記成立 | S0Gを次の**研究用**基準へ。次の構築改善をS0Gと比較する準備ができたと報告して停止。製品既定の切替は別計画 |
| 意味は正しく軽くなるが、効果保持・改善の証拠が不足 | S0Gの昇格は保留。既に得たS0の改善証拠を残して研究継続。追加seedや別予算をその場で足さない |
| S0Gだけの明確な悪化・不整合 | この軽量版を修正対象として停止。S0全体を無効と一般化しない |
| 元S0も新群で改善を再現しない | S0Cと新群を別表で示し、効果の不確実性を更新する。S0を無条件に優位と固定せず、新群に合わせた再調整を行わない |

## 6. 工数・保存物・停止位置

概算**0.5〜1.5人日**。純粋関数、proxy、研究adapter、薄い3条件harnessとテストが中心。学習・GPU・新C++探索・新binaryは不要。計算時間の出発点は前回256試行約15分なので、384試行は同じ環境で約20〜30分を見込むが未測定。回帰・再生・固定観測検査は別窓で計測する。

新しい`data/fever/baselines/<実行日>-firstscore40-s0-mass-gate/`へ、計画コピー、設定、source/native/build snapshot/hash、seed監査、テスト、保存再生、全反復時間、24smoke、384本試行、全steps、gain/lossとF監査、費用と最終判定を保存する。旧S0Cのraw、gate、inventoryは不変にする。

**次に実行する範囲はS0G-0〜4だけ。** 結果を提出して停止する。追加探索への時間再配分、probeの得点上界化、並列化、275/300ms化、H1/B2/Value/MCTS、最終holdout、製品・セカンド・Tsu・bridge変更、コミット/pushへ自動では進まない。

この工程はS0の価値を再びゼロから証明させるためではない。観測された改善を次の構築研究で利用するために、最小の費用削減と比較基準の整理を行う工程である。
