# フィーバーのマージンタイムと失敗発火（2026-10-06）

通常盤面に保留された予告を理由に規定未達の発火を選ぶ場合、次のタネを操作できないだけでは遅い発火と判定しない。連鎖終了時に時計が残れば、失敗連鎖にも時間が加算され、次のタネが出る。タネ探索は、終了の短めの見積もりでも時計が0になる配置を最後の失敗発火とする。現在の計測誤差の安全余裕を含め、`end_at >= remaining_frames + safety_frames` を条件にする。

それより早い規定未達の発火には、規定以上の可視手順、または次のツモが出る時間と小連鎖以上の発火口を残す非消去手があればそちらを選ぶ。全消しの規定未達も時間加算で次のタネが出るため、この判定から除外しない。おじゃまの実落下をまたぐ架空の後続手順は作らない。生存する発火口を残す別手が探索予算内に見つからなかった場合は、操作を放棄せず従来の実行可能手を返す。その例外を`failure_timing_status`で示す。フィーバー盤面へ確定予告が降って発火口を失う強制局面は、通常盤面への予告を保留する目的と区別する。

最後の操作可能ツモは時計0でも操作を続ける。積む手の準備判断は、通常盤面への保留予告を再利用キーに含める。出現が予測より遅れ、次のツモが出る余裕を失った積み判断を再利用しない。時計が十分残る間は先読みを利用する。

2026-10-06追加：この延期判定は通常盤面の保留予告だけでなく、Fever盤面の確定・未確定予告と観測した相手連鎖にも適用する。少量の実落下を受ける手を一律に除外しない。全端数列で生存して小連鎖以上の発火口を残し、落下演出後に次ツモが出る時間があれば1手積んで再観測する。予告減少から次操作可能までの実測6例は41～71F、両境界が確定した4例は1個46F・4個50F・12個55F・30個71F。最大71Fに余裕9Fを加えた80Fを延期判定の推定予算に使う。[固定した実測根拠](../data/fever/baselines/2026-10-06-fever-garbage-ready.json)。全盤面の保証上限ではない。

直接の幾何評価で規定連鎖の発火口が見つからなくても、実落下後の各候補盤面で残りの可視NEXT2を使って非消去配置から規定以上へ発火できる手順を調べる。成功する手順が全端数列で期限内に存在する場合は、埋まった発火口の復旧候補として優先する。途中の規定未達消去はタネが交換されるため復旧手順として認めない。さらに実落下が必要になる手順も再観測の対象として打ち切る。返す操作手順は現在の1手だけで、列不明の盤面を決め打ちして次の配置を送らない。復旧探索は既存のノード・時間予算を共有し、未探索を復旧可能と推定しない。発火口保存や可視復旧が見つからない致死局面、次ツモを待つ時間がない局面では実行可能な相殺・最後の発火を残す。

`remaining_piece_budget`は現在のツモを含めた出現数の概算。最短の非消去周期`placement_frames + spawn_frames`と、13段ちぎりの推定増分を加えた周期の両方を使う。可視手順のちぎりは従来どおり盤面形状から個別に計算する。未知色の発火確率、自然落下速度、長い操舵時間、おじゃま落下演出を確率分布で推定している値ではない。幾何的な発火口の保存は将来その色を引く保証ではない。可視3ツモの実行手順と概算を区別し、探索の手数・時間上限は増やさない。

## Web調査とSteam版での扱い

2026-10-06復旧の追加：可視3ツモで規定連鎖に届かない場合でも、既におじゃまがある盤面を失敗確定とは扱わない。色ぷよが4個以上残り、11段以下に合計4個以上の積む余地があり、中央2列の高さが10未満なら復旧の候補とする。これは未知色の将来の正規発火の証明ではなく、タネを維持して次の観測へ進むためのヒューリスティック。端数列不明の実落下は全組合せで空きと生存を確認する。おじゃまを仮に除去した盤面や不可視ツモで実行手順を作らない。

この復旧待ちは通常の伸ばしの固定手数上限から分離する。毎ツモの実盤面・可視NEXTで判断し直し、何手積んだかだけでは失敗発火に切り替えない。空きや生存を失う場合、または実落下後の演出待ち＋次操作14F＋初消去13F＋安全余裕が時計に収まらない場合には待てない。ちぎりは現在手の形状から計上し、将来の未知配置のちぎり・成功確率は保証しない。`repair_workspace_available`と`repair_status=reobserve_each_piece_unknown_colors_not_proven`で可視の成功証明と区別する。確定予告がなくなった後にもこの判断を適用し、準備済みの手の再利用時にも次操作時間を確認する。

探索上限と可視範囲を増やさず、保存された条件で可視3ツモでは解けない最初の盤面から5手目の6連鎖まで、各回可視3ツモだけで再生検証した。これはオフラインモデルの確認であり、新AIでの実入力・成功率の受入れではない。

[SEGAの2018-12-17の更新告知](https://puyo.sega.jp/portal/topics/info/20181217_001796/)は、PS4/Switch版eスポーツv1.02のフィーバールールの初期マージン設定を192に修正すると説明する。現在のSteam対戦の設定値をこの資料だけで192と断定しない。

[イノセンス氏の2004-06-01の原測定](https://www.inosendo.com/puyo/margintime.html)は、PS2版フィーバー・アルル同士・中辛の条件で、開始192秒、以降16秒間隔のレートを記録する。初期120に対し90、60、45、30、22、15、10、7、5、3、2、1。消去時点の時間で換算し、端数得点は次の消去へ持ち越す。これは旧フィーバーの測定であり、Steam版の同じ周期・列の確認ではない。[参考データ](../data/fever/margin_reference.json)に出典と適用範囲を保存した。

実対戦では各観測の`target_point`を正とする。設定が未確認の間は現在レートで計算し、192秒を決め打ちした未来予告を作らない。観測レートが120から参考列へ移ると、前後の観測フレームを境界の幅として保持し、参考の16秒間隔で将来レートを推定する。自分は境界の遅い側、相手は早い側を使い、攻撃量を過大評価せず、相手の攻撃量を過小評価しない。周期・列と矛盾する観測は推定を無効にする。`margin_forecast.status`はこの推定をSteam実測済みとは表示しない。

オフラインで設定とフレーム原点が既知なら、`margin_policy: {start_frame: ..., initial_target_point: 120}`を明示できる。現在レートが参考列と一致しなければ未来推定を無効にする。通常のnative予告探索、フィーバーのタネ探索、列不明のPython単手判断は、将来の各消去時刻に適したレートで端数を持ち越して相殺・送信を計算する。マージン境界の近くでは準備した手をそのまま使わず、現在観測で判断する。通常の相殺待ち専用の小消し優先判断もこの領域で避ける。未知の設定・ハンデを自動的に補完しない。
