## 4. 主な発見

### 4.1 本線を自分で崩す問題は前夜より減っている

- 勝者が最初に撃った時点（10連鎖以上）で敗者が10連鎖以上を保持していた局は 229局中174。そのうち、その後に撃てた局が141、撃てずに終わった局が33。33局の崩れ方は、保持したままFeverへ入る8、構築側の1〜2連鎖で崩す10、小さく消す手（`tactics_offset`）で崩す8、積む・構築側の積みなど6、崩れを確認できない1。
- 前夜は同種の集計で55局（敗者が一度も撃たなかった125局中）、うち `tactics_stack` 18・`tactics_offset` 27・構築8。定義が違うため概算だが、`tactics_stack`・`tactics_offset` による崩しは明確に減った。
- 残る形：構築側（`normal_build_or_fire`）が保持10以上を1手で4以上減らす手が、保持10以上の判断4,843のうち164回（C0 102、C1 29＋22、C2 11）。ただし 117回（71%）は中央値205フレーム後に保持10以上へ戻り、一時的な被せだった。勝者側にも124回あり、敗者の特徴とは言えない。

### 4.2 先に撃った側が負けやすく、同じ連鎖数なら返した側が勝つ

- 両者が10連鎖以上を撃った154局で、先に撃った側が負けた局が96、勝った局が58（62%対38%）。
- 両者が8連鎖以上を撃った174局で、勝者の最初の連鎖数が敗者以上の局は153（88%）。同数40局では、後から返した側が30局（75%）勝つ。
- 発火の盤面は、勝敗にかかわらず約63〜66個（12連鎖で中央値64個、13連鎖で63個、14連鎖で66個）。15連鎖は発火621回中5回。13連鎖が194回で最多。つまり盤面がほぼ満杯になった側から撃っている。

### 4.3 相手が既に同等の連鎖を持っている所へ先に撃っている（今夜の新しい測定）

最初の10連鎖以上の発火（231局）で、撃つ側の判断記録にある相手盤面（`enemy.field`）の保持（エンジンの `holding`）を測った。

| 発火の時点の相手の保持 | 局数 | 先に撃った側の勝率 |
| --- | ---: | ---: |
| 発火した連鎖数−1 以上（同等の返しを持っている） | 94 | **35%** |
| 10以上だが発火した連鎖数−1 未満 | 74 | 73% |
| 10未満 | 63 | 70% |

- 94局のうち82局は、撃った時点の自分の盤面が60個以上（中央値64個）。撃った理由は `normal_build_or_fire` 78・`tactics_offset` 16。相手の盤面は中央値60個で、同じ連鎖をより少ない個数で持っている。
- 解釈（未検証）：撃つ側は盤面の余白が尽きて撃っており、待つ選択肢が小さい。相手の保持との関係を発火判断に入れても、余白が無ければ撃たざるを得ない。ただし相手が自分より少ない個数で同等の連鎖を持つ局が多いので、構築の効率（1連鎖あたりの消去ぷよ数、置き場の使い方）の差が先に撃たされる原因になっている可能性が高い。
- 限界：相手の保持が大きい局は、そもそも相手が有利な局に偏る。因果は未確認。

### 4.4 Fever前後：塊を受けたあとはほぼ逆転できない（前夜と同じ）

- Feverから戻った335回のうち、確定おじゃまが300個超の160回は96%が負け（100〜299個の44回は98%、30〜99個の14回は100%、0個の108回は30%）。
- 通常→Feverの遷移402回のうち、おじゃまが400個超のまま入ったのが133回で、そのうち125回は入る手が `tactics_offset`（多くが1〜6連鎖）。400個超を持って入った158回（戻り判定）は93%が負け。
- 先に突入した側が負けた局は128局（勝者側の該当も97局）で、これ単独では勝敗を分けない。

### 4.5 セカンド不発（42局、中央値9,171フレーム）

- 負けた側の最後の通常区間は中央値5判断。保持は3連鎖以下が39局、盤面のお邪魔は中央値36個。Feverから戻ってすぐ相手の次の塊を受けて終わっている。前夜と同じ形。

### 4.6 タネ消化失敗：ラフィソルの特殊な組ぷよ

- Fever内のタネ発火927回のうち、レベル未満は72回（7.8%）。66回は最終的な敗者側。
- 意図的な失敗（`fever_intentional_failure_hold_nuisance`、おじゃまを保持）33回を除く39回が意図しない失敗。内訳は1P（ラフィソル）28回（全く消せず1連鎖で終わるのが13回）、2P（アリィ）11回（1回）。
- ラフィソルの全消失敗13回のうち11回は、出現したのが特殊な組ぷよ（`0:`1個・`4:`2×2・`J:`・`L:`）。ラフィソルのFever内の組ぷよの半分は特殊形（759／1,500）。

### 4.7 自滅（通常盤面で満杯のまま死亡）

- `few_nuisance_death` 10局：長い局（6,000〜7,500フレーム）で、盤面61〜69個・保持6以下のまま `tactics_stack`／`normal_build_or_fire` を続け、最後に `no_rescue_fast_finish` で死亡。降ったお邪魔は無い（round-5・54・55・98ほか）。
- `died_holding_main` 12局：round-63・73・114・118 は、構築側が保持10〜13を1手の1連鎖で3以下へ崩す、または `tactics_stack` で保持を使わずに満杯になって死亡。

## 5. 修正候補（優先順。採否はユーザー判断）

1. **発火判断に相手の保持を入れる（4.3）**。相手の盤面は判断時に観測できる。同等の保持を持つ相手へ先に撃つ前に、(a) 待てる余白があるか、(b) 余白が無ければ、少しでも大きく／相手より先に有利な形で撃てるか、を評価に入れる。まず `bench` ではなく、同一シードの実機または独立シミュレーター（`fever-simulator`）で、現行と変更を勝率で比べる。
2. **構築の効率（4.2・4.3）**。同じ連鎖数を少ない個数で持つ側が先に撃たされない。単体測定では13連鎖を約65個、1連鎖あたり約4.6〜4.8個。目標は15。連鎖数を1つ増やす、または同じ連鎖を数個少なく撃てる構築を狙う評価（本線の形・色の使い方）が要る。
3. **ラフィソルのFever内の特殊組ぷよのタネ消化（4.6）**。特殊形（`0:`・`4:`・`J:`・`L:`）での全消失敗13回を局面ごとに再現し、探索の候補に有効な置き方が無かったのか、操作側の除外が候補を消したのかを分ける。
4. **満杯での自滅（4.7）**。お邪魔が降っていない局で、盤面60個以上・保持が小さいときに、死ぬ前に確実に消す（小さくても発火する）判断を強める。`no_rescue_fast_finish` に入る前の数手。
5. **Fever前後（4.4）**。400個超のおじゃまを保持したまま `tactics_offset` の小連鎖でFeverへ入る133回の形を、入らない選択肢と比べる（Fever突入を避ける、または突入前に本線で相殺する）。実際の効果は未測定。
6. **操作（2）**。壁寄りの `measured` 6件のみ。件数が小さく優先度は低い。直すなら `fever_play.py` の測定済みプログラム選択（`measured_skipped` を見る）。

## 6. 限界

- 集計はログからの事後の読み。因果は未確認で、4.3 は相手が有利な局に偏る影響を除いていない。
- 保持（`holding`）は「1手で撃てる最大連鎖」で、消去後に落ちたおじゃまによる低下や、色の巡りを含む。
- 前夜との比較は定義が異なる箇所がある。件数の比較は参考値。
- 両席のキャラ・beam・先読みが固定のため、席の差は原因に分けられない。

## 7. 追加調査：自分のFever中の「即発火」の条件

依頼（ユーザー）：フィーバー状態の即発火の条件が緩く感じる。仕様は「伸ばすのが基本、即発火は2つの場合だけ」（`FEVER_MODE_ENGINE.md` 5.1、2026-10-08）。

### 7.1 測定（Fever内のタネ発火927回、`seed decision` を発火の設置と結合）

| 項目 | 値 |
| --- | --- |
| `press` あり（仕様の即発火） | 132回（14%。`opponent_in_fever_holds_nuisance` 85、`lands_on_their_normal_board` 44、ほか）。前夜は7% |
| `press` なし | 795回。うち規定（レベル）ちょうどが360回（全体の39%、前夜47%）、規定未満が68回 |
| 自分の「待つ」計画（`wait`）が、発火した連鎖より長い連鎖を示していたのに発火した回 | 176／915回（19%）。差は1連鎖が大半（158）。そのうち規定以下で発火が99回 |
| 規定以下の発火で、残り900F以上・盤面36個以下・`press` なし | 60回（6.5%）。残り900F以上だけなら112回 |
| 発火した連鎖−レベルの平均（`press` なし） | 0.76。待った判断が見ていた連鎖−レベルの平均は1.19 |
| 前夜（185局）との比較 | `press` なしの規定ちょうどの発火は 47%→39%。`press` の割合は 7%→14%。10-08以降、この部分の実装は変えていない（悪化ではなく従来の挙動） |

- 比較した `wait` 計画の価値は、規定を超える発火との差が小さい。`fire` が `wait` より上になった123判断（価値が正）の比は中央値1.22、4割弱は1.15以下で、`seed_odds`（0.85）・`piece_odds`（0.5）の割引で決まる接戦。
- `press` の中身：`opponent_in_fever_holds_nuisance` は相手の通常盤面用の保留が **1個でも** あれば成立する（`fever_battle/mode_engine.py:1037`）。今夜の成立148判断では保留の中央値は218個で、6〜29個が7判断、30〜99個が23判断（残りは100個以上）。`lands_on_their_normal_board` は「送る量−自分の予告−相手盤面の保持」が正（1個でも）になれば成立し、余裕の下限が無い（同:1047）。成立すると `PRESSED`（15連鎖の10倍）が加点され、他のどの手順にも勝つ。
- 不明：発火した連鎖が伸ばせたかどうかの反実仮想（伸ばしていれば得点・Fever時間・次のタネがどうなったか）は、ログだけでは測れない。実機で「緩い」と感じた局面の記録（局・フレーム）があれば、その判断を再現する。

### 7.2 判断（暫定）

- 仕様の2条件以外の即発火は、実装上は存在しない。ただし「伸ばす」手の価値（`wait`）が割引され、規定+1連鎖の発火が接戦で先に出るため、2条件以外でも規定ちょうど〜+1で撃つ回が多い（上表）。「緩い」感覚はこの接戦の扱いと、`press` の下限が無い点が原因の候補。
- 変更するなら、(a) `seed_odds`・`piece_odds` の再測定（実機でタネを撃てた割合）、(b) `press` に下限（保留量・余裕の最小値）を入れる、のどちらかを、タネ単体のベンチ（`fever_battle/bench_seed.py`）と実機で比べる。

## 8. 追加調査：Fever中の相手への「潰し」

### 8.1 測定（自分は通常盤面、相手がFever中の判断：前夜5,408回、今夜5,906回）

判断時の選択（`fever_disruption.kind`）を、判断時の自分の保持（`holding`）別に数えた。

| 自分の保持 | 種類 | 前夜（5,408） | 今夜（5,906） |
| --- | --- | ---: | ---: |
| 4〜9連鎖 | `overpower` | 18（0.7%） | **0** |
| 4〜9連鎖 | `main_pressure` | 11 | 3 |
| 4〜9連鎖 | `jab` | 9 | 11 |
| 10連鎖以上 | `jab` | 9（0.7%） | **2（0.2%）** |
| 10連鎖以上 | `overpower` | 4 | 0 |
| 10連鎖以上 | `main_pressure` | 94（7.6%） | 76（7.2%） |
| 3連鎖以下 | 3種計 | 18 | 26 |

- 全体では潰しを選んだ判断が 163（3.0%）→118（2.0%）。消えたのは「構築途中（保持4〜9）の `overpower`／`main_pressure`」と「保持10以上での `jab`」。完成した本線を使う `main_pressure` と、保持の小さい盤面での潰しは残っている。
- 途中の実行（10-14 14:28：6試合を除く30試合、18:39の82試合）でも同じ傾向（`tactics_disrupt`＋`kind`が0.25〜0.38%）。

### 8.2 原因（コード確認。因果の再現は未実施）

1. `fever_battle/tactics.cpp` に、10-14に入れた2つの課金がある（未コミットの差分、実機のバイナリには入っている）。(a) 消さずに置いても、引き金を埋めた分を `main_links_spent` に加える（約317行）。(b) 小さく消す手でも、置く前の保持（`main_held`）から消去後の保持を引いた分を加える（約214〜237行）。
2. `main_links_spent` は `defense_state.lost_links` になり、`lost_links > 0` かつ Fever中の相手に対して `unready_main` が成立する（約398行）。`protected_main = (unready_main || …) && root_cells >= 24` が成立すると、`disruption = {}`（約426行）。**つまり、本線を1連鎖でも埋める／削る潰しは、費用が足されるのでなく、潰しの加点そのものが0になる。**
3. 構築途中（保持4以上＝`mainline_min` 4）の盤面で、小さな潰し（`overpower`・`jab`）は引き金の近くに置くため、ほぼ全て `lost_links > 0` になる。10-14前半の（A）（B）の導入後に、この種類が消えている。
4. `_window_build`（`mode_engine.py`）は、相手の連鎖が観測されて終了時刻が分かり、保持10以上のときに `stack`／`offset`／`take` の戦術返答を構築側の置き方へ置き換える。相手がFever中の局面（5,906判断）のうち322判断（5.5%）が `normal_build_in_window` で、置き換えられた返答の中に潰しがあったかどうかは記録に残っていない。

### 8.3 修正候補（採否はユーザー判断）

1. `protected_main` で潰しの加点を0にする条件を、「本線を埋めたかどうか」でなく、「本線を撃てる状態を失うか（`holding` が目標未満に落ちる、または引き金を完全に失う）」に絞る。保持4〜9の途中の盤面では、潰しの価値（`disrupt` 3000×評価）と埋める費用（`mainline` 1120×リンク）を並べて比べる。
2. `_window_build` が置き換える返答に、Fever中の相手への潰し（`fever_disruption.kind` が `jab`／`overpower`）を含めない。
3. 確認：同一の局面群で、(A)(B)を戻した変種と現行を `tools/investigate_main_keep.py` 系の再現で比べ、潰しの選択数と、本線の保持の変化を測る。ログの判断は、敵のFever時計・フェーズなどの要求の欠落があり、そのままでは再生できない。
