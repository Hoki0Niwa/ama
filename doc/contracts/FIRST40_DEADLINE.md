# B1：期限付き構築の再現契約

入口は `tools/bench_fever_first40_deadline.py`。B0と同じ参照native・通常構築を使い、B1の期限付き構築を比較する。nativeの出所とhashを検査し、製品の探索・既定設定は変更しない。

## 終端と比較

空盤面・標準周期位相0・可視3・最大40配置。最初の実10連鎖以上が15以上なら成功、10〜14は失敗終了。1〜9は継続。死亡・配置不能・timeout・未発火を分母へ含める。これは得点で成功を判定するPscoreとは別契約。

幅250、最大深さ8、仮想6列、native6thread。B1の切替条件・予算は `first40_deadline_backend.py` とツールのmanifestへ保存する。B0との同seed比較、固定124観測の費用検査、保存B0の再生を分ける。固定観測を独立した空盤面試行へ数えない。

開発判定は純増が正、loss0、各キャラgain>=loss、B1の危険終端がB0以下。通過しても追加開発へ進む条件で、最終採用ではない。全試行の結果・手順・失敗時間とsource/config/native/specificationのhashを新規出力先へ保存する。

正確な設定・固定群はツールとローカルbaselineを参照する。保存済み実験の凍結仕様は成果物内のコピーを使う。[結果](../RESEARCH_RESULTS.md)。
