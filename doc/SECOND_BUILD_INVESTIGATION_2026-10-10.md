# 本線後の通常盤面の再構築：調査

日付：2026-10-10。対象は本線発火後／Fever復帰後の通常盤面。タネの伸ばしソルバーとは別。実装の静的調査であり、性能改善・実戦受入れの報告ではない。

## 結論

Fever専用の再構築評価へ変える理由はある。ただし現行は通の小さいセカンド用分岐の直移植ではなく、初回と同じ大連鎖ビーム探索で再構築する方式。問題候補は、履歴による目標切替しかないことと、特殊ツモ対応の配置探索の中で通由来のポテンシャル・得点評価を使っていること。先行ユーザー方針の13〜14連鎖安定を維持し、再構築のためだけに小連鎖へ目標を下げる変更は提案しない。

## 実装で確認したこと

| 項目 | 通 | 現行Fever |
| --- | --- | --- |
| 構築の選択 | `ai/ai.cpp` の `think` が資源差・相手全消しでAC、相手おじゃま阻害でFASTを選択。AC/FASTは可視2組のDFS | `fever_battle/mode_engine.py::_normal_options` → `SoloBuilder` → 対戦workerの`op=solo`。通常は一貫してFever用ビーム |
| セカンドの認識 | 専用の本線発火履歴ではなく現在の盤面資源を比較 | 通常実観測最大が初回目標−1以上、または`mode_generation>0`なら初回後。Fever経験だけでも切り替わる |
| 構築と発火 | 戦術とBUILD/AC/FASTで判断 | `second_target_chain`指定なら同じ構築／発火目標。nullなら19を構築目標にして安全容量まで積む。安全に積めないときは発火条件1 |
| 盤面とツモ | 2個組 | 実際のビーム展開・可視発火検査はPiece、キャラ周期、Fever合法配置に対応 |
| 途中の整理 | DFS等で評価 | `preserve_build`は順位順で現在消去0〜2連鎖の候補を探す。小消しは禁止していない |

通の資源小判定は色ぷよ20個以下または相手が自分の2倍以上、かつ相手22個以上（`ai/gaze.cpp::is_small_field`）。「本線後なら必ず小さいセカンド」という実装ではない。Feverの現在の構築は`config.json`の`fever`評価（なければ`build`）を使い、通の`ac`・`fast`・`freestyle`を切り替えない。任意設定の`fever_aim`は別だが、既定`normal_build.objective`は`mainline`。

## 改める価値がある箇所

1. **発火履歴と現在の構築状態を分ける。** 初回／セカンドの目標設定の履歴は残す。その上で、色ぷよ残量・おじゃま・発火口・安全な配置数から「整理／復旧」「大連鎖構築」を判断する。本線直後の少量残しとFever復帰時の保存済み大盤面は同じ状態ではない。履歴だけで同じ評価を当てる必要はない。
2. **通の得点をFeverの得点に置換する。** `fever/search.cpp::expand`は`chain::get_score`、仮想未来の候補順位は最大通得点の6本合計（通常の`aim=false, stretch=true`）。共有`beam::eval::evaluate`の`score`項も通のPOWERに基づく余分消去の利益・損失を使う。既定Feverの`score=400`なので実際に有効。戦術側の実攻撃はキャラ倍率を使うが、通常構築側は同じではない。連鎖数目標を維持しつつ、通常倍率・同時消しを使った資源効率へ置換する。タネ用Fever倍率は使わない。
3. **単色追加ポテンシャルを、Pieceでの実現性と組み合わせる。** `ai/search/beam/quiet.cpp`は1列に同色を最大3個足す仮想発火。到達範囲も中央の出現列から高さ11の壁で止まり、追加は12段まで。これ自体は安い近似として有用だが、L/J/4/でかぷよの余分なセルや実測上端操作を表さない。可視ツモで何手・どの余分セルを伴って発火口を作れるかを併用する。全ビーム節点で完全探索すると高コストなので、浅い層や上位候補から比較する。
4. **整理は残存連鎖の改善として評価する。** 消した連鎖数が0〜2という条件だけでは有益な整理か判断できない。残存ポテンシャル、発火までの必要手数、安全配置数、おじゃま除去を消去前後で比べる。過去の一律小消し禁止は悪化したため再導入しない。3連鎖以上を整理に使う提案は先行の本線保護方針と衝突し得るので、まず0〜2の候補内で比較する。
5. **仮想色列の最大値だけでなく安定性を測る。** 現行は各列の最大得点合計、`chain`はどれか1列の最大値。目標に達した仮想列の割合、到達までの手数、低い側の達成量を診断に追加する価値がある。ただし未知色は試作生成モデルで、実ゲームの成功確率と断定しない。単純な連鎖数優先や深さ16化は10/09に改善せず不採用だった。

以上はコード上の不一致／設計候補。9〜12連鎖の再構築残件をこれらが引き起こしたという因果は未証明。固定14連鎖だけを原因と断定する根拠もない。

## 戦術との接続

相殺でゲージをためてタネを消すことと、自前盤面の次の大連鎖を構築することを分ける。自分の通常盤面・保存盤面、相手の通常／Fever、ゲージ、確定攻撃の着弾までの時間が違えば、同じ小連鎖でも価値が変わる。相殺ストックと時間内の返しは既存戦術層で比較し、構築評価へ一律の小消し／突入加点を足さない。相手がFeverというだけで本線を崩す変更は先行方針と矛盾する。

SEGAの公式説明も相殺によるゲージ蓄積とタネの大連鎖をルールの特徴としている。ただしセカンド構築の最適な戦術は示していない。公式資料を上記設計の性能根拠にはしない。

- https://puyo.sega.jp/puyopuyo%21%21/play/rule/04/index.html
- https://www.sega.jp/game/detail/puyopuyo_esports/

## 比較の順序

まず実戦の本線後盤面・Fever帰還盤面・可視ツモ・周期・相手状態を固定ケースとして収録する。無妨害の空盤面再構築も対照に含める。現在方式、Fever通常得点への置換、整理評価追加、Piece発火実現性追加を一つずつ比較する。

測定は13／14連鎖到達率、到達手数とゲーム内フレーム、途中整理、容量発火数、死亡、判断待ち。残ぷよ／おじゃま量とキャラ周期で分け、複数回の大連鎖まで継続する。ゲージ・相手反撃・保存盤面帰還も含めた試験を別に行う。10/09の試作色列では初回13/13/13/14に対し再構築9〜12の残件が記録されているが、実戦の到達率ではない。現在のupper重み追加後の比較でもない。

本調査では実装・設定・バイナリ変更、ビルド、性能比較、ゲーム操作を行っていない。変更するなら最初はFever専用の構築得点と診断の追加を小さな独立変更として試し、共有Tsuコードを変えない。

## 2026-10-10〜11 実装と追加指示

上記は調査時点の記録。ユーザーの変更依頼と「初回もキャラ別倍率が必要」「通の盤面を埋める量で十分としない」という追加指示により、以下を実装した。

- **初回を含む通常構築全体**のビーム候補、可視発火、`eval`／`next_score`をキャラ別通常倍率・既存Feverボーナスへ統一。`data/fever/scoring.json`から生成する`fever/normal_scoring_data.h`を使い、カレントディレクトリに依存しない。生成結果の一致を回帰検査する。TsuバイナリとFeverタネの倍率は変更しない。
- `fever/evaluation.cpp`でFever用のポテンシャルを評価する。単色追加は近似だが、通の2個組用の壁境界は継承しない。実得点の同時消し増分は同じキャラ・同じ連鎖長の4個消し得点で正規化して幾何評価へ加点する。初期重みでは`bonus * score / max(1000, pure_score)`。終端の実得点順位は正規化せず、実得点を6仮想列で合計する。
- 通の「余分な1個は末尾の1/4連鎖になったはず」という機会費用を廃止。特殊ツモで自然な5〜6個消しはこれで減点しない。発火リンク以外の各リンクで6個を超える色ぷよだけを、1個あたり`chain / 4`評価点で減点する。おじゃまは得点にも色ぷよ消費にも数えない。`score`重みは、このFever専用評価では同時消し効率への重みとなる。
- 初回完了の実観測またはFever経験後に`rebuild`を設定。色ぷよ24個以下／おじゃまありを整理・復旧段階、成長済みの清潔な盤面を大連鎖構築段階とする。2セルの発火鍵が必要というだけで成熟盤面を復旧扱いにしない。
- 復旧では現在の0〜2連鎖の候補に対し、残存ポテンシャル、鍵数、次ツモの安全な非消去配置数、おじゃま量と可視Pieceによる発火を比較。NEXTは最大2組、各層幅6の確認であり完全な2手探索の保証ではない。未知色は補わない。残存連鎖・おじゃま・配置余地が改善しない小消しは安全な非消去候補の後へ回す。目標／容量発火はこの比較より先に従来の発火方針で判定する。
- 復旧の補助値は`250*potential_chain - 100*key + 20*min(safe,24) - 150*garbage + 120*min(potential_chain,visible_chain)/max(visible_moves,1)`。候補の実得点合計へ、消去前後の補助値差を6仮想列分だけ足す。将来節点ごとには累積しない。この係数は試作値であり勝率から校正した値ではない。
- 対戦の十分な本線返し同士は実得点の大きい順、同点なら早い順へ変更。余剰90個を超えたら得点差を無視する比較と85000点の上限を廃止。目標点数の省略時もキャラの通常14連鎖得点から計算する。最小相殺・資源を保持して突入する副砲・必要な緊急返し・本線保護は維持する。

ラフィソルの8連鎖は**相手なしの試作ツモテスト**で、14連鎖目標前の容量発火だった。72個送信による勝ち判定、通の得点目標達成による発火ではない。静的確認でも通常構築の発火条件は連鎖数／安全配置余地で、得点による自動早打ちではない。一時的に初回を旧評価へ戻す提案は、ユーザーの追加指示により撤回した。初回も実倍率を使う。

比較スクリプトは`tools/bench_fever_second.py`。本線の消去後盤面・周期・可視ツモを引き継ぎ、空盤面にリセットせず120手まで継続する。試作色列、相手なし、タネ配布／攻撃／ゲージなしであり、全消し後も空盤面で続ける幾何試験は実対戦の再現ではない。比較対象は`2026-10-10-second-before.json`、最終版は`2026-10-11-second-final.json`。途中のtrial／char-score／normalizedは不採用案または途中の比較として保存し、最終版と混同しない。

確認結果と残件はWORK_LOG.mdの2026-10-11追記を参照。13〜14連鎖の連続安定・勝率・逆転低減は達成扱いにしない。
