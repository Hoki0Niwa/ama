# Sol High向け：初回15連鎖・40手期限の最小試作仕様

改訂2026-10-12。**F40-0のベンチ・独立B0・保存再分類を実装し小規模検証済み。探索B1/B2とF40-1のnative特徴追加は未実装。** [ベンチ報告](FEVER_FIRST40_BENCHMARK.md)、[再分析報告](FEVER_FIRST40_RESEARCH_2026-10-12.md) に基づく。[原仕様](FEVER_CHAIN15_PROTOTYPE_SPEC_2026-10-11_ARCHIVE.md) のP15@120、セカンド、長いrollout、学習の実装計画は今回の対象外。

最初の候補は一つ：**期限・空間余裕を残す多様性ビーム**。B0/B1/B2は一つの試作の分解比較。製品設定、セカンド方針、Tsu、Feverのタネ探索、bridgeは変更しない。

## 1. 目的と終端契約

主指標P15_first@40、副指標@30/@35。初回本線は最初の実10連鎖以上。10〜14を先に消した後の15は成功にしない。

`placed_total=t` は既に設置したPiece数、開始0。次の配置はt+1手目。小消しで戻さない。`moves_since_chain`、周期位相、`dropset_index`とは別に保持する。

```text
for move = 1..40:
    observation = 実盤面 + 現在手/NEXT/NEXT2 + 周期 + t
    合法手を取得。エラー/配置不能なら失敗終了
    実配置と連鎖をシミュレートし t += 1
    deadなら失敗終了（実15と同じ遷移でも失敗。今回の明示指示を優先）
    links >= 10:
        初回本線を確定
        links >= 15なら成功、10..14なら失敗終了
    1..9連鎖は手数・除去数・残り・廃棄を記録して継続
40手終了時、初回15が無ければ失敗
```

@30/@35は同じ40手試行から算出する。30手で未成功でも止めない。40手目の実15は成功、41手目は失敗。`expected_chain=15`、発火準備、未来のWitnessだけでは成功にしない。全開始試行を分母へ入れる。

10〜14は吸収する失敗終端。5〜9はベンチでは非終端だが、既存ビームのPRUNE_CHAIN=5は初期試作で維持し、この整理計画を十分に扱えない限界を記録する。1〜3の整理禁止や回数制限は加えない。

Field、Piece、normal_space::moves、drop_piece/pop/is_dead、dropset、normal_scoringを再利用する。重複の物理実装や大規模な共通化はしない。共有コードの変更が必要ならAGENTS.mdのirregular-form先行を守る。

## 4. B1：期限と資源

`remaining=40−t`、`D=min(8, remaining)`。Dより先の配置で発火する結果を当期の価値にしない。可視発火のWitnessも必要手数がremaining以内かを検証する。10〜14発火の後に作り直して15という値を伝播しない。

現search_multiは受け取ったqueue全体を検索し、depthより可視queueが長くても自動では短縮しない。B1/B2ではObservationの可視3とは別に、検索用queueを `min(可視数,D)` へ切り、必要な仮想列をDまでだけ補う。発火/容量の研究呼出にもremainingを超えない列を渡す。depth設定値だけを1/2にして期限対応済みとしない。

短い本線は合法fallbackとして残せるが、研究成功にはしない。15未満の発火を一律禁止してnomoveを増やすガードは作らない。確定した期限内15が可視なら、その具体手順を実行する。

最大仮想連鎖でroot全体を並べ直す変更は今回入れない。10/09の不採用実験を踏まえ、旧root順位を基本にし、候補保持の効果を測る。

盤面の色数C、t+1〜H手の既知形状による供給量S(t,H)を使い、`mass_slack_H=C+S(t,H)−60`（H=30/35/40）を計算する。負なら空盤面開始・外部から色追加無しでは必要な色数が不足する。正でも色・構造・操作は保証しない。おじゃまをCに含めない。

シミュレーション子ではtも設置数だけ進め、その後の供給だけをSへ入れる。既に置いたPieceを二重に数えない。H<tならその期限はexpiredとして扱い、逆向きの供給和を評価に使わない。

色数最大化や巨大な加点には使わない。mass_slack40負の候補へ予約枠を使わず、全候補が不適格なら合法fallbackを返す。mass_slack30負でも40へ間に合う候補を捨てない。基準25/30/35手の未終了局面でmass_slack40負は0であり、この下界だけで改善するとは期待しない。

## 5. B2：空間候補を一部残す

### 特徴

現potential()が既に行う同色1〜3個の仮置きとpopから、研究版だけで次を取得する。製品のPotential型の改造は不要。幾何評価の最善Witnessを使い、追加の全可視探索を各ノードで走らせない。

| 記号 | 内容 |
| --- | --- |
| Lg | 仮の鍵を足したリンク数。合法Pieceでの実現保証ではない |
| Eg | 色の消去群合計−4×Lg。5/6個消しも記録するが強罰にしない |
| Rg | 仮消去後の残り色数。尾の材料か邪魔かは未識別 |
| Kg / Xg | 仮に足した鍵の数 / 発火列 |
| Hg | 中央2列の安全高さの残りの最小値 |
| slack30/35/40 | 上記の必要資源の余裕 |

EgとRgを一つに潰さない。同じL/鍵ならその和はほぼ盤面総数に還元される。群は小さくても残りが多い例と、群が大きく残りが少ない例を別経路として保持する。Xgは尾の位置を意味しない。

既存pop計算から特徴を取り、重複計算を抑える。cacheのキーは盤面と評価条件、rootの支持は別管理。NEXTの操作余地は既存root検査を利用する。高価な容量検査を全ノードへ追加しない。

### 選別手順

W=250、Q=50から始める。別の幅ではQ=floor(0.2W)とするが、初期比較で幅/係数を大量探索しない。

1. 従来通り合法遷移・評価を作り、旧 `eval+action` 上位W−Qを取る。
2. 未採用候補をrootごとに分け、そのrootの最大Lgから1以内、Lg≥2、mass_slack40≥0だけを予約候補にする。
3. 全rootの1巡目に `(Eg昇順, Hg降順, Kg昇順, Lg降順, 旧評価降順)` の1件を取る。
4. 2巡目に、別の候補を `(Rg昇順, Hg降順, Kg昇順, Lg降順, 旧評価降順)` で1件ずつ取る。最大22rootなら44枠まで。盤面重複を二重に数えない。
5. 残り予約枠は異なる `(Lg, Xg, Hg帯)` から旧評価上位を選ぶ。Hg帯は0/1〜2/3以上。候補が不足すれば従来順位で埋める。
6. Wを超えない。幾何候補が無い序盤は予約枠を従来枠へ戻す。選別理由・root生存・脱落深さを記録する。

選別元はその層で生成した候補群。既存Layer.addで上位Wだけへ落としてから予約候補を探してはいけない。研究版では最大およそW×合法手数の一時poolから選ぶか、同等の候補を保存する別heapを用意する。poolのメモリと選別時間も計上する。

B2の候補重複は最初は `(盤面, root_id, 層の時刻/可視列/ルール)` 内で判定し、rootを跨ぐ同盤面で別の初手を消さない。盤面だけの静的評価cacheは共有できるが、行動累積値とroot支持は別に持つ。B0の同値経路は従来実装をそのまま残す。

20%と上の順序は未検証の初期案。単純な強減点にせず、同程度の潜在連鎖の別経路を少数残すという仮説をQ0/Q50で試す。これで良い候補が見つかる保証はない。

## 6. 手数による動作

序盤はまだ60個が揃わないので、現在個数だけで価値を潰さず期限までの供給を見る。Lgが無い間は従来選別を維持する。

20〜30手付近は潜在連鎖が近く空間消費が異なる候補を残す。小消し/廃棄で30の必要条件を失う時点をログに出す。30目標のために40成功を落とす強制発火は入れない。

終盤はremainingがそのまま深さを短縮する。残り3手以下なら設置する色は全て可視であり、その期間の実発火を検査する。期限外の仮想15へ延々と期待しない。多数の時期別重みを追加するより、この期限と資源条件を先に試す。

**B2にも現行仮想列の楽観性は残る。** 40手成功確率を正しく推定する器や、未知色問題の解決済み版とは呼ばない。今回は空間候補の消失を改善する仮説だけを評価する。

## 7. rolloutの再定義（今回実装しない）

将来戻す場合の値は `Pr(初回本線≥15, かつ t+τ≤40 | observation,a,継続方策π,色モデル)`。10〜14、死、配置不能、真の40手未達は失敗終端で、作り直しを続けない。

P40を第一とし、P35/P30は副指標。未校正な重み付き和で30だけを優遇しP40の低下を隠さない。計算を途中で止めたものはunfinishedであり、40失敗にも実成功にも加算しない。幾何値やValueを成功件数へ混ぜない。

再検討時の最小shadow案は最大2root×2共通未来×最大4手。残り4手以内なら期限まで評価し、それより前は打切り葉の代理値として別に記録する。序盤の大量rolloutはしない。2サンプルで精密な成功確率を得たとは扱わない。

環境だけが未来標本を持ち、行動器は毎手現在＋NEXT2だけを受け取る。内部Samplerは外側の環境と独立。同じ観測と探索RNGなら隠れた実列を変えても同じ初手となる。候補生成列と最終評価列を分ける。

内側で旧器全体を呼ばず、安価な可視探索等の費用を測る。共有prefixと完了batchを使い、途中で良い結果だけ届いた候補を選ばない。shadowの結果を実選択へ使う実装は、このB2評価後の別判断。

## 8. ベンチ・ログ・計算予算

同じ空盤面、phase0、2キャラ、試作色モデル、可視3、ルール、margin、操作モデル、CPU、総6 threadsで対応比較する。探索RNGは環境seedと独立して固定する。新器に環境の全キューを見せない。

試行ログには初回の手/links、success30/35/40、停止理由、1〜3/4〜6/7〜9消去、除去セル数、残り、廃棄、盤面、実配置を保存する。**実行したtransitionのdiscarded**を使い、入力Piece＋before−消去−廃棄=afterを検査する。旧ログの返答由来discardedに8手の不一致があったが全て40手以降で、今回の主指標には影響しない。

診断はbefore/afterを区別し、t/remaining、幾何Witness、root別生存/脱落、容量理由・safe/retaining/improving実数、可視fire必要手数、構築提案→発火選択→Python採用→実消去を記録する。no_main_retaining_continuationは保持0と同義でない。

wallは要求送信から合法手受信まで（容量・Python・IPC込み）。全関連processのuser+kernel CPU秒、P50/P95/max、1試行総CPU、固定局面処理時間、ノード/評価数、ピークメモリ、timeoutを保存する。CPU秒/wall秒というcore相当と、さらに論理CPU数で割るホスト換算使用率を区別する。早い失敗で平均費用が安く見える点にも注意する。

最初は同幅250×8の無制限比較、次に同wall上限250ms/手の比較。250msは研究用で、製品の時間制限変更ではない。保存ログの無制限結果をそのまま時間制限器の対照に使わない。

両器の研究adapterに同じdeadlineと合法fallbackを用意する。最初に合法手を確保し、最後の完了した探索単位を返す。不完全な候補比較を確定値にしない。キャンセル粒度と返却の遅れも計測する。6-thread検索を入れ子で増殖させない。1秒以上、全未来oracle、Steam実測は初期タスクに含めない。

## 10. 合格・不採用

開発群は既知31001〜31024＋過去使用を確認した追加40seed/キャラ。選別目安はP40対応差+10pt。Q50で改善しなければQを多数探索せず、候補消失ログから仮説を棄却/保留する。B1だけの改善をB2の功績にしない。

最終群は未使用200以上/キャラ。候補910001〜910200の使用履歴を確認し、方式/予算/係数/RNGを凍結。最終対照は開発段階で選んだ1候補とB0で、最終データを見てB1/B2を選び直さない。

率はWilson95%、対応差は環境seed単位bootstrap、成功入替はMcNemar exact。全手を独立標本として水増ししない。初回10〜14の失敗を生存分析の打切りにして消さない。

暫定合格案：P40対応差の95%下限>0、P30下限>−5pt、初回P13/P14下限>−5pt、死亡/nomove増加の95%上限<+2pt。P35も報告し、大幅低下は保留理由。全て初回40内の率で、旧120手の13/14率を使わない。200件で全非劣性を判定できるとは限らず、区間が跨げば保留する。

同一250ms予算で期限内返却を目標にし、超過が観測されたら原因・率を示して保留する。P95/最大が旧器より10%以上増える場合もそのまま実用採用しない。10%は事前固定する研究上の余裕値で、実対戦の承認済み遅延ではない。CPU増分と二席同時動作は製品統合前に別途受入れる。

P15@120、セカンド、最大潜在連鎖、得点効率だけの改善は不採用。NN、MCTS、部分目標生成、大量rollout、margin緩和、製品設定切替はこの実装タスクに含めない。
