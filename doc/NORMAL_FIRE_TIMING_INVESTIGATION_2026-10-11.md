# 相手Fever・自分通常の発火タイミング調査

2026-10-11。対象は不足する返しの早打ち、遅すぎる潰し、新しく構築している本線の見切り発火。以下は変更前の原因調査。ユーザーの修正依頼による実装は末尾に追記し、調査当時の結果と区別する。

## 結論

主な問題はキャラ倍率ではなく、通常戦術探索の時間範囲・生存判定・本線消費評価・潰し分類にある。前回のキャラ別得点／再構築評価変更後の既定対戦バイナリでも再現した。個々の報告試合と完全に同一の要求が保存されているわけではないため、全死亡の原因を一つに断定しない。

1. 本線発火で探索を打ち切り、発火後の未相殺攻撃を受ける状態まで生存を確認しない。
2. 予告を少しでも相殺できる本線は、未完成でも温存ガードを抜ける。ゲージ7到達や、待って相殺可能なリンクを増やす比較は必須条件でない。
3. 文書に記載された本線消費／不足する返しの減点は、現行戦術評価で使われていない。
4. `overpower` は次の種に合わせる時刻・相手の積む手数を検査しない。将来の副砲による潰し加点が、現在の無相殺小消しを採用する理由にもなる。

## 現行バイナリによる再現

`tools/investigate_fever_fire_timing.py` は相手の既知得点イベント、可視3組、通常倍率、予告を固定して `op=tactics` を呼ぶ。返答・全候補・完全なnative要求を `data/fever/baselines/2026-10-11-normal-fire-timing-investigation.json` に保存した。公開平積み7連鎖に独立した小消しを追加した合成盤面であり、Steamでこの盤面を操作した試験ではない。

構築側の指定は非発火の内部座標x=5（6列目）上向き、`builder.fire=false`。相手Feverの次の種の返し見積もりは300個、残る攻撃見積もりは550個。相手の既知イベントは30000点（250個）とその50F後の確定。自分の初期ゲージは0。

## 早打ちの経路

`fever_battle/tactics.cpp::Search::ends` は `n.fired_main`／`n.builder_fire` で探索終了。`leaf` の `alive` はその時点のField死亡判定で、連鎖中にはおじゃまを落とさない。ゲージが7未満でも本線を使い切った直後で止まる。

`leaf` は `arriving = fixed + flying + future(n)` を計算するが、その値は現在の評価では使われない。`pending` 重みも既定0。現在予告の次の落下に対する危険は `exposed` の有限減点であり、死亡扱いでもない。相手の残攻撃 `enemy_hold` は全消し加点の縮小にしか使わない。従って、本線を失いゲージ不足の盤面へ大攻撃が来る場合でも、相殺で得たゲージの加点が勝てる。

通常相殺の優先群は最終的な `incoming` と `points/rate` を比較するが、そのあとに来る未観測の種、ゲージが何リンクで増えるか、発火後の防御資源の要否を必須検査にしない。優先群の `values[i].alive` も上記の限定された判定。今回の合成不足ケースは優先群だけでなく、通常の値の最大化からも選ばれている。

弱い本線を攻撃到着前に止めるガードは `step.cancelled==0`、現在の確定＋未確定予告0、潰し加点が小さい場合に限定される。確定予告1個でもこの条件を外れる。最後の `held_main_for_counter` も `incoming==0` に限定され、脅威のある状態の一般的な本線保護にはならない。

## 本線消費評価の仕様と実装の不一致

`doc/FEVER_MODE_ENGINE.md` 第4.2節の旧説明には、本線から失ったリンクに対する `mainline`、丸ごと撃って予告が残る場合の `uncountered`、消費ぷよと連鎖中に失う構築手数の費用がある。

現行 `tactics.cpp` は `mainline`、`uncountered`、`mainline_min`、`growth_cells` をWeightsへ読み込むが、`leaf` の評価へ接続していない。`fire_delay` も加算するだけで値には使用しない。本線消費にかかる直接費用は主に消したぷよ数×`consume`（既定12）で、文書のリンク単位減点とは異なる。再現要求で `mainline` と `uncountered` の両方を0／1000000にしたprobeは、候補のchoice全体が一致した。

`protected_main` は潰しと全消しの加点を止めるが、本線候補を除外したり相殺資源の消費を減点する条件ではない。初回・セカンド共通の経路であり、再構築モードを追加してもこの問題は残る。

資源分類 `step.main` は「消去後セル数がmax(24,初期セルの半分)未満」で判定。消去後に24個以上残った大きな部分消去は、本線ポテンシャルを壊していてもmainと判定されないことがある。潰しに使える副砲 `step.side` も残量と冗長度で判定しており、単に短い連鎖を意味しない。従って「本線だけ保護する」条件では新しい本線を削る部分消去も漏れ得る。

## 修正方針と検証すべき条件

1. **生存とゲージの時系列を先に満たす。** 未完成本線の候補を、現在予告だけでなく既知の相手攻撃全体を相殺し切る／ゲージ7へ確実に到達する／他に生存手段がない場合に絞る。予告が未到着なら、可視の非消去配置や最小相殺で待つ手順と比べる。ゲージ7到達前の本線消費を、途中Fieldが生きているというだけで安全な返しにしない。
2. **発火後の脅威を評価する。** 少なくとも既知攻撃の終了と次の落下・可視の対応まで確認する。可視外の色で生存を捏造しない。未知の後続種は確定死亡とも確定生存とも扱わず、相殺資源を失う危険として区別する。
3. **新しい本線の保護を資源差で行う。** 初回／セカンドの目標と容量発火を維持し、残存ポテンシャル・相殺ストックを壊す副砲も本線消費へ含める。消去後セル数だけで分類しない。未使用の旧パラメーターをそのまま復活させるのでなく、現仕様に合う費用を実装と説明で一致させる。
4. **潰しの時機を攻撃種類すべてで評価する。** 相手に何手与えるか、その間に伸ばし／早期発火して返せるかを、現在の攻撃を上回るという条件とは別に検査する。窓を過ぎても成立する継続火力は得点差で評価し、発火口妨害の加点と混同しない。未来の成功で現在の無益な小消しを買わない。
5. **入力をやり直すのでなく価値の失効を検査する。** 新しい種・発火・期限を更新契機にする既存方針を守り、操作中に全探索を毎リンク再実行しない。独立した必要相殺の契約と潰し契約を分ける。

追加回帰は、予告0/1/20で保護が不連続にならないこと、待つことで相殺リンクが増える場合、ゲージ未達で本線後に大攻撃が来る場合、本線を残す最小相殺、独立した緊急発火、211F遅い副砲、新種へ移った妨害、初回とセカンドの同一条件を対象にする。

既存counter19件・main_preserve10件・disruption16件は45件すべて成功した。従って既存回帰だけではこの不足を検出できない。調査によるゲーム操作、戦術ソース・設定・バイナリ変更は行っていない。実機の修正受入れと勝率比較も未実施。

通の `frame`／`frame_real` は連鎖1リンクを2とする抽象的時間であり、Feverの60fpsの実フレームへ数値を直接移植しない。同期潰しで「相手の連鎖終了に間に合うかを先に絞る」という構造が比較対象。

通も未来の相手攻撃をすべて含む生存証明ではなく、受入れ・得点・盤面の近似と条件分岐で判断する。通にはFeverゲージと種の連続交換がないので、「十分な単発返し」や「盤面へ二段送る」をそのままFeverの成功条件にしない。また今回見つかった未使用のmainline／uncounteredはFever独自評価の未接続であり、通の同名重みが移植されなかったという意味ではない。

修正では通の同期時機と不足返しの厳しい許可条件を参考にしつつ、Feverのリンクごとの相殺・ゲージ到達・種交換後の反撃を追加する。通の数値閾値や90個余剰の飽和へ戻す案ではない。

## 修正実装

ユーザーの「場当たり的にルールを増やさない」という指示に従い、個別盤面・キャラ・予告個数の例外ではなく、防御の状態と攻撃の効果帰属を整理した。

- `fever_battle/normal_defense.h` に通常盤面の防御結果を分離。既知の相手リンクを最後まで精算した予告、次の種の標準得点から残送信を引いた反撃見積もり、自分の消去によって失った本線リンク、ゲージ7到達、残予告を受けられる盤面かを別々に保持する。既知攻撃と推定反撃は混ぜて診断しない。
- 本線消費は、各消去の直前／直後の単色追加ポテンシャル差から累積する。実際に消えた連鎖数を直前ポテンシャルの下限に使い、特殊ツモで初めて発火できた本線も数える。消去直前の本線が`mainline_min`以上の場合に費用を付け、おじゃまを受けて崩れた本線を自分から発火した費用として二重減点しない。残セル数だけでsideと分類された消去にも同じ費用を適用。
- 相手Fever時の費用は、失ったリンク×`mainline`と、失ったリンク×`uncountered`×反撃リスク。反撃リスクは（既知残予告＋次種の反撃見積もり）／（2×`fever_reach`）、上限1。ゲージ7に達すれば後者は0。構築自身の発火は、既知交換を処理できて次種への防御も確保できる場合に基本の消費費用を免除する。`growth_cells`と未使用の`fire_delay`はこの評価へ重ねず、実装から除去した。
- 本線を撃っただけでは探索を終えない。可視ツモの残りで相殺・配置を続け、葉では既知相手連鎖の最後まで精算した収支も評価する。ゲージ7・全消し・未知列のおじゃま落下・可視探索範囲での終了は維持。未知色の生存を保証しない。
- 十分な返しの優先処理も同じ防御結果を使う。ゲージ到達・既知交換後の受入れ・本線資源を残せるか・次種への余剰を確認し、現在予告だけを消す弱い本線を優先群に入れない。この不適格候補を不足返し群へ回す抜け道も除去した。全候補から消す方式ではなく、独立した緊急発火・他に実行可能な手がない場面は有限の値で比較できる。
- 現在の観測攻撃を上回るだけの`overpower`は、自攻撃が相手終了＋既存窓までに確定する時だけ加点。早く確定し、相手の残リンクでも消えずに残る攻撃は有効。相手終了から211F遅い攻撃はこの一時的潰しに含めない。次の種の標準反撃を上回る継続火力は別の条件で評価し、高得点を頭打ちにする旧方針へ戻さない。
- 初手が実際に消去する場合、攻撃加点はその一発で見込める量・種類・期限を上限として将来へ持つ。後の副砲の加点が、今の無意味な小消しを買わない。非消去の準備手は将来の攻撃を評価できる。防御ゲージや残盤面の先読み自体は止めない。
- 伸ばし中の固定種の幾何は、送信確定までに相手が通常の一手を積める長さを越えた場合、潰しの証拠に使わない。現在の時間モデルでは既存の26F窓で判定するため保守的で、静的幾何だけから遅い通常連鎖の伸ばし妨害を加点しない。着弾中に相手が積む未来盤面を完全探索したとは扱わない。
- 一時的潰しには種類と期限への依存を返し、`tactics_clear`でも既存の入力直前検査へ絶対期限を渡す。十分な防御として独立に選ばれた発火・必要相殺・全消しは、付随する潰し期限だけで取り消さない。操作中に相手の得点リンクごとに探索し直す変更は行っていない。
- 戦術選択を使った通常返答のゲージ予測も、同じnative時間計算の`gauge_after`・相殺リンク数・相殺量へ統一。連鎖中に届く相手攻撃を無視して現在予告だけで計算し直す経路を除去した。戦術返答に新しい相殺リンク診断がない旧workerや構築のみの返答では従来の静的計算を維持する。

診断に`known_exchange_pending`、`known_exchange_secured`、`next_seed_exposure`、`defense_commitment`、`main_links_lost`、`disruption_requires_timing`、選択理由の`defensive_fire`を追加。`survives`は引き続き可視探索中の実盤面死亡判定であり、未知の未来に対する勝利／生存証明ではない。`known_exchange_secured`も、ゲージ7到達・予告消滅・残予告をその盤面で受けられるという限定された意味。
