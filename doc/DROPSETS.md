# キャラ別ツモ形状周期（ドロップセット）

更新：2026-10-04

対象：ぷよぷよeスポーツ（Puyo Puyo Champions）Steam版のフィーバールール。全24キャラと隠し2キャラの形状周期を、形だけ用意したもの。色はここでは扱わない。機械可読版は [`data/fever/dropsets.json`](../data/fever/dropsets.json)。

## 1. 表記

| 記号 | 意味 | セル数 |
| --- | --- | --- |
| `2` | 2個組 | 2。Steam画面と一致 |
| `L` / `J` | 3個組の2種。軸と同色の腕が縦か横かの違い | 3。Steam画面と一致 |
| `3` | 3個組（旧表記。L/J を区別しない） | 3。Steam画面と一致 |
| `4` | 2色4個組（22ぷよ） | 4。Steam画面と一致 |
| `0` / `*` | でかぷよ（`0` は puyo-camp 表記、`*` は旧表記） | 4。Steam画面と一致 |

16文字で1周期。17手目以降は先頭から繰り返す。周期の開始位置と、フィーバー突入・終了時にリセットされるかは**未確認**。

`L` は縦3個組（軸と上が同色、右が別色）、`J` は横3個組（軸と右が同色、上が別色）。2026-10-04に公式アミティ・ラフィーナ図と公開キャラ選択画面を照合して対応を決めた。ラフィーナは手3=縦、手10=横、手13=縦。実装の対応は `core/dropset.h` の `decode()` に集約し、JSONの `triple_mapping` とも一致テストする。色配列は縦が `(A,A,B)`、横が `(A,B,A)`。同色3個組では両者とも `(A,A,A)`。

## 3. 確認状況と注意

- 2026-10-03時点の文字列は検索要約経由で収集した。2026-10-04には記事本文、キャラ選択画面の一覧画像、公式組ぷよ図を直接取得した。新たに読む周期・向きは画像そのものと照合した。残る `player` 状態を一括して公式確認済み・Steam実機照合済みにはしない。T7で各キャラ16手を実機と照合する。
- アルルは全16手が2個組であることを公式図で確認し `official` に更新。ラフィーナは公式図の向きを再確認してL/Jを補完。シグ・すけとうだらは公式図と公開実機画像を使って向きを補完したが、状態は `player` を維持。
- ヘドは公開キャラ選択画面の周期を採用。英語公式 `hed_puyo.png` はこの画像・記事の「すけとうだらと同じツモ」という記述と一致しないため、公式図だけで上書きしない。
- りすくまは公開キャラ選択画面で `2J22220222422L22`、38個と取得した。公式図とも一致するが `player` とし、Steam実機照合は未実施。**→ 第4節のSteam画面との照合で `2J222202222422L2` に訂正した。**
- ドラコの手11/12/14/15は縦/横/横/縦。公開キャラ選択画面を再読し、2026-10-04にユーザーからSteam版でも同じ向きとの回答を受け、旧データの「全てL」を訂正した。英語公式 `dracocentauros_puyo.png` はりすくまと同じ図になっているため採用しない。ユーザーの確認は3個組の向きに対するもので、T7の全26キャラの16手実機照合とは区別する。
- 周期が未取得なら `status: unknown` とし、コードでは `std::nullopt` を返す。旧表記の `3` しか分からない場合は `TRIPLE_UNKNOWN` を返し、縦横を推定しない。現在の26件はすべてL/J付きの周期を持つが、不明データを扱う経路もテストする。
- Puyo Nexus の表に「Lidelle/Draco（Fever版）は 8/6/1/1 の42個」とあるが、eスポーツのホウライ（リデル流用）は 11/2/1/2 の40個で食い違う。eスポーツ版は puyo-camp の文字列を採用する。
- 流用元の記述（フェーリ、クルーク、リデル、アコール、ユウ＆レイ、さかな王子）は参考情報で、eスポーツ版の文字列を優先する。

## 4. Steam版のキャラ選択画面との照合（T7、2026-10-04）

Steam版（`PuyoPuyoChampions.exe` sha256 `2a3540514327f6b6…`、ブリッジのプロファイルでは build 15209927）の「ぷよぷよフィーバー」のキャラクターセレクトでは、選択中のキャラの欄に16手の組ぷよ図が出る。ユーザーがカーソルを全キャラへ動かす間にウィンドウを連続で取り込み、図を画素から読み取って周期表と比べた。

- 図の記号：縦に2個の丸＝2個組、縦棒＋右下の丸＝縦3個組（L）、左上の丸＋横棒＝横3個組（J）、縦棒2本＝2色4個組、大きな丸＝でかぷよ。棒は同色の2個を表し、L=縦 `(A,A,B)`、J=横 `(A,B,A)` の対応と一致する。
- 読み取りは `tools/fever_select_screen/parse.py`（白い塊を収縮で分離し、図の傾きに沿うものだけを左から形状へ組む）。全キャラを拡大画像の目視でも確認した。
- **23キャラは一致**：アルル、アミティ、りんご、ヘド、スルターナ、シェゾ、シグ、まぐろ、シエル、ホウライ、ルルー、ラフィーナ、すけとうだら、アリィ、ラグナス、ドラコ、ウィッチ、ハーピー、セリリ、カーバンクル、サタン、ハルトマン、アレックス。スルターナは立ち絵が図に重なり自動読み取りが2手分乱れたため、塊の一覧と目視で確認した。
- **りすくまは不一致で、訂正した**：Steam版は `2J222202222422L2`（3フレームで同じ読み取り）。旧値 `2J22220222422L22` は、でかぷよの後の2個組が3つで末尾が2つだったが、実際は4つと1つ。22ぷよは12手目、縦3個組は15手目。個数（2個組12・3個組2・22ぷよ1・でかぷよ1、計38個）は変わらない。旧値は公開画像を目で数えたもので、数え間違いとみられる。「公式図とも一致」という以前の記述は再確認していない。
- **隠しキャラ2体は部分的**：ラフィソルとパプリスは選択すると「決定」の表示が図の左側を隠す。見えた末尾7手（ラフィソル `…4L024J0` のうち `024J0` と直前の22ぷよ・3個組、パプリス `…0J2024`）は周期表と矛盾しないが、先頭9手はこの方法では読めなかった。下の実プレイで全16手を確認し、状態を `steam` にした。
- ドラコの手11/12/14/15＝縦/横/横/縦も図で確認できた。
- 上の24キャラは画面の図との照合で、**実際に16手を置いて確かめたものではない**。

### 隠し2キャラの実プレイでの照合

隠しキャラは決定前の状態で図を出せないので、ユーザーが実際に対戦で置く間、画面左半分を0.3秒間隔で取り込み（`tools/fever_select_screen/watch_play.ps1`）、NEXT・NEXT2の表示が変わるごとに形を目視で読んだ。開始前の画面から取り込めたので1手目から読めている。取り込み範囲にキャラ名は映っておらず、キャラはユーザーの選択による。

| キャラ | 読み取った手（1手目から） | 周期表との比較 |
| --- | --- | --- |
| ラフィソル | `222L222J24L024J0` ＋ `222L2`（21手） | 16手すべて一致。17〜21手目は先頭の繰り返し |
| パプリス | `2L22J22L420J2024` ＋ `2L22J22`（23手） | 16手すべて一致。17〜23手目は先頭の繰り返し |

- NEXTの見え方：2個組は丸2つ（同色は縦長の1つ）、縦3個組は縦長＋右下の丸、横3個組は丸＋下の横長、2色4個組は2色の円、でかぷよは大きな丸。L=縦・J=横の対応と一致する。
- **周期は対戦の1手目から始まり、17手目で先頭に戻る**ことを、この2キャラで確認した。どちらもフィーバーに入る前の範囲で、フィーバー突入・終了時にリセットされるかは未確認のまま。他の24キャラの開始位置は実プレイでは確かめていない。

`status` の `steam` は、Steam版で16手すべてを確認したことを表す（図で24キャラ、実プレイで隠し2キャラ）。全26キャラを `steam` に統一した。アルルとラフィーナは公式図でも確認済みで、以前は `official` としていたが、Steam版での確認を状態の基準にそろえ、公式図の確認はJSONの `official_diagram` に残した。

## 5. T1のコードAPIと確認

- `piece::Piece` は形状と最大4色を持つ。2個組は軸・子、3個組は軸・上・右、22ぷよは左下・左上・右下・右上。でかぷよは `colors[0]` だけ使用し、他は `NONE`。`cell_count(BIG)=4`、`color_count(BIG)=1`。
- `piece::from_pair()` は軸・子の順を保存。`to_pair()` は有効な2個組だけ変換し、特殊ツモ・不正な色は `std::nullopt`。`is_valid()` は同色2/3個組を許可し、22ぷよは異なる2色が隣接して2個ずつであることを確認する。
- `dropset::characters()` / `find(id)` で26件の定数表と資料の状態を参照する。実行時にJSONを読み込まない。
- `dropset::drop_at(id, index)` は向きも含む種別を返し、`shape_at(id, index)` は `piece::Shape` を返す。`index` は0始まりで16手ごとに循環し、不明なID・未取得周期は `std::nullopt`。状態を確認したい呼び出し元は `find()` を併用する。
- `python test/test_fever_piece.py` はC++20でAPIをビルドし、全26件のID・状態・新旧周期・個数・総数、3周期と最大64bit添字、JSONの向き情報を照合する。変換・色制約・不明データの扱いも検証する。
- 落下・回転・配置・色列生成・探索との接続はT2以降。T1の成功はSteam実行や大連鎖構築の達成ではない。
