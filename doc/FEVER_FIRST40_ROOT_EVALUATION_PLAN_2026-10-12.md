## 3. R1の仮説と測る量

仮説H：同じ観測でB0が選ばなかった初手の中に、可視3で動くB0をその後使っても、独立未来に対する初回15@40の成績が高いものがあり、少数の別標本からそれを選び分けられる。

測る値は `Q_B0(s,a) = Pr(最初の実10以上が15以上、かつ絶対40手以内 | 観測s、最初だけa、その後B0、試作色モデル)`。

- 一度だけ初手を固定し、その後は各手で通常のB0を呼ぶ。候補ごとに後続の配置を固定しない。
- 観測に同じ実盤面・可視3・周期・絶対手数・過去の整理消し履歴を渡す。B0の探索は幅250・深さ8・6仮想列のまま。
- 成功判定だけが初回10/期限40を持つ。B1の短縮を継続器へ黙って入れない。
- この値はB0継続下の成績であり、盤面からの最適到達確率でも、空盤面からR1を毎手適用したP40でもない。

### 最大2候補

`a0` は最終的なB0採用手。nativeの先頭rootだけで代用しない。最初に保存B0との配置・実遷移一致を確認する。

`a1` は次の固定手順で選ぶ。6仮想列の情報は**提案する別初手を1つに絞る用途だけ**に使う。

1. 既存F40-1診断を同じB0要求に一度だけ使い、root別の6列のscore/chain/next_roomを取得する。既存の合算・安定順位をそのまま再現し、native順位の一致を検査する。`stretch/trigger` 等を無視して単純なscore順へ置換しない。
2. `a0.fire=true`、Pythonの保持/延長上書きあり、又は直接のnative提案と最終採用が違う局面では `a1` を作らずB0固定とする。発火・容量解除・採用後のガードを今回の介入に混ぜない。保存16件のうち2件はfire=true、残る14件はこの入口条件を満たす。別rootの有無は未測定。
3. 同じ検索の合法rootから、実遷移が生存・廃棄0・実消去0〜9で、既存marginとNEXTの置き場条件を満たすものを残す。B0で正のnext_roomを優先する条件を緩めない。既存の保持/延長採用を通すと差し替えられる候補も除外する。安全条件を新しく緩和しない。
4. `a0` と同じ盤面・実links・廃棄を生む候補は重複とする。BIGの色を含む実遷移で同値を判定する。
5. 残った候補に仮想chain>=15が一つ以上あるrootがあれば、その集合で従来順位が最上位の1件を `a1` にする。無ければ残る集合の従来最上位を使う。候補が無ければB0固定。幾何Lg15を仮想実pop15へ混ぜない。

候補生成中は独立標本の未来や元の実未来を使わない。結果を見て候補数、順位、閾値を変えない。単純な「最大chainを選んで実配置」と異なり、`a1` は後述の継続評価に勝たなければ選ばれない。

容量応答による許可条件は現 `_solo_build` を基準に照合する。代替rootを入れた場合にも既存ガードがその手を維持することを研究側で確認し、差し替えられる場合は不適格と記録する。root値を替えただけの古い `next_field/next_chain` を実遷移へ流用しない。

## 5. 未知色・継続・選別の契約

### 同じ未来、独立した2組の標本

1局面について選別用4列、確認用4列を用意する。両候補は同じ8列を使う。R1内部の標本は元の環境seed、元の未来、固定6色袋と独立にする。

標本seedは `SHA256('ama.first40.root-eval.v1' + '|' + observation_sha256 + '|' + split + '|' + index)` の先頭8byteをbig endianのuint64とする。`split` は `select` / `validate`、indexは0〜3。元seedや候補番号を含めない。この仕様を結果前に凍結する。

同じ参照nativeの `op=queue` で43手分を生成し、当該t以降の形状位相を合わせる。t,t+1,t+2は保存された可視3で置換し、それより後だけ生成色を使う。現在のqueue APIにはstart指定がないため、短い列を0位相から生成して継ぎ足してはいけない。全43列は環境側だけが持つ。

各配置時、行動器へ渡すのは現在＋NEXT2のみ。内部に保持する未来列、標本seed、元seed、候補の最終成績は渡さない。実験用の独立列で得た成功をSteamの成功として扱わない。

### 終端までの継続

- 初手だけa0/a1を強制し、参照nativeで合法性・実links・セル収支を検証。その後は新しいB0 instanceで可視3から再判断する。各候補・標本のキャッシュを共有しない。
- 通常構築の観測履歴を毎手更新する。途中1〜9は記録して継続し、初回10〜14・死亡・配置不能・engine errorは失敗。初回15以上でも同時死亡なら失敗。
- 絶対40手目まで。実15@30/@35/@40、初回13/14、全消去群、残り容量、整理消し、各手wall/CPU、メモリを保存する。結果レコードには開始絶対tと今回の継続長を別々に持つ。
- 既存の `terminal` / `normalize_step` / 物理を再利用する。空盤面専用 `run_trial` や連続1始まりを要求する `trial_result` へ中間局面の行を無理に渡さない。小さい研究用継続driverを追加し、共通コードを改変しない。
- 研究全体の予算終了で止めた継続はunfinished。40手未達という失敗とは別。started件数から消さず、完了数・unfinished数と成功率の下界/上界を出す。未完了があれば昇格判定をしない。

### 標本の使い分け

選別4列で、a1の実P40成功数がa0より多く、死亡＋配置不能件数がa0以下の場合だけa1を選ぶ。それ以外と同点はa0。P35/P30、score、潜在連鎖を混ぜて同点を破らない。この保守的な規則を一つだけ試す。

選択結果を保存・hash固定してから確認4列を評価する。確認側では、選別側で決めた手とa0の差を測る。確認結果から勝者を選び直してはいけない。

`max(確認側Q(a0),確認側Q(a1))` は参考の事後上界であり、実装できる選択器の成績として報告しない。4標本の0/4や4/4は精密な確率推定ではない。継続方策B0の弱さ・2候補への限定による見逃しも残る。

## 6. 範囲・費用・停止判定

主検査は最大16局面×2候補×8未来。全て40手まで続いた場合でも、初手後のB0 chooseは最大3,328回。候補のない局面はa0固定を明記し、切替可能だった局面だけで全体差を良く見せない。a0とa1の実行順は標本ごとに交互にする。並列の6-thread検索を複数起動しない。

既知のgain/lossを理解する補助検査として、ラフィーナ31017/34手の2D対1U、ラフィソル41027/37手の5D対0Rを同じ8標本で比べる。最大144 chooseの追加。介入後はどちらもB0を使うので、元のB1全試行を再現する実験ではない。既知の良い手が独立色でも勝つという前提を置かず、主検査の昇格基準へ加算しない。

元の実未来でa0の保存結果を再現する制御検査は別枠。隠れた未来は環境だけに置き、選別へ使わない。全実験のwall上限30分。これはゲーム40手の期限、1手250msの製品予算とは別。

既存の平均約84〜94ms/chooseからは主検査の検索だけで約5分の桁、起動・診断・検証・保存を含め概ね6〜15分を見込む。ただし新実装の実測値ではなく、30分で未完了なら未判定とする。最大約3,500判断×6-threadのCPU仕事量を記録し、1判断へそのまま持ち込めないことを明示する。GPUと学習は不要。実装・回帰・レポートの目安は2〜3人日で、成果は保証しない。

**次の軽量化設計へ進むための探索的な条件**を以下で固定する。製品採用の合格基準ではない。

1. 再現・意味的テスト・情報制約が全て成功し、全主検査が完了。
2. 選別側で切替が起きた局面が、少なくとも4つの異なる元seedにあり、両キャラと24手目を含む。単一終盤例だけで判断しない。
3. 確認側の選択手対a0のP40差が全体で正、各キャラで非負。正の差が少なくとも3つの異なる元seedにある。
4. 確認側の死亡＋配置不能、初回13以上/14以上、P30/P35が各キャラで悪化しない。初回10〜14はP40失敗として数える。

同じ元seedの別時刻・別キャラを独立試行にしない。主検査全16局面を等重みで集計し、元seedをまとめた対応bootstrapの区間とgain/lossの生数を併記する。小標本のため、条件を満たしても一般的優越は未証明。

- 条件を満たす：root評価に改善余地がある限定的な根拠。次に実時間向けの軽量化と空盤面からの対応試験を設計し直す。**この実装タスク内では進まない。**
- 切替が十分あるのに確認側で改善なし：このR1を不採用。最大連鎖優先へ戻したり、標本数・候補数を後から増して救済しない。
- 切替不足、成功がほぼ観測されない、又は予算打切り：情報不足として保留。全root、B2、階層計画の不可能性とは結論しない。

いずれも一回の診断レポートで停止する。各200seed以上の最終holdoutはまだ使わない。将来の採用判断は空盤面・同CPU/時間上限・全開始試行分母のP15_first@40で行う。
