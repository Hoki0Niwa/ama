# 独立Feverシミュレーターとの接続

オフラインの完全対戦・学習環境は `C:/Users/ho_ki/git/fever-simulator` が所有する。AmaはAI・探索・評価・エンジンAPI、ブリッジは観測・入力・ランチャーを担当する。

## 用途と実行

C++20のイベント駆動審判で、通常→突入→タネ交換→復帰→勝敗を進める。全26キャラ、52タネ、倍率、相殺、2系統予告、時計、マージン、並列試行、記録・再生、学習用batch APIを扱う。

```powershell
python C:/Users/ho_ki/git/fever-simulator/tools/ama_selfplay.py --ama-root C:/Users/ho_ki/git/ama-fever --seed 0 --matches 4 --workers 2 --output bin/simulator-check --audit
```

Amaの `ModeBattleEngine`／nativeを2席へ接続し、現在手＋NEXT2と同時刻の公開観測を渡す。席別設定は `--seat-config`・`--seat-width`・`--decision-budget-ms` を使い、正確な引数形式は同ツールの `--help` を参照する。再生はシミュレーターの `fever_simulator.exe --replay`。Ama側 `fever_battle.replay` は別の明示イベント形式用。

## 確認範囲と制約

実機の記録と照合済み：色列とタネ、攻撃の発射・到着フレーム、相殺、通常全消し交換、落下なし復帰、共有乱数、マージン。未照合：入力時間の代表値14F（既定の `direct`。記録の入力を再生する経路だけが一致する）、別キャラ・別の日。環境の連鎖時間一致をAmaの時間予測・入力一致へ自動的に読み替えない。Amaの審判・モデルはrevision 10の時点のままで、revision 12〜15の相違は [対戦ルール](FEVER_BATTLE_RULES.md) と [時間モデル](FEVER_TIMING.md) に書いた。

実機と同じ席設定の5seed比較では、全5リプレイが再生一致し、同条件の再走も同一。実機の勝者とは3/5一致で、手数・最大連鎖・Fever突入は相違した。prefetch・実入力遅延・壁時計探索を完全再現しておらず、5標本の勝敗一致を精度として使わない。

出現列が塞がった局面で、接続が現在Pieceの実姿勢を渡せず停止する制約がある。未完走を敗北や成功へ置き換えず、比較の全試行へ含めて報告する。

## 学習用に凍結する条件

原因の分からないおじゃま落下の1〜3F（捨てられるおじゃまがある落下だけ、実機が長い）は、既知の相違として残して凍結できる。同じシード同士の対照（Ama同士、40シード×キャラ入替、2026-10-18、`tools/ama_option_ab.py`）で、捨てがある落下を+3Fしても、勝者が変わったのは捨てがある57試合のうち2試合で、手数・連鎖・突入・試合の長さの差は有意でなかった。

凍結の前に決めることが2つある。

- 入力時間のモデル。`direct`（代表値14F）と `source_control`（移植した操作処理、1手14〜28F）では、試合の長さが+35％、通常の最大連鎖が両席の合計で+4.6、勝者の入れ替わりが25/78試合と大きく違った。どちらが実機に近いかは、実機ログの手数・試合の長さ・最初の本線と比べて決める。
- 観測の項目。シミュレーターの観測は、飛行中の攻撃の量と最も早い到着を別に持つ。ブリッジの実機用の読み取りは、飛行中と到着を合わせた未確定の量だけを渡す。記録ツールは同じ値をメモリーから読めるので、ブリッジに読み取りを足すか、学習の観測から外す。

同じ試験で、シミュレーターのFever倍率表が17値のままでAmaの要求が拒まれ、Amaの自己対戦が止まることが分かった。シミュレーター側で19値を渡すように直した（得点の計算は変わらない）。数値と限界は同リポジトリの `docs/VALIDATION.md`「凍結の感度試験」。
