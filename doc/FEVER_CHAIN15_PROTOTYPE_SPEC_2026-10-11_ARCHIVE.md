## 0. 目的と実装単位

第一目的は `P15@120`：空盤面から120手以内に、15以上を実際に消去した試行の割合。最大潜在連鎖、仮想列での最大連鎖、通常得点は補助指標とする。まず可視3、空盤面、おじゃま無し、ラフィーナ/ラフィソルで比較する。

試作を二つに分ける。

- **P1：多様性ビーム＋可視情報だけで進む方策の継続評価。** 現Amaの候補生成を再利用し、rootと構造の違う盤面を残す。最終候補を別の未知色標本で比較する。学習/GPU不要の試作を先に成立させる。
- **P2：学習した完成確率＋探索。** まず小型Value＋ビームだけを比較する。改善を確認した場合にPolicyと確率ノードPUCTを追加する。P1の観測・遷移・評価器・記録を使う。

80%は研究目標。初期の開発用64試行/キャラでは現行に対するP15の絶対差+10ptを候補選別の目安とする。これを最終的な有意差や採用条件と混同しない。

## 2. 情報・遷移・発火の契約

概念的なC++ APIは次の形とする。以下はコンパイル可能な実装コードではなく、責務を固定するための型の設計。

```cpp
struct Observation {
    Field field;
    std::array<Piece, 3> visible;  // 現在手 + NEXT + NEXT2
    unsigned visible_count;      // 原則3。可視2試験は別群
    CharacterId character;
    uint64_t dropset_index;       // モード出入りや本線発火で戻さない
    unsigned remaining_moves;
    ConstructionPhase phase;     // 初回/再構築。判定方法をmanifestに固定
    RuleProfile rules;            // margin、廃棄時機、special_moves等
};
struct Budget {
    unsigned total_threads;      // nested parallelismを含め上限6
    uint64_t node_limit;          // 0なら指定なし
    SteadyTime deadline;
    size_t memory_limit;
};
struct Candidate {
    Move first;
    Evidence evidence;           // observed / geometric / sampled / oracle
    CandidateStats stats;
    std::optional<VisibleFireWitness> fire;
};
CandidateSet propose(const Observation&, const ProposalOptions&, Budget&);
Decision compare(const Observation&, const CandidateSet&,
                 FutureSampler&, const EvaluationOptions&, Budget&);
```

環境seedや実際の4手目以降を `Observation` へ入れない。実ツモを保持する環境と、探索用RNG・標本を作るSamplerを別オブジェクトにする。各rolloutで行動器に渡すものもObservationだけ。環境の隠れキューやその乱数状態を読む関数を持たせない。

1手の遷移は「現Pieceを合法設置 → 14段目等の処理 → pop → 敗北判定 → 可視キューを1つ進め新NEXT2を公開」。現在のRule実装を使い、同一seed上の旧器/新器で変えない。発火で手数や形状周期を巻き戻さない。

通常構築の候補と発火方針を分ける。最初の比較では旧 `_normal_options/_solo_build` 相当の方針を固定する。最終手が変わった場合は `builder_proposal → fire_selected → tactical_selected → executed` を個別に記録する。`fire=false` でも実消去するので、成功判定には必ず遷移のlinks数を使う。

可視3手以内の確定15発火は別のWitnessとして保存する。毎手盤面と可視列を照合し再検証する。Witnessが確定する範囲を過ぎた部分、幾何的な仮置き、未知色を仮定した手順には「確定」と付けない。

## 3. P1の候補生成

### 3.1 層の多様性

最初は幅250・深さ8、仮想列6という旧器と同じ規模にする。初手は最大22配置程度なので、各rootの候補を失う位置を記録できる。

暫定quotaは次のように実装する。合計幅は増やさず、比較は同じ実行時間でも行う。

1. 同一層で実盤面が一致する候補をまとめる。root別の支持は保持する。64bitのhashだけで同一と断定せず完全盤面を照合する。
2. 生存しているrootごとに上位2個、最大44枠。
3. まだ採用していない候補から構造bucketごとに上位2個、合計最大64枠。
4. 残りを全体上位で満たす。root/構造の予約枠が余れば全体へ返す。幅250を越えない。
5. 小幅16〜32のrollout器にはこの固定44/64枠を流用しない。比率と最小1枠を別設定とし、まず従来型の安価な層選択を使う。

構造bucketの初期案：`(主な仮想発火点の列, 潜在連鎖の帯, 中央高さの帯, 左右どちらに余地が多いか)`。これは連鎖形の完全な識別子ではない。尾の位置・消去順の簡易署名を加えた版は別ablationにする。発火口候補が複数ある場合の上位2個を記録し、主発火点の変更回数も測る。

候補の根拠は分けて保存する：現行幾何評価、実発火得点、潜在リンク数、消去群の余分な個数、残りセル数、現在/NEXTの合法な非致死配置数。初回は旧評価の重みを変えずquotaのみの効果を確認する。

その後に検証する空間特徴は、`現在cells−消去可能cells`、`消去群合計−4×links`、中央の余白、特殊形状の安全な配置数、同色供給待ちの鍵の数、発火点が埋まる候補数。これらは到達確率の代理値であり、絶対的な容量の証明ではない。1〜2連鎖の整理を一律に罰したり禁止したりしない。5/6個消しへの減点は過去の強罰失敗を踏まえ独立ablationにする。

### 3.2 候補消失と延長可能性の診断

各層で `generated / illegal / dead / TT_merge / score_pruned / quota_pruned / chain_cutoff / deadline` の件数、root別の生存数、最終消失深さを記録する。発見した15のWitnessが途中のどの比較で落ちたかを、保存局面から大きい予算で再生する。

局面への後知恵をオンライン機能に混ぜない。oracleや重い探索で見つけた配置列のprefixを旧器の層へ挿入し、(a)生成できない、(b)生成したが評価で落ちる、(c)終端評価で選ばれない、を別の診断モードで数える。これがC/Dを区別する主実験。解を見つけられなかった局面はCでもBでも未分類にする。

動的予算は最初から学習しない。quota版が同条件で有効なら、占有48未満/48〜63/64以上とroot評価差・不確実性に基づく予算配分を次の比較にする。任意のrootが目標へ届いた瞬間に全rootを停止する旧条件と、各rootの完了状況を保持して共通深さまで比較する条件を分ける。

### 3.3 未知色Sampler

形状は `drop_at(character, dropset_index+k)` で確定。試作環境に一致するSamplerはpair/tripleのA/Bを独立4色、quadを異色2色、BIGを任意色選択可能な形として扱う。BIG出現色は操作時間を測る場合には残す。quadの12順序付き色対を等確率で引く。BIGで1種類へ畳むのは色変更時間を目的に含めない盤面モデルだけ。

現行固定6列、試作分布の6列、標本数増加を別々に比べる。未知色が偏ったストレス分布は最悪条件評価として別群にし、Steam分布だと主張しない。

候補生成に使った標本と、候補を最終評価する標本は独立。最終評価では全候補に同じ将来標本を渡す（Common Random Numbers）。探索RNG seedは環境seedの派生にせず、別に固定しmanifestへ記録する。

## 4. P1の非先読みrolloutとAnytime動作

### 4.1 正しい推定対象

候補aの値は、aを置いた後に固定した継続方策πで判断し続けた `P(残りh手以内に実15 | observation, a, π, 色モデル)`。最適方策の到達確率とは呼ばない。rollout方策は可視3からの安価な幅16〜32・深さ3のビームを初期案とする。深さ4以上を使う場合、その先は行動器自身の独立Samplerで補い、外側rollout環境の未公開色を渡さない。

初期Kは最大8root（旧器の選択手を必ず含む）。未評価の合法手の中にも良手がある可能性があるため、K22の重い対照と候補生成源を変えた対照を設ける。弱いrolloutが旧器の良い計画を実行できない場合があるので、旧器π・安価π・学習πのラベルと比較を混同しない。

```text
incumbent = 完了した旧器の合法手、または最初に確保した合法fallback
candidates = diverse_beam.propose(obs, proposal_budget)
for complete_batch in 評価用の未知色標本:
    for a in 全ての残存候補:
        s = env.apply(obs, a)
        while 未終了 and horizonが残る:
            next_action = rollout_policy(observe(s))  // q0..q2のみ
            s = env.apply(s, next_action)
        save(success15, dead, first_fire, moves, censored, leaf_features)
    同一標本数の比較が完了したらincumbentを更新
    明らかに不利な候補を段階的に除き、残存候補へ追加標本
return 最後の完了した比較でのincumbent
```

段階標本数は4→8→16を開始案とする。少数標本で各手の厳密な95%保証を作ろうとしない。Wilson等の区間は不確実性診断へ使い、候補の削減規則は開発seedで固定する。最終性能の信頼区間は独立した試行単位で計算する。

### 4.2 長い目的と短い計算の整合

**H24で15が出なかったことをP15@120の失敗ラベルにしてはいけない。** 最初のオフライン実験Aでは残り120手を上限に方策を最後まで進め、成功/死/上限未達を集計する。H8/16/24の打切り版は `success_within_H` と `unfinished`、葉の特徴を別に返す。未完成を成功数に加えず、120手の確率とも表示しない。

実用版ではまず「H内の成功率＋未完了葉の旧評価」を明示した代理評価として比較する。P2導入後だけ、葉の残り手数に条件付けたValueで長期推定を補う。真の実成功、推定Value、幾何評価を同じ列に合算保存しない。

予算内に有用なrolloutができなければP1を多様性候補生成だけに縮小し、旧器より勝った部分だけを残す。P1全体が実用時間で無効なら採用しない。

### 4.3 時間・空間制約

研究比較点は100/250msと1/5秒。実対戦の承認済み上限ではない。まず候補生成60%・継続評価35%・返却5%という配分を試し、時間の内訳を実測して変更する。deadlineはmonotonic clock、外側で総スレッド6を管理し、6-thread検索を6本入れ子にしない。

時間切れの直前に有利な結果だけ届いた候補を選ぶ偏りを避ける。未完了batchは比較へ入れず、最後の同一標本数の結果を使う。共有可視prefixの遷移cacheを使い、最大メモリ256MiBを初期の研究上限とする。時間/メモリ超過時は完了した手を返す。旧器adapterにも同じdeadlineと安全な完了単位を設け、現在の無打切り器を時間制限器と称して比較しない。

## 5. 発火方針を変える実験の分離

検索方式と発火方針を直交させる。

| 方針ID | 初回扱い | セカンド扱い | 用途 |
| --- | --- | --- | --- |
| legacy_mode | 現在の容量解除＋build15 | 現在のsecond14、sustained_min12 | 最初の検索方式比較 |
| requested_second15 | 初回同じ | 指定second15、min12は残る | 今回測定した設定対照 |
| research_p15 | 15完成確率優先 | 同じ目的、旧効率発火を別候補化 | P1の効果を切り分けた後 |

research_p15でも13/14を無条件に禁止しない。容量解除で選ばれた発火を含め、消す/伸ばすを同じ未来標本で評価する。死や配置不能を回避する制約を併記し、「必ず15を待つ」という変更をしない。相手の致死攻撃を無視して15を追う方針は通常構築の研究範囲外。

途中の小消しは、同一局面の非消去候補との対応rolloutで、生存やP15への差を測る。改善があるものは整理消し、無いものは不要消去候補と操作的に分類する。計算で未確定のものを不要と断定しない。

## 6. P2a：学習Value＋ビーム

### 6.1 データ契約

入力は6×13の色/空き/おじゃまone-hot、中央の敗北線、可視3の形状と色、BIGの選択可能性、16周期の位相と未来形状、残り手数、初回/再構築、margin・廃棄規則。キャラ通常倍率も使う場合はデータから入力する。キャラ別専用ネットを最初から26個作らない。

保存単位は `trajectory_id, environment_seed_group, observation, candidate_action, behavior_policy_version, continuation_policy_version, model_version, search_budget, sampler_model, draws, successes, deaths, censored, first_fire, time_to_goal, expert_action_distribution`。教師探索が大きいだけの値を実結果のラベルに置き換えない。oracle成功列は候補やcurriculumに使えるが、未知色での成功確率1の教師にはしない。

軌跡seedでtrain/validation/testを完全分離する。同じ盤面の色置換や再開局面を分割の両側へ入れない。ログの隠れツモ、seed、未来の最大連鎖は入力禁止。学習途中の性能確認で最終200seedを読まない。

最初の教師は旧器だけでなく、P1・重い可視探索・部分目標生成から集める。各候補を独立未来で継続し、探索を増やした教師が本当に旧器より良いか検証する。改善を確認した候補分布をPolicy教師にする。旧Amaの行動をそのまま大量模倣して性能上限を超えたとは扱わない。

### 6.2 モデルと目的関数

初期案は64chの小型residual CNN 4block程度＋global features＋mask付きaction head、0.3〜1Mパラメータを目安とする。実際のパラメータ数、CPU推論時間、SIMD/batchの効果は実装後に測る。

- ValueはP13/P14/P15/P16、死亡/配置不能、到達手数分布を出す。`p13=sigmoid(z13), p14=p13×sigmoid(z14), ...` 等で包含関係を保つ。
- 複数未来の成功数k/nには二項の負対数尤度を使い、標本数と方策版を保持する。12手打切りの未完了局面を120手失敗の教師にしない。
- Policyは合法配置mask付き分布を学び、探索の訪問数/候補比較結果を教師にする。推論時に不合法手が最大でも返せない構造にする。
- 到達時間は右打切りを扱う離散hazardまたは生存損失。15未達を都合よく削除しない。
- 色の24置換はルール対称性を確認して使える。左右反転は出現位置/経路/3個組の型の変換が必要なので自動的には増強しない。

評価は未知seedでのBrier score、信頼度図、校正誤差、占有帯/形状/キャラ/再構築別の誤差と、最終的なP15。単なる平均二乗誤差の低下を採用基準にしない。holdoutで「推定0.8」の盤面が実際には0.2なら温度校正だけで直るとは限らず、教師・分布・入力を再検討する。

初期使用箇所はP1ビームの葉の順位とrolloutの打切り葉。旧幾何評価との混合係数、NN無し、NNのみを比較する。Value精度が良くても推論で候補数を失いP15が下がれば不採用。

## 7. P2b：Policy＋chance PUCT

decision nodeの探索指標を `Q15(s,a) + c_puct P(s,a) sqrt(N(s))/(1+N(s,a))` とする。窒息・P14等は別統計で持ち、主目的に大得点が勝つような安易な混合をしない。開始時は合法手すべてに小さいpriorを置き、NNの0確率で探索不能にしない。無学習UCT版も計算比較用に残す。

chance nodeは次に新しく見えるPieceの色をモデルで引く。pair/tripleは16色対、quadは12異色対、BIGの盤面上の色自由度は1クラス（入力時間を扱う場合は出現4色）。形状は既知。**chanceの子にPUCTで有利な色を選ばない。** 既知確率の平均か確率に従う標本平均でback upする。

rootは合法手が約22以下なので全て用意できる。progressive wideningは深部の目標macro/履歴で子が増えるときに `children ≤ c N^α (0<α<1)` として導入する。色の不利な少数事象を永遠に追加しない方式にしない。小さいchance集合は全列挙平均の対照も作る。

tree/TT keyは盤面、可視3、キャラ/周期、残り手数、phase、rule/margin、目的/Value版。隠れた実キューをキーへ入れない。観測が同じなら将来標本が違っても同じdecision nodeで方策を共有する。実際に次Pieceが判明したら一致部分へrootを移し、盤面の変化や物理条件が違えば破棄する。

葉ではValueを返すか、可視3だけの方策rolloutを少数追加する。推定Valueを「15連鎖発見数」として数えない。木再利用の有無、方策prior有無、Value有無、同時間beamとの比較を個別に行う。

## 8. 第3候補：動的逆算・階層計画の接続点

P1/P2が空間と尾の問題を残す場合の次工程。最初から完全な固定15連鎖盤面を生成しない。

目標は2〜4リンクの部分消去順、同色/異色制約、支持セル、発火口、尾の追加位置、必要な空間として表す。既存盤面へ逆に群を追加し、forwardの `pop` でその順序と連鎖延長を検証する。これは連鎖としての成立検証で、実ツモからの到達可能性とは別。

少数の異なる目標（最大8を初期案）を保ち、現在可視3の合法遷移で近づける手だけをP1の候補源へ入れる。可視の範囲には具体的な配置Witnessを要求し、遠い部分は制約充足度と必要色・配置余地を推定する。未知色により成立しなくなれば目標を変更するが、変更回数・達成した部分構造・放棄理由を記録する。切替コストの強さは開発seedで固定する。

GTRという名前や左右の固定位置を必須条件にしない。発火口を残す小目標と、尾を伸ばす小目標を分け、合法到達Witnessと未知色への継続成功率で共通比較する。目標の高さが過大、必要セルが不足、特殊ツモの置き場が無い場合は候補を減らす。厳密な不可能性が証明できない下界で全候補を捨てない。

## 9. 原因A〜Fを分離する実験

同じ失敗局面から介入を一つずつ変える。要因は重複するので排他的な100%の円グラフにはしない。

| 原因 | 比較する介入 | 得られる結論の限界 |
| --- | --- | --- |
| A 容量 | 合法な非致死配置、廃棄を除く候補、margin緩和候補、NEXT余地を全列挙 | その時点の逃げ道を診断。そこへ至った原因とは別 |
| B 構造 | 同じ色数/占有帯で部分目標候補、余分な群消費、連鎖尾の延長Witness | 形の関連。見つからないことは不可能の証明でない |
| C 探索 | 同一評価でquota/予算を変更。発見した解のprefix消失を追跡 | 実解を見つけたケースだけ検索の取り逃しを示せる |
| D 評価 | 同一候補集合を旧得点/幾何/非先読み継続値で再順位付け | 候補生成の改善と分離できる |
| E 未知色 | 可視3、既知8、既知全列を同計算量で比較。さらに複数未来再抽選 | 情報差と計算差を分ける。oracle失敗は上限証明でない |
| F 発火/戦術 | 同じ構築提案をlegacy/P15方針、さらに戦術有無で実行 | 本線消費の採用理由を区別。対戦勝率は別目標 |

保存局面を選ぶ基準を結果の良いものだけにしない。今回の初回15未達全35件を開発診断へ使い、成功13件も対照にする。各局面で64の独立した未知色へ継続する実験を先に設計し、費用を測って実行数を決める。これを最終holdout成績へ混ぜない。

## 10. 比較契約・採否・必要な検査

### 比較manifest

`source hash, dirty diff hash, binary/DLL hash, compiler flags, CPU/OS, total threads, timer/budget, backend/options, physics/margin, visible_count, character/pattern, seed groups, initial field, horizon/stop reason, scoring/color model, policy versions` を保存する。ホスト/バックグラウンド負荷が異なる速度測定は混ぜない。

開発16→64/キャラ、最終は方式を凍結して**未使用200以上/キャラ**。train/validation/holdout候補は研究報告を参照し、実行前に過去使用を確認する。複数方式を最終holdoutで選び直さず、比較対象と判定を事前に固定する。

各seedで旧器/新器のツモ・盤面・可視数・ルール・計算上限を揃える。wall時間P50/P95/max、期限超過、node/evaluation回数、全processメモリ、火力ではなく実linksを保存。対戦の二席を並列動作させた遅延は独立した実用評価群。

15未達の120手終了、死、nomove、engine errorを分母から除かない。15消去と同時に死んだ場合はP15と死亡の両方へ記録し、`P15_and_survive` も出す。最終採用では死亡増を許容しない条件を別に検査する。16以上は15で停止する本試験とは別に、継続400手の群でも測る。

暫定採用基準案：P15対応差の95%下限>0、P13/P14の対応差の95%下限>−5pt、死亡/nomove増加の95%上限<+2pt、時間上限遵守。後二つのmarginは研究開始時に固定する提案値。200件で非劣性まで十分に識別できるとは限らず、区間が跨げば保留/追加試験とする。新器だけ都合よく標本を除外したり上限を変えたりしない。

達成率はWilson95%、対応差はseed単位bootstrap、成功の入替はMcNemar exact。探索乱数を複数引く場合は環境seedをclusterとして集計する。200で観測80%と真の率80%以上の95%保証は別。途中でholdoutを開けて方式を直した場合は新しいholdoutを用意する。

### 意味のある検査

- **未来漏洩**：同じObservationで未公開実列だけを入れ替え、同じ探索seedで最初の選択が一致する。公開された色が違う次手からは変化してよい。
- **物理**：全4形状、単色triple、BIG全色、13段目/14段目、中央敗北線、廃棄、上端の経路を既存回帰と独立scalar再生で照合する。
- **状態key**：盤面一致でも周期/可視/残り手数/margin違いを誤結合しない。複数root支持を消さない。
- **予算打切り**：短予算でも合法fallbackを返し、未完了batchを有利な証拠として採用しない。計算量・memory統計が実展開と一致する。
- **成功指標**：13/14や `expected_chain=15` で成功/試験終了にしない。実連鎖の全linkを独立再生する。
- **学習**：同軌跡のseed分割漏れ、隠れqueue列の入力混入、確率の包含関係、mask、打切りラベルを検査する。
- **統合時の回帰**：Tsu protocolと同seed benchを固定し、Feverの既存回帰、旧backendでの同入力同結果を確認する。

### 作業順と中止基準

| 段階 | 提出物 | 次へ進む条件 |
| --- | --- | --- |
| R0 3〜5人日 | 診断、同条件adapter、再現manifest、既存器一致 | baseline再現、未来漏洩/物理/指標検査成功 |

P2はR2の実用改善が小さくても、オフライン教師に改善がありその計算を圧縮できる根拠があれば着手候補になる。R3で負けた器を既定へ入れる理由にはしない。

学習資源の初期案はCPUによる100万〜1000万遷移と、12〜24GB GPU1台・24〜72時間の試行枠。必要十分量の予測ではない。10,000遷移の費用から再見積もりする。現行相当100msの判断を10万局面×16未来×24手に使うと約44日相当になるので、生成policyの高速化とbatch推論が必要。3訓練乱数で再現性を確認し、予算・誤校正・教師改善無しのいずれかで打ち切れるようにする。

ゼロからの深層RL、全評価係数のCEM、全15リンクの厳密逆算は初手にしない。RLを後で試す場合は13/14局面のcurriculum、到達状態archive、探索教師を使い、潜在報酬を `γΦ(s')−Φ(s)` と終端0で整合させる。最終P15を他の密な報酬で置き換えない。
