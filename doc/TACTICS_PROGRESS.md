## 2. 判断の物差し（ユーザーの指示）

- 勝敗に最も関わるのは、どちらがより強い本線を打ったか。強い本線を素早く完成させるのが最優先。
- 先に本線を打たれて自分の本線を崩すのは相当な悪手。届く本線は時間ぎりぎりまで積んで打つ。届かない本線は打たず、小さな相殺でフィーバーを繰り返す。相殺して100個くらいまで減らせればフィーバーで逆転の機会がある。
- 勝ち筋は、中盤戦を仕掛けて相手を先にフィーバーへ入らせること。
- フィーバー中のタネは伸ばすのが基本。即発火するのは、相手の通常盤面に降らせて連鎖を組む時間を与えない場合と、両者フィーバー中で相手に保留予告がある場合だけ。全消しは積極的に狙う。
- 縦3や中央の高さのような人間向けの形の目安は、計測で示せるまで入れない。例外ルールを足す実装は避ける。

## 4. 測って分かったこと

- **連鎖の時間の予測は合っている**。相手連鎖の終了の予測が実際より遅かった例は208回中0。ちぎりの時間の見積もりも実機と合う（1段11フレーム、2段18など）。
- **予告は、送った側の連鎖が終わったフレームで確定する**。リンクが数えられてから相手の予告欄が増えるまでは約24フレームかかる。
- **接地した後に確定した予告も、そのツモに降る**。落下456回のうち83回がこれで、接地の中央値15フレーム後に確定している。ちぎりで落ち着くまでの間が狙われる。
- **端数のおじゃまが落ちる列は決まっている**。端数の落下133回は、すべて 1・4・3・6・2・5列目の順の連続した並びだった。
- **フィーバーで巻き返せる量**：予告を抱えて突入したとき、戻りの残りが30個以下だった割合は、100個以下で67〜82%、101〜400個で43〜53%、400個超で19%。目安の100個は控えめである。
- **本線1連鎖あたりのぷよ数**は中央値6.5個で、想定（6個）と合う。
- **確定予告が盤面を埋める量の2倍を超えると**、ゲージ0〜3では68%が敗北、ゲージ4〜6では23%。ゲージが近いと逃げられる、という式の向きは合う。
- **フィーバーから大量の予告を抱えて戻ると立て直せない**：300個以上で戻った119回のうち、その対局の敗北は83%。戻ったときの盤面はぷよ中央値30個・最長連鎖3しかない。

## 5. 残っている問題

10-09更新：通常対通常のゲージ加点をなくし、突入目的の小消しを減点。セカンド目標設定・戦術の中央列余白・同じ攻撃の最終収支での準備再利用・潰しの誤加点除外を追加した。以下の元の観測は残す。修正版の実機受入れ・勝率・潰しの実着弾は未確認。

1. **「降らないと判断したのに降った」設置**：5時間で18件（設置約15600回）。うち17件は相手連鎖を渡せていて、予告欄は0、連鎖の残りは終了だけという状況だった。原因は特定できていない。要求はログに残っている。
2. **位置を渡しても残る「本線を崩す」判断**：計測で、1条件あたり24〜40回残る。原因は未調査。
3. **倒せない相手に本線を持ち続ける**：完成した本線を打つ理由が、相手を倒せる見込み以外に値の中に無い。計測の相手（倒せない空盤面）に対して、12連鎖を持ったまま予告を受け続け、埋まって負ける局がある。実戦でも相手がフィーバー寸前のときに起きうる。
4. **タネ消化の失敗**：5時間でタネの発火787回中80回（10%）が規定未満。オフラインでは、15連鎖のタネで置き場所が尽きる失敗（規定12開始の失敗21回中17回）と、自分のフィーバー側に確定予告があるときの失敗（列が不明な落下で180局面中7〜12件）が残る。
5. **催促ができない**：本線だけを組む構築では、催促に使える連鎖が盤面にほとんどできない（本線のある434手中1手）。
6. **発火を遅らせる操作が無い**：相手の連鎖の終わりに合わせられるのは「どのツモで打つか」までで、発火色を引いてから空中で待つことはできない（ブリッジの入力の変更が要る）。
7. **式の定数は未調整**：倒せる見込み（着弾の割合の2乗、相手は3ツモで1リンク作る）、巻き返せる目安100個、妨害の加点、全消しの加点。
8. **入れていない戦術**：相手のタネ交換中を狙う単発（妨害の加点で一部は出るが、タネ交換の瞬間は見ていない）、記事の「両者フィーバー中で相手に予告がある場合」の連続発火、15連鎖タネの扱い、でかぷよ用の段差。

### 2026-10-09 開始から初回Feverまでの構築保護

双方のmode_generationが0で通常盤面の場合、無脅威時の一般的な催促加点は使わず、実際に相手が相殺でFeverへ入れる副砲を評価する。構築が発火を許可していない手は、本線／副砲の分類を問わず、部分的な倒せる見込みだけで発火させない。全消し、目標／容量発火、相手の実攻撃への必要な防御は維持する。初回以後の一般催促は従来の条件を維持するが、将来の本線まで消費する手順を副砲催促として加点しない。Pythonのquiet採用も、ネイティブが実際に催促を加点した手順へ限定する。

構築の実完了深さを仮想未来6本別に返す。深さ設定の値は探索完了の保証ではない。対戦の構築は別exeではなく、対戦worker内のop=soloを使用する。


### 2026-10-09 最新方針：高い本線を繰り返し、細いFeverの勝ち筋を潰す

ユーザーの追加指示により、11連鎖到達を合格条件とした先の比較は受入れ基準から外す。高い初回本線とセカンドの継続構築を基準とする。

- 倒せる見込み（保持・高さ・将来ゲージ逃げから作るkill比率）は攻撃加点・quiet発火採用から削除。互換の `projected_kill` は0を返し、kill重みも使用しない。フィーバー潰しは量・実際の送信先・相手種の反撃・着弾時機で評価する。
- 構築60ms、戦術40ms、種探索・相手種検査・お邪魔防御・終了検査のCPU時間による打切りを撤廃。旧 `decision_budget_ms`／`budget_ms` は互換入力であり探索を打ち切らない。設定した幅・深さ・ノード上限は探索量を規定する。通信故障を検出するworker応答待ちは別で、未完了層を判断結果へ流用しない。
- マージンタイムによる得点レート変化、実際のFever残り時間、相手連鎖終了と潰しの着弾期限は維持。これらはCPUの計算制限とは別である。
- 初回も手数経過で要求連鎖数を下げない。初回／セカンドは設定目標で構築・発火し、安全な積み場所がなくなった場合は容量発火を探す。容量発火で目標未満を打てたことは、目標達成とは扱わない。
- 構築に必要な1～2連鎖の整理まで一律に禁じると、元の最良候補を捨てて大連鎖構築が劣化した。最良候補の小消しは許し、未完成の3連鎖以上の本線消費を抑える。大盤面の目標前本線を将来の全消し加点で上書きしない。少量盤面の全消し・相手突入を促す副砲・必要な防御は維持。

設定連鎖数がある場合に仮想未来の連鎖数を直接優先する実験と、深さ16へ増やす実験は、連続構築で改善せず採用しなかった。最終版は元の構築順位を維持する。試作色列比較は実戦成績ではなく、15連鎖の安定達成を確認したものでもない。
