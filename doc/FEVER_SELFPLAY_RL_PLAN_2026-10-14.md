# Ama Fever：構築の事前学習から自己対戦へ進む研究計画

2026-10-14。依頼は、複雑なフィーバー戦術を自己対戦による強化学習で改善し、その過程で通常の16万点超えの構築も習得できるかを、実験結果から再検討すること。**今回は調査・保存結果の確認・設計のみ。学習、追加ベンチ、環境の実装、製品変更は開始していない。**

推奨は **「S0Gを教師にした構築方策の初期化 → 目標得点@40の強化学習 → 構築課題を併用するリーグ自己対戦」**。自己対戦だけから16万点構築が自然発生すると期待せず、構築を学べる初期能力と練習課題を持たせる。既に改善したS0Gを比較基準として残す。最初の実装単位は後述の **RL-P1：通常構築の教師初期化＋小規模PPO** 一つとする。

## 3. 自己対戦で16万点構築を学べるか

**可能性はある。ただし、勝敗だけでは習得を保証しない。** 相手より早い小連鎖、相手をFeverへ送る手、守備の継続で勝てるなら、それらが報酬を得る。16万点の準備に負ける弱い初期方策同士では、長い構築へ進む動機も学習例も乏しい。自己対戦の勝率や内部Eloが上がったことと、大連鎖の組み方が上達したことを別に測る必要がある。

今回の有利な出発点は、既に13〜14連鎖を組め、S0Gで目標点成功の実例も得られていること。Amaの配置・成功／失敗軌跡で初期化すれば、完全なランダム方策から大連鎖を発見する課題を避けられる。Amaの候補上位だけへ行動を制限せず、以後は全合法配置と実成否で更新することで、模倣の限界を超える余地を作る。

強化学習でもルール、合法配置、報酬、観測の境界はコードで決める。減らせるのは「何個なら保持する」「何手前なら撃つ」といった相互作用の手調整である。ルールや操作の誤りをなくす工程は残る。Valueは実結果から学ぶ評価値であり、評価が不要になるという意味ではない。

## 4. 比較した進め方と選定

| 方法 | 長所 | 今の問題／扱い |
| --- | --- | --- |
| 完全ランダム初期化＋勝敗だけの自己対戦 | 手作りの戦術に縛られにくい | 大連鎖を経験できず、小連鎖への偏り・共倒れ・学習環境の穴への適応が起き得る。初手には採らない |
| 既存の数個の戦術案を学習で選ぶ | 小さい行動空間。構築器を保持できる | 候補にない配置を発見できず、16万点構築の改善経路が弱い。後の戦術試作の足場には使える |
| 学習Value＋既存ビーム | 差し替えが比較的小さい | 教師の潜在連鎖を正解にすると従来評価を再生産する。学習・beam費用が両方残る。直接方策の費用／保持が悪ければ次の候補 |
| AlphaZero型MCTS／MuZero | 方策改善と探索を一体化できる | 未来色・同時進行・時間の不確実性を扱う必要がある。既知の物理を最初から学ぶ必要性も薄い。初回から木探索とRLを同時開発しない |
| **Ama教師→構築RL→構築課題併用の自己対戦** | 成功例を使え、全合法配置から教師を超える学習ができる。対戦へ構築を持ち込める | 高速環境・忘却検査が必要。小規模試作で段階ごとに効果と費用を確認する。**推奨** |

## 6. RL-P1の公開観測・行動・実行

### 6.1 環境と入力

最初は凍結S0Gと同じ標準周期・通常モード・空盤面・位相0・可視3・splitmix4。`first40_benchmark.Observation`の7項目と、固定した公開のキャラ周期／通常倍率／目標Tを入力に使う。盤面は14×6、空・4色・おじゃま、可視Pieceは形状と色を区別する。残り手数は`40-placed_total`。整理消しで時計や周期を戻さない。

現在の`op=placements`と`op=transition`を参照とし、2個組、L/J、4個組、でかぷよ、上端消滅、敗北列、配置経路を共通化する。参照nativeが返す現在Pieceの配置をすべて候補にする。将来の3手列やteacher順位で候補を間引かない。キーは既存の`x/r`と必要なPiece意味を保存し、ペアの22手を全形状へ固定しない。死亡を伴う合法手は正しく死亡へ遷移させ、存在しない手と混同しない。

**actor/criticにはseed、列生成器、非公開の4手目以降、試行ID、ログの勝敗・将来得点を渡さない。** criticにも特権的な未来を与えない初期版とする。学習ラベルとして実際の終端結果を使うことと、推論の入力に未来を入れることは別である。環境とactorはAPI・オブジェクト所有を分離し、同じ公開prefixに異なる隠れsuffixを付けたとき、greedy推論の出力が同一になることをテストする。

研究標準と実機modの周期／配置プロファイルは別ID・hashにする。初回試作に製品の新しい操作制約を部分的に混ぜない。後に実機プロファイルを加える際は、S0G対照もそのプロファイルで新測定する。

### 6.2 小型Policy/ValueとS0Gの残し方

提案する初期モデルは64channel・4残差ブロック程度の小型CNN＋公開数値のMLP、全体0.3〜1Mパラメータを目安とする。位置を保つ特徴から、各合法配置のID・現在Pieceだけの配置後盤面・実即時消去点／廃棄をまとめてlogitを出す。候補をbatch評価し、無効候補をmaskする。最初から巨大Transformerや学習済み世界モデルを作らない。

主Valueは**現在の方策で初回T以上を40手以内に実発火する確率**。補助headとして@30/@35、初回の実得点比・死亡を予測してもよいが、teacherの潜在連鎖や幾何Witnessを到達可能性の正解にはしない。BC段階のValueはS0G方策に条件付いた成績であり、最適方策の価値と表示しない。

配置器`RL+F`は、まず凍結S0Gと同じmass gate＋可視score-probe（F）を呼び、採用できればその準備／発火手を返す。Fが無ければNNが全合法配置から1手返す。**NNの通常経路にB0 fallbackを置かない**ことで、構築をNNが担当したかを測れるようにする。timeout・モデル／protocol errorをB0で隠して成功へ変えない。

比較用にはS0G（B0+F）、BC+F（模倣のみ）、PPO+F（模倣後にRL）の同じFを使う。F以前の最初の配置差、F到達手数・率、目標未満発火・未発火・死亡を分け、発火器だけの効果を構築学習の成功と呼ばない。NN単独のFなし版は保存観測・少数の開発診断だけで確認し、本試作の主比較を増やさない。

総chooseは250ms、F内部25ms、CPU上限・観測は対照と同じ。NN推論・候補列挙・IPC・F費用を全て含む。学習用GPU batch推論の速さを実機batch1 CPU推論と混同しない。CPU推論を正式比較に使い、GPU推論は別条件として記録する。

### 6.3 学習データと教師の限界を越える方法

- 保存S0G/S0Cの成功・失敗両方の合法配置prefixを利用する。別方式で同じ公開観測・配置の行は重複として扱い、12,908配置を12,908の独立した学習例とみなさない。seedと元episodeでgroup分割し、同seedの別キャラ・類似prefixを学習／検証に分けない。
- BCは主にS0Gの選択を教師とする。timeout自体には配置教師ラベルがない。正しいprefixは使えるが、時間切れを「この盤面から絶対成功できない」というValueラベルにしない。未知の継続結果はcensoredとして扱う。
- 保存群を訓練へ転用した時点で、その群は以後の未知評価に使わない。必要な追加教師は合計2万判断を上限とし、費用を測る。毎回B0で長いロールアウトを大量に生成しない。
- BCは初期化。RLではNN自身の行動と実結果を使い、teacherと異なる合法配置も探索する。BC補助損失の係数は最初の25万遷移で0.1→0、以後0を初期案として固定する。teacherとの永久一致を採否条件にしない。
- Prefix開始は訓練だけで使用。先行教師の16〜28手の公開状態から、可視3以外の未来は環境が独立に生成する。絶対手数を維持し、成功例だけに偏らず失敗prefixも含める。最初の25万遷移は空盤面50%、次の25万は75%、以後100%。評価は全て空盤面から行う。

### 6.4 報酬とPPO

最初の本線（実10以上）・死亡・配置不能・40手目を終端とする。成功終端報酬1、それ以外0。1〜9の整理消しは報酬0で継続。途中の得点、潜在連鎖、盤面の高さ、ゲージを主報酬へ加算しない。**割引率γ=1**、最大40手の有限episodeで成功確率を学ぶ。早期達成は@30/@35の補助Valueと同率時のcheckpoint選択で扱い、早撃ちボーナスのため@40を犠牲にしない。

得点不足で終わった13/14の実得点比はcriticの補助教師として利用できるが、0.99Tを成功1へ変えない。H1の幾何増点を密な報酬として再導入しない。報酬の疎さはBCとprefix練習で緩和し、まず報酬を一つに絞る。

初期案はPPO clip0.2、Adam学習率3e-4、4epoch／更新、minibatch256、約2048遷移の完了episode集合、勾配norm0.5、entropy係数0.01→0.001。40手までの実returnからadvantageを作る。数値はAmaで最適化済みではなく、pilot前に設定ファイルへ凍結する初期仕様である。

Fが強制した手やBCデータはNNがsampleした手ではない。**PPOのactor lossはNNが実際に選んだ行動だけ**に掛ける。Fの遷移は実returnとcriticには含め、F介入のsourceを全件残す。rollout途中の計算上の打切りはgame terminalと分けてbootstrap／censorを記録する。40手期限は本当の終端で、bootstrapしない。NN例外は評価では失敗、学習では実装不具合として停止・保存する。

## 7. 完全な自己対戦へ進むための設計

RL-P1の成績が良くても、この節の環境完成を省略しない。逆に、完全な実機再現の完成まで通常構築の学習を待つ必要もない。

| 必要な環境機能 | 実装・照合する内容 |
| --- | --- |
| 同時進行 | 両者の設置・各連鎖リンク・落下・操作再開をフレームイベントで処理。同時刻の順序と相殺を明示し、席順の実装都合で有利にしない |
| モード | ゲージ、突入、通常盤面保存、Fever時計の進行／停止、時間加算、終了と通常盤面復帰。周期indexはモード変更で戻さない |
| 攻撃 | 通常／Feverそれぞれの確定・未確定予告、保留、送信先、マージンのレート、端数、相殺、落下上限・列順 |
| タネ | 種類・レベル・色・成功失敗・全消し報酬。記録をそのまま再生するだけでなく、方策が別の結果を出した時にも因果的に次のタネを供給できること |
| 観測 | 観測した相手盤面・可視ツモ・連鎖進行・時計・予告と、その履歴。相手の隠れツモ、未出現タネ、保存盤面の未観測情報を渡さない。不明値にはmaskを付ける |
| 操作と時間 | 実行可能な配置・ちぎり・配置時間。最初は配置単位の判断、明示的wait行動なし。任意待ちを追加する場合は自然落下・ロック・思考遅延を進め、時間を止められる行動を作らない |

`ModeReferee`、native物理、倍率、timing、seed solver、既存プロトコルを再利用し、新しいresearch schedulerを追加する。最初はslowな参照実装で、固定イベントの差分テストを行う。必要な箇所だけC++/batch APIへ移す。試作のタネ分布・時間近似はversion化し、既知のSteamの挙動へ一致しない分布で得た勝率を実機成績と呼ばない。

学習が進むと、乱数の周期、特定タネ、時計停止、落下順の誤りを利用し得る。通常→Fever、両者Fever、時計0境界、全消し、相殺と突入の同フレーム等の保存fixtureを先に用意する。未供給のタネ・モデル不整合は環境errorとして止め、学習上の勝利や引分に置換しない。全モデルを実機で完全照合できない場合は「近似環境でのpilot」に範囲を絞り、相違点を明示して実機移行前に検証する。

対戦方策は通常構築NNの重みから開始し、公開履歴を扱う小型GRUと対戦用Valueを追加する。通常盤面の全合法配置を出せるようにし、既存の戦術ラベル数個だけに固定しない。Feverタネの処理は初期段階で既存solverを再利用し、発火・伸ばし候補の選択を学習する。その候補制約が上限になった時点でFever内の全配置へ拡張する。

**単独構築の「Tが見えたらFで発火」を対戦へ無条件に移さない。** 返し・送信先・残り時計によって温存が合理的なこともある。対戦ではFは合法な候補／公開の証明として渡し、採用を方策が判断する。単独構築の採用済みFの監査と、対戦の戦術決定を分ける。

## 8. 自己対戦の報酬・相手・構築忘却

対戦の主報酬は勝ち+1／負け−1／規則で確定した引分0。16万点を撃つことを全状況で上乗せしない。点数稼ぎのために負ける方策を作らない。ゲーム内上限時間を設ける場合は規則・引分処理を事前固定し、計算予算切れによる未完了と分ける。

構築を維持するため、初期案は更新batchの**25%を空盤面の目標点@40課題、75%を対戦**にする。構築Valueと対戦Valueを分け、方策・盤面encoderを共有または転移して更新する。正規化した各課題lossの重みを固定し、gradient競合・構築成績を監視する。この割合の優位性は未測定で、初回自己対戦前に凍結する。悪化したらcheckpointを保存して割合変更を別実験にする。

相手の初期配分は、凍結した最新Ama25%、一定間隔で保存する過去NN50%、最近の強いNN25%。過去NNが無い間は初期BC方策でその枠を埋める。固定の攻撃寄り・防御寄り対照も診断に使い、初期から大人数のexploiterリーグを作らない。相手更新はepisode境界に限定し、相手checkpoint・sampling分布を保存する。内部Eloだけで昇格させず、固定相手への勝率表と相性・循環を報告する。

構築専用headの成績だけ良く、対戦headが構築を使わない可能性も検査する。通常対戦headを受動相手・無おじゃまの条件で動かす診断と、実対戦中の最初の本線得点・構築手数・被攻撃前後を併記する。対戦で小さい返しが勝ちにつながったことを単独構築失敗と混同しない。キャラ・周期・予算が違う成績は別表にする。

## 10. 評価の分離と判断基準

**新規seed群は実行前の重複監査後に登録する。** 候補範囲は訓練7000000〜7999999、開発8000000〜8000063、独立確認8100000〜8100199。今は未使用を証明・予約したものではない。既知610xx/620xx等は訓練／既知診断へ分類し直し、旧成績は保存する。色源・両キャラ・方式間で同seedを対応させ、ActorへIDを渡さない。

- 開発は64seed／キャラで、3訓練runそれぞれのBCとPPOを比較する。checkpoint選択はPscore@40、同率なら@30、@35、CPU費用の順。開発群は繰返し選択に使ったことを明示し、未知性能の信頼区間を装わない。
- 独立確認へ進めるのは設定とモデルを凍結した1候補。S0G、その候補と同じ初期化のBC+F、PPO+Fの3条件×200seed×2キャラ＝1200試行を上限として事前固定する。追加教師・再学習・seed追加を同時に行わない。この200群を見て調整した後は、群全体を開発済みへ変更する。将来の製品用最終holdoutは別に残す。
- 最重要は全開始試行のPscore_first@40。@30/@35、成功者限定の中央値と全試行の累積分布、初回点数、未発火／死亡／nomove／timeout、cleanup別分布、思考平均/P95/最大・CPU・メモリを保存する。
- 同じCPU/thread上限、250ms、周期、可視3、物理、normal scoringでS0Gを同時期に対照測定する。F同一・配置変化を監査する。NN inferenceは決定的argmax＋固定同点順、推論乱数で良い成績だけを選ばない。
- 両キャラを同seedクラスタとして差のbootstrap95%を出し、gain/loss・キャラ別区間を表示する。教師ラベルの一致率、内部報酬、内部Eloを主成功率へ代用しない。3訓練runの開発ばらつきと、選択後の独立確認を分ける。

個々のseedのlossやCIが0をまたぐことだけで、改善候補を廃棄しない。次の区別を事前に固定する。

| 観測 | 判定 |
| --- | --- |
| 公開情報漏洩・得点／遷移不一致・F不整合 | 当該実装を修正して停止。強さの採否以前の問題 |
| 開発でS0G以上、またはPscore低下2pt以内でCPU/判断を50%以上削減 | 独立確認へ進める研究候補。小標本の同等性を証明したとは言わない |
| 独立確認でS0G比+5pt以上・差の95%下限>0、各キャラの点推定が−2pt以上 | 構築品質の新しい研究基準候補。PPO−BCも表示し、RLの上積みがあるか判定 |
| 差が正でも区間が0をまたぐ、または小さい成績差と明確な速度利益 | 候補とcheckpointを保存して継続判断。改善の兆候を保持し、追加実験は別計画にする |
| 速いが品質の上積みなし | Pscore差の下限が−5ptより上、点差−2pt以内かつCPU半減なら速度重視の別候補。母集団の完全同等・16万点構築改善とは呼ばない |
| 3runともS0Gより5pt超悪化し、BCからも改善傾向なし | このpilotの予算拡大を保留。観測・学習曲線・候補制約を調べ、Value＋既存探索等の別案を再計画。RL全体の不可能性とは一般化しない |

研究昇格には同時に、正常返答250ms超0、P95はキャラ別S0G+25ms以下、CPU/判断はS0G比+15%以内、timeout・死亡/nomove率の悪化は各+2pt以内を使う。全失敗は既に主率へ含む。重大な共通失敗局面は件数と根拠を示して別扱いにし、「lossが1件ある」だけの拒否へ戻さない。初回pilotの改善目安は+5ptであり、80%をいきなり合格条件にしない。

対戦段階では、固定Amaに対する勝率を別の主指標にする。少なくとも200seed×両席入替の400対戦／固定キャラ組を一つの事前設計例とし、実行前に環境費用から予算を凍結する。将来の研究昇格目安は勝率55%以上かつseed/席クラスタ95%下限50%超、固定相手群での大幅退行なし。構築課題の点推定−2pt以内と区間も確認する。勝率が向上しても構築が落ちる場合はトレードオフとして提示し、勝手に16万点要件を廃止しない。
